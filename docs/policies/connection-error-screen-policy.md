# 전역 연결 오류 화면 정책

## 개요

- 목적: 사용자가 서비스를 계속 이용할 수 없는 연결 장애만 전역 오류 화면으로 안내하고, 일반적인 요청 오류가 전체 화면을 가리지 않도록 합니다.
- 적용 범위: 웹 클라이언트의 API 응답 판정, 전역 연결 오류 화면 표시와 해제, 서비스 워커의 앱 셸 복구 동작에 적용합니다.
- 기준일: 2026-08-27

전역 연결 오류 화면은 다음 세 가지 장애만 표현합니다.

| 장애 유형 | 판정 근거 | 화면 안내 |
| --- | --- | --- |
| 데이터베이스 연결 장애 | 서버가 JDBC 연결 실패로 분류한 공통 오류 응답을 반환합니다. | 데이터베이스 연결을 확인한 뒤 다시 시도하도록 안내합니다. |
| 브라우저 오프라인 | API 응답을 받지 못했고, 같은 시점에 브라우저가 오프라인 상태입니다. | 인터넷 또는 서버 연결을 확인한 뒤 다시 시도하도록 안내합니다. |
| 백엔드 또는 상위 서버 단절 | 공통 응답 없이 HTTP 502, 503, 504를 받거나, 개발 프록시가 백엔드 연결 거부를 빈 본문의 HTTP 500으로 반환합니다. | 인터넷 또는 서버 연결을 확인한 뒤 다시 시도하도록 안내합니다. |

## 표시하지 않는 경우

다음 상황은 요청 단위로 처리하며 전역 연결 오류 화면을 표시하지 않습니다.

- 데이터베이스 연결 장애로 분류되지 않은 일반 HTTP 5xx 응답
- 인증, 권한, 입력값 검증, 업무 규칙 위반과 같은 HTTP 4xx 또는 공통 오류 응답
- 브라우저가 온라인인 상태에서 발생한 응답 없는 네트워크 오류
- 타임아웃 오류만 발생한 경우
- 앱 시작 시점이나 `offline` 이벤트만으로 브라우저 오프라인 상태가 감지된 경우
- API 요청이 실제로 실패하기 전의 일시적인 네트워크 상태 변화

브라우저의 `navigator.onLine` 값은 보조 신호로만 사용합니다. 이 값이 `false`라는 이유만으로 화면을 고정하지 않으며, 실제 API 요청 실패와 함께 확인되었을 때만 브라우저 오프라인 장애로 판정합니다.

## 상태 해제 기준

| 현재 장애 유형 | 해제 조건 |
| --- | --- |
| 데이터베이스 연결 장애 | 이후 API가 정상 공통 응답을 반환합니다. |
| 브라우저 오프라인 | 이후 API가 HTTP 응답을 반환하거나 브라우저의 `online` 이벤트가 발생합니다. |
| 백엔드 또는 상위 서버 단절 | 이후 API가 정상 응답 또는 공통 오류 응답처럼 실제 백엔드 응답을 반환합니다. |

- 화면의 `다시 시도` 동작은 현재 페이지를 새로 불러와 앱과 API 상태를 다시 확인합니다.
- 동시에 여러 장애 신호가 발생해도 화면에는 한 가지 원인만 표시합니다. 활성 장애가 해제된 후 다음 요청부터 새로운 장애 원인을 판정합니다.

## 서비스 워커와의 관계

- 문서 탐색 요청에서 네트워크 오류가 발생하면 캐시된 앱 셸을 사용할 수 있습니다.
- 문서 탐색 요청이 HTTP 5xx를 반환했다는 이유만으로 정적 오류 페이지로 교체하지 않습니다.
- API와 업로드 요청은 서비스 워커 캐시에 저장하지 않습니다.
- 앱 셸이 열린 뒤의 전역 연결 오류 화면은 이 문서의 API 판정 기준을 따릅니다.
- 캐시와 업데이트 상세 정책은 [PWA 업데이트 정책](pwa-update-policy.md)을 따릅니다.

## 대표 시나리오

| 상황 | 기대 결과 |
| --- | --- |
| 백엔드는 실행 중이고 데이터베이스 연결만 실패합니다. | 서버의 JDBC 연결 실패 응답을 확인한 뒤 전역 연결 오류 화면을 표시합니다. |
| 프론트엔드는 실행 중이지만 백엔드 연결이 거부됩니다. | 개발 프록시의 빈 본문 HTTP 500을 확인한 뒤 전역 연결 오류 화면을 표시합니다. |
| 게이트웨이가 백엔드 장애를 HTTP 502, 503 또는 504로 반환합니다. | 공통 응답이 없으면 전역 연결 오류 화면을 표시합니다. |
| 브라우저가 오프라인이고 API 요청도 응답 없이 실패합니다. | 전역 연결 오류 화면을 표시합니다. |
| 서버가 업무 오류나 일반 애플리케이션 오류를 공통 응답으로 반환합니다. | 전역 화면을 표시하지 않고 기존 요청 오류 처리 흐름을 유지합니다. |
| 백엔드 연결이 복구되어 실제 API 응답을 받습니다. | 백엔드 단절 상태를 해제하고 기존 화면으로 돌아갑니다. |
| 데이터베이스 연결이 복구되어 정상 공통 응답을 받습니다. | 데이터베이스 연결 장애 상태를 해제하고 기존 화면으로 돌아갑니다. |

## 구현 근거

- `src/main/frontend/src/app/connection/connectionStatus.ts`: 장애 유형과 표시 조건을 판정합니다.
- `src/main/frontend/src/app/api/axios.ts`: API 성공·실패 응답에서 장애 상태를 등록하거나 해제합니다.
- `src/main/frontend/src/components/ConnectionError/ConnectionErrorScreen.tsx`: 전역 화면의 문구, 온라인 복구 감지, 다시 시도 동작을 제공합니다.
- `src/main/java/org/our/sadari/global/common/exception/CommonExceptionHandler.java`: JDBC 및 데이터베이스 연결 예외를 공통 오류 응답으로 분류합니다.
- `src/main/frontend/public/service-worker.js`: 문서 탐색 실패 시 앱 셸 복구와 API 캐시 제외를 처리합니다.
