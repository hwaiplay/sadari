# 독서 모임 기능 설계

## 개요

- 목적: 맞팔 관계의 사용자를 초대해 같은 도서와 목표 기간을 공유하고, 독후감 공개와 다음 도서 선정을 반복하는 독서 모임 기능을 설계한다.
- 적용 범위: 사용자 앱의 독서 모임, 회차, 참가, 독후감 공유, 도서 추천·투표, 채팅 및 알림이다.
- 기준일: 2026년 8월 1일이다.
- 구현 상태: 제안이며 소스, 데이터베이스, 공통코드 및 화면에 적용하지 않았다.
- 정책 상태: [독서 모임 정책 결정 항목](../policies/reading-club-policy-decisions.md)의 필수 항목이 미확정이므로 구현을 시작하지 않는다.

## 설계 결론

독서 모임은 계속 유지되는 공간이고, 공동 독서는 반복되는 회차이다. 모임과 회차를 분리하고 다음 도서 선정은 회차와 별도 수명주기로 관리한다. 개인 책장 기록은 기존 `TM_REPORT`를 재사용하지만, 모임 안에서 공유하는 독후감은 전체 공개 여부인 `PUBC_YSNO`와 분리한다.

핵심 구조는 다음과 같다.

1. 사용자가 비공개 독서 모임을 만들고 맞팔 사용자를 초대한다.
2. 모임장은 도서와 목표 기간이 정해진 회차를 예약한다.
3. 모임원은 회차별로 참가 또는 쉬기를 선택한다.
4. 회차 시작 시 참가자별 `READ` 독서 기록을 `TM_REPORT`에 일괄 생성한다.
5. 참가자는 기존 독후감 편집 흐름으로 개인 기록을 작성하고 모임 제출을 별도로 수행한다.
6. 목표 종료 시각 전에는 다른 참가자의 내용을 숨기고 종료 후 제출본을 동시에 공개한다.
7. 다음 도서 선정은 추천과 투표를 거쳐 새 회차로 확정한다.
8. 활성 모임원은 모임 채팅과 시스템 메시지를 이용한다.

## 자체 검토 결과와 정정 사항

초기 기획안을 현행 구현과 대조한 결과 다음 오류와 모호성을 확인했다.

| 검토 항목 | 초기 기획의 문제 | 정정 설계 |
| --- | --- | --- |
| 회차와 도서 선정 | 하나의 진행 회차만 허용하면서 다음 도서 선정을 병행해 상태가 충돌했다. | 도서 선정을 회차와 별도 엔터티로 분리하고 선정 완료 후 새 회차를 생성한다. |
| 독후감 공개 | `TM_REPORT.PUBC_YSNO`만으로 모임 공개를 표현하면 전체 공개와 구분할 수 없다. | 모임 제출본과 열람 권한을 별도 관리하며 `PUBC_YSNO`를 자동 변경하지 않는다. |
| 개인 기록 생성 | 회차 참가 확정 즉시 기록을 만들면 도서와 기간 변경 또는 회차 취소 시 불필요한 기록이 남는다. | 회차가 `SCHEDULED`에서 `READING`으로 전환될 때 참가자 기록을 하나의 트랜잭션으로 생성한다. |
| 평균 평점 | 자동 생성한 미선택 평점이 평균에 포함될 가능성을 검토하지 않았다. | 현행 정책대로 자동 기록은 `READ`, 평점 `0`, 비공개 `N`으로 생성하고 평균 평점 조회에서 `READ`가 제외되는 계약을 유지한다. |
| 공동 목표일과 개인 완료일 | 모든 참가자의 `TM_REPORT.REPT_ENDT`를 계속 같게 유지하면 조기 완독자의 실제 완료일을 잃는다. | 공동 목표 기간은 회차에 보존하고 `DONE`·`STOP` 개인 기록의 종료일은 현행 정책에 따른 실제 종료일로 분리한다. |
| 편집과 삭제 | 기존 독후감 API로 모임 연결 기록의 기간을 변경하거나 삭제하면 공동 기간과 제출 관계가 깨질 수 있다. | 진행 회차에 연결된 독후감은 기간 변경과 삭제를 제한하고 모임 서비스에서 연결 상태를 검증한다. |
| 조기 완료 | 전원 제출 시 회차를 조기 완료하면 목표 기간 전 독후감 동시 공개 원칙과 충돌했다. | 전원 제출 여부와 관계없이 목표 종료 전에는 공개하지 않는다. 완료는 공개 이후에만 가능하다. |
| 열람 대상 | 모임원 전체와 회차 참가자를 혼용했다. | 기본 추천안은 해당 회차 참가자만 비공개 제출본을 열람하는 방식이며 최종 범위는 정책 결정 대상으로 둔다. |
| 제출본 변경 | 개인 독후감을 실시간 참조하면 공개 후 수정으로 회차 기록이 계속 바뀐다. | 제출 시점의 상태, 평점, 본문을 모임 제출본으로 저장하는 스냅샷 방식을 우선안으로 둔다. |
| 첫 도서 선정 | 다음 도서 추천만 정의해 첫 회차의 선정 기준이 없었다. | 첫 선정은 원본 회차 없이 생성할 수 있고, 모임장 직접 선택 또는 추천·투표를 모두 지원한다. |
| 탈퇴와 퇴장 | 일반 퇴장, 비활성화, 영구 탈퇴의 보존·삭제 범위를 확정하지 않았다. | 관련 처리를 구현 차단 정책으로 분리하고 사용자 확정 전에는 현재 정책으로 단정하지 않는다. |
| 채팅 기반 | 의존성에 WebSocket 관련 전이 패키지가 있다는 사실만으로 채팅 기반이 구현된 것은 아니다. | 현재 전용 채팅 도메인은 없는 것으로 기록하고 WebSocket과 REST 혼합 구조를 신규 제안한다. |

## 요구사항

### 필수 요구사항

- 한 사용자는 여러 모임을 개설하고 여러 모임에 참여할 수 있어야 한다.
- 모임장은 맞팔 사용자 중 초대 가능한 사용자를 조회하고 여러 명에게 초대할 수 있어야 한다.
- 초대받은 사용자는 수락 또는 거절할 수 있어야 한다.
- 모임은 대표 카테고리와 운영 정보를 가져야 한다.
- 모임 안에서 같은 도서와 목표 기간을 공유하는 회차를 반복할 수 있어야 한다.
- 모임원은 회차별 참가 여부를 선택할 수 있어야 한다.
- 참가자별 개인 독서 기록은 기존 책장에 표시되어야 한다.
- 목표 기간 종료 전에는 다른 참가자의 독후감 내용을 볼 수 없어야 한다.
- 목표 기간 종료 후에는 정책상 허용된 참가자가 제출 독후감을 볼 수 있어야 한다.
- 모임원은 다음 도서를 추천하고 투표할 수 있어야 한다.
- 활성 모임원은 채팅할 수 있어야 한다.
- 계정 상태, 모임 상태, 역할 및 회차 상태에 따른 서버 접근 검증이 있어야 한다.

### 전제조건

- 맞팔은 `TB_FOLLOW`에 두 방향의 관계가 모두 존재하는 상태로 판단한다.
- 도서 식별은 기존 `TM_BKINFO.BOOK_NUMB`와 ISBN 중복 방지 계약을 사용한다.
- 개인 독서 기록은 `TM_REPORT`를 기준으로 유지한다.
- 알림 저장과 푸시는 기존 `TB_ALTEMP`, `TB_ALIMXX`, `TB_PSHSUB` 흐름을 재사용한다.
- 계정이 `ACTIVE`인 사용자만 초대 수락, 회차 참가 및 채팅이 가능하다.

### 제외 범위

- 공개 모임 검색과 불특정 사용자 가입 신청
- 유료 모임과 회비 정산
- 오프라인 장소 예약과 출석 인증
- 채팅 이미지·파일 첨부
- 음성 및 영상 모임
- 여러 단계 운영진과 세분화된 관리자 권한
- AI 독후감 자동 작성

## 현행 구조

### 재사용 가능한 구현

| 영역 | 현행 구현 | 설계 활용 |
| --- | --- | --- |
| 팔로우 | `TB_FOLLOW`에 방향성 관계를 저장한다. | 양방향 교집합으로 초대 후보를 조회한다. |
| 도서 | `TM_BKINFO`에 ISBN 기준 도서 정보를 저장한다. | 회차와 추천 후보가 기존 도서를 참조한다. |
| 독서 기록 | `TM_REPORT`에 상태, 기간, 평점, 본문, 공개 여부를 저장한다. | 참가자의 개인 책장 기록으로 재사용한다. |
| 알림 | 템플릿 기반 알림 저장 후 커밋 뒤 푸시를 발송한다. | 초대, 회차, 제출, 투표 이벤트를 추가한다. |
| 계정 상태 | `ACTIVE`, `WITHDRAWN`, `DELETE_PENDING`, `SUSPENDED` 상태를 관리한다. | 모든 모임 접근 검증의 선행 조건으로 사용한다. |

### 신규 구현이 필요한 영역

- 독서 모임과 모임원 도메인
- 초대 수명주기와 정원 동시성 제어
- 반복 회차와 회차 참가 상태
