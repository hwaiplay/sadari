# 고객문의 및 관리자 답변 정책

## 적용 범위

- 기준일은 2026년 8월 14일입니다.
- 1차 개발은 비공개 고객문의 접수, 본인 문의 및 답변 조회, 관리자 검토·답변과 문의에 연결된 이용정지 해제를 포함합니다.
- 사용자 기준 경로는 `/inquiry/list`, 관리자 기준 경로는 `/sadari/adm/inquiry`입니다.
- 파일 첨부, 사용자의 추가 메시지, 답변 수정·삭제, 이메일·채팅 상담과 푸시 알림은 1차 범위에서 제외합니다.

## 공개 범위와 접근

- 고객문의와 답변은 작성자 본인과 고객문의 메뉴 권한이 있는 관리자만 조회합니다.
- 사용자 API는 요청으로 전달된 회원번호를 사용하지 않고 인증 정보의 `USER_NUMB`로 소유권을 검증합니다.
- `ACTIVE` 회원은 문의 등록, 목록 및 상세 조회를 이용할 수 있습니다.
- `SUSPENDED` 회원은 `/suspension`과 고객문의 화면 및 API, 영구탈퇴와 로그아웃만 이용할 수 있습니다.
- `ACTIVE` 회원은 기존 공통 헤더와 하단 네비게이션으로 고객문의에 접근합니다.
- `SUSPENDED` 회원의 고객문의 화면에서는 공통 헤더와 하단 네비게이션을 표시하지 않으며 정지 안내 화면의 단일 문의 버튼으로만 진입합니다.
- `WITHDRAWN`과 `DELETE_PENDING` 회원은 1차 고객문의 화면과 API를 이용할 수 없습니다.
- 회원 원본이 물리 삭제되면 기존 문의와 답변을 사용자 계정으로 조회할 수 없습니다.

## 문의 접수와 답변

- 문의 카테고리는 `GENERAL`, `ACCOUNT`, `SUSPENSION_APPEAL`, `BUG`, `SUGGESTION`을 사용합니다.
- 문의 상태는 `INQR_RECEIVED`, `INQR_REVIEWING`, `INQR_ANSWERED` 순서로 처리합니다.
- 문의 제목은 공백 제거 후 최대 200자, 문의와 답변 본문은 공백 제거 후 UTF-8 최대 4,000바이트로 제한합니다.
- 문의와 답변은 HTML을 허용하지 않는 일반 텍스트로 저장하고 화면에서도 텍스트로 출력합니다.
- `ACTIVE`와 `SUSPENDED` 회원이 작성한 문의 제목과 본문은 저장 전에 공통 비속어 검사를 적용하고, 비속어가 탐지되면 문의를 접수하지 않습니다.
- 관리자가 상세를 조회하는 행위만으로 담당자나 상태를 변경하지 않습니다.
- 관리자가 검토 시작을 실행하면 현재 관리자를 담당자로 지정합니다.
- 답변 등록은 문의 답변 행 생성과 문의 상태 및 최종 답변 일시 변경을 한 트랜잭션으로 처리합니다.
- 답변을 등록해도 이용정지를 자동 해제하지 않습니다.

## 이용정지 이의제기

- `SUSPENDED` 회원의 문의 카테고리는 화면과 서버 모두 `SUSPENSION_APPEAL`로 고정하며 다른 카테고리 접수를 거부합니다.
- `SUSPENSION_APPEAL` 문의는 서버가 작성자의 가장 최근 `TH_USSPND.SPND_NUMB`를 연결합니다.
- 같은 정지 이력에 `INQR_RECEIVED` 또는 `INQR_REVIEWING` 상태의 이의제기가 있으면 중복 접수를 제한합니다.
- 정지 안내 화면은 현재 활성 정지 시작 이후 접수된 이의제기가 없으면 `이용정지 문의하기`를, 있으면 최신 문의 상세로 이동하는 `문의내역보기`를 표시합니다.
- `SUSPENDED` 회원의 문의 상세에는 정지 안내 화면(`/suspension`)으로 이동하는 전체 너비의 공통 검정 `돌아가기` 버튼을 뷰포트 하단에 고정하며, 브라우저 이력에 문의 상세를 남기지 않도록 현재 경로를 교체합니다.
- 제한 상태에서 허용된 문의 등록과 로그아웃 요청이 CSRF 보호를 유지할 수 있도록 CSRF Token 조회 API만 추가 허용합니다.
- 이용정지 해제는 고객문의 답변과 별도 작업으로 실행하며 기존 현재 사용자 관리의 상태 변경, 감사값 및 동기화 처리를 그대로 사용합니다.
- 연결된 정지가 이미 만료 또는 해제된 경우 중복 해제를 허용하지 않습니다.

## 계정 수명주기와 데이터 보존

- `WITHDRAWN` 전환 시 기존 고객문의와 답변은 관리자 운영 이력으로 유지하지만 사용자 접근은 차단합니다.
- `WITHDRAWN` 회원이 같은 Kakao 계정으로 재로그인해 기존 `USER_NUMB`가 `ACTIVE`로 복귀하면 유지된 본인 문의를 다시 조회할 수 있습니다.
- `DELETE_PENDING` 유예기간에는 문의 데이터가 유지되지만 사용자 접근은 차단합니다.
- 영구 삭제로 `TM_USERXM` 행이 삭제되면 `CT_INQURY.USER_NUMB`를 외래키의 `ON DELETE SET NULL`로 비식별화하고 문의와 답변은 운영 처리 이력으로 계속 보존합니다.
- 물리 삭제된 문의 작성자와 새로 가입한 계정은 서로 연결하지 않으며 과거 문의와 답변을 새 계정에 복원하지 않습니다.
- 고객문의 보존은 현재 별도 만료 기간을 두지 않는 운영 이력 보존으로 적용하며, 추후 보존기간을 정하면 별도 삭제 작업과 함께 정책을 개정합니다.
- 고객문의 기능은 알림, 푸시 구독, 팔로우, 좋아요와 기타 소셜 관계의 보존·삭제·복원 범위를 변경하지 않습니다.
- 1차에서는 답변 알림과 푸시를 생성하지 않으며 사용자는 고객문의 목록의 미확인 답변 표시로 새 답변을 확인합니다.

## 2차 회원 탈퇴정책 연계

- 2026년 8월 13일 적용한 2차 회원 탈퇴정책에는 고객문의 기능 확장을 포함하지 않습니다.
- 정지 회원의 영구탈퇴, `TH_USWTHD`와 `TH_USSPND`를 이용한 Kakao 계정 제재 유지, 관리자 해제와 제재 해제 뒤 신규 가입은 [계정 비활성화 및 영구 탈퇴 정책](withdrawal-policy.md)을 단일 기준으로 처리합니다.
- 1차 고객문의 테이블은 재가입 차단의 기준 데이터로 사용하지 않으며, 새 계정에 탈퇴 전 문의와 답변을 연결하거나 복원하지 않습니다.
