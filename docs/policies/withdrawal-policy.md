# 계정 비활성화 및 영구 탈퇴 정책

## 적용 범위

- 기준일은 2026년 8월 4일입니다.
- 사용자 계정 비활성화, 복귀, 영구 탈퇴 유예·취소·삭제와 관리자 계정 처리 이력 조회에 적용합니다.
- 설치형 웹앱의 정적 리소스 업데이트가 계정 상태에 미치는 영향도 적용 범위에 포함합니다.
- 독서 모임 기능이 출시된 뒤 적용할 모임장 부재·승계 연계 기준은 별도 절에 구분해 기록합니다.

## 공통 절차

1. 사용자가 계정 비활성화 또는 영구 탈퇴와 처리 사유를 선택합니다.
2. `OTHER` 사유를 선택하면 상세 사유를 필수로 입력합니다.
3. 상세 탈퇴 사유는 UTF-8 기준 최대 500바이트까지 입력할 수 있습니다.
4. 서버가 계정 처리 유형과 사유를 공통코드로 검증합니다.
5. 사용자가 최종 확인창에서 확인한 경우에만 재인증 요청을 생성합니다.
6. 탈퇴 요청은 예측 불가능한 OAuth `state`와 함께 Redis에 10분간 저장합니다.
7. Kakao 재인증 계정과 현재 로그인 계정이 일치해야 탈퇴를 진행합니다.
8. Kakao 연결 해제 성공 후 로컬 탈퇴 상태를 적용합니다.

확인창에서 취소하면 재인증 API를 호출하지 않으며 Kakao 화면으로 이동하지 않습니다.

화면의 비활성화와 영구 탈퇴 선택 카드에는 각 정책의 핵심 안내 한 줄만 표시하며, 도움말 버튼을 누르면 전체 정책을 비교할 수 있는 안내 팝업을 제공합니다.

도움말 팝업의 비활성화 목록은 `CT_POPUPX`의 `ACCOUNT`·`WITHDRAWAL_POLICY` 행에 있는 `CONT_FIRS`, 영구 탈퇴 목록은 `CONT_SECO`에서 조회합니다. 콘텐츠가 없거나 조회 및 JSON 검증에 실패하면 화면에 포함된 현재 기본 문구를 표시합니다. 세부 저장 및 조회 기준은 [사용자 안내 팝업 콘텐츠 정책](popup-content-policy.md)을 따릅니다.

## 계정 비활성화

- 처리 유형: `SOFT`
- 회원 상태: `WITHDRAWN`
- 관리자 이용 정지가 적용된 `SUSPENDED` 회원은 정지를 우회할 수 있으므로 비활성화를 신청할 수 없습니다.
- 같은 Kakao 계정으로 재로그인하면 기존 회원 계정을 `ACTIVE` 상태로 다시 활성화합니다.
- 회원 원본 정보와 로그인 이력은 유지합니다.
- 작성한 독후감은 모두 비공개로 전환합니다.
- 작성한 댓글은 삭제된 댓글 상태로 전환합니다.
- 댓글에 등록한 좋아요는 삭제하며 계정 재활성화 시 자동 복원하지 않습니다.
- 댓글 수정·삭제 메뉴와 API는 `ACTIVE` 상태에서 본인이 작성한 미삭제 댓글에만 제공합니다.
- `WITHDRAWN` 상태에서는 본인 댓글 수정·삭제 메뉴를 표시하지 않으며 직접 API를 호출해도 처리하지 않습니다.
- 수신 알림은 삭제 상태로 전환합니다.
- 비활성화 전에 다른 회원에게 발송된 댓글 좋아요 알림은 수신자의 알림 기록으로 유지하며, 발신 회원이 복귀해도 새로 생성하거나 복원하지 않습니다.
- 브라우저 푸시 구독은 비활성화합니다.
- 팔로우 및 팔로워 관계는 유지합니다.
- 다른 사용자가 탈퇴 회원 프로필에 접근하면 제공 정보를 제한합니다.
- 비활성화 과정에서 변경된 독후감 공개 상태, 댓글, 알림, 푸시 구독은 계정 재활성화 시 자동 복원하지 않습니다.
- 계정이 다시 활성화된 로그인에는 “다시 돌아와서 반가워요” 팝업을 표시하고 자동 복원되지 않는 항목을 다시 안내합니다.
- 일반 로그인에는 비활성화 계정 복귀 팝업을 표시하지 않습니다.

## 영구 탈퇴

- 처리 유형: `HARD`
- 회원 상태: `DELETE_PENDING`
- 운영 환경은 신청 직후 삭제하지 않고 기본 30일의 유예기간을 둡니다.
- 유예기간에는 영구 삭제 예정일을 사용자에게 표시합니다.
- 유예기간이 끝나기 전에는 영구 탈퇴를 취소할 수 있습니다.
- 관리자 이용 정지 중인 회원은 정지 해제 또는 기간 만료 전까지 영구 탈퇴를 신청할 수 없습니다.
- 취소하면 유효한 관리자 이용 정지가 남아 있을 때는 `SUSPENDED`, 남아 있지 않을 때는 `ACTIVE`로 복구하고 탈퇴일과 삭제 예정일을 제거합니다.
- 유예기간 동안에도 독후감 비공개, 댓글 삭제 상태, 알림 삭제 상태, 푸시 비활성화 정책을 적용합니다.
- 영구 삭제 대기 전환 시 댓글에 등록한 좋아요를 삭제하고, 탈퇴를 취소해도 자동 복원하지 않습니다.
- `DELETE_PENDING` 상태에서는 본인 댓글 수정·삭제 메뉴를 표시하지 않으며 직접 API를 호출해도 처리하지 않습니다.
- 유예기간 종료 후 매일 03:00 영구 삭제 스케줄러가 대상 회원을 처리합니다.
- 영구 삭제 시 `TM_USERXM` 회원 원본을 삭제합니다.
- 로그인 이력은 보존하고, 정책상 보존 대상이 아닌 회원 연관 데이터는 삭제합니다.
- 영구 삭제 시 작성 댓글 원문과 회원 연관 댓글 데이터를 물리 삭제하며 이후 복구하지 않습니다.
- 영구 삭제 시 회원이 등록한 댓글 좋아요와 물리 삭제되는 댓글을 대상으로 한 좋아요를 모두 삭제합니다.
- 영구 탈퇴 전에 다른 회원에게 발송된 댓글 좋아요 알림은 수신자의 알림 기록으로 유지하며 공통 알림 보존·삭제 정책에 따라 정리합니다.
- 탈퇴 이력에는 원본 OAuth 식별값 대신 SHA-256 해시를 저장합니다.
- 탈퇴 이력의 `USER_NUMB`는 탈퇴 당시 내부 회원번호를 감사 이력으로 보존합니다.
- `TH_USWTHD.USER_NUMB`는 회원 원본 삭제 후에도 값을 유지해야 하므로 `TM_USERXM`과 FK로 연결하지 않습니다.

## 독서 모임 모임장 연계 예정 정책

이 절은 독서 모임 설계에 확정된 연계 기준이며 현재 모임장 선거와 승계 프로시저는 구현되지 않았습니다. 현행 영구 삭제 스케줄러의 동작이 이미 변경됐다는 의미로 해석하지 않습니다.

- 모임장의 계정이 물리 삭제되면 해당 모임의 모임장 부재 사유를 확정하고 활성 모임원 선거로 다음 모임장을 선출합니다.
- 모임장이 복구 불가능한 영구 이용 제한을 받으면 관리자가 비가역성을 확인한 뒤 같은 선거 절차를 시작합니다.
- 모임장의 자발적 승계 요청도 확정 부재 사유로 처리하며 특정 후임자를 직접 지정하지 않고 선거를 시작합니다.
- `WITHDRAWN`, 기간이 정해진 이용 정지, 해제 가능성이 남은 무기한 이용 정지 및 `DELETE_PENDING`만으로는 확정 부재로 판정하지 않습니다.
- 최근 로그인·게시·채팅 활동이 없다는 사실만으로는 모임장 선거를 시작하지 않습니다.
- 확정 부재 사유, 근거, 확정자와 일시 및 선거에 따른 권한 변경은 감사 이력으로 남깁니다.
- `DELETE_PENDING` 30일 유예 중에는 모임장 선거를 시작하지 않고 해당 회원의 모임 접근·운영·알림만 중지합니다.
- 영구 탈퇴를 취소하면 모임원 자격은 복원하되 비활성화된 푸시 구독과 개인 독후감 공개 설정은 자동 복원하지 않습니다.
- 물리 삭제 뒤에는 소유 모임을 다시 찾을 수 없으므로 `TM_USERXM` 삭제 직전에 모임별 확정 부재 이벤트, 모임장 선거 및 감사값을 멱등하게 기록합니다.
- 모임별 부재 이벤트와 선거 생성이 모두 성공하면 선거 완료를 기다리지 않고 예정된 계정 물리 삭제를 진행합니다. 한 모임이라도 기록에 실패하면 계정 삭제 전체를 재시도 대상으로 남깁니다.
- 선거는 시작 시점의 활성 모임원 명부로 24시간 동안 정족수 없이 비밀투표를 진행하고, 유효표 최다 득표자를 다음 모임장으로 선출합니다.
- 동률이면 동률 후보만 24시간 결선 투표를 한 번 진행합니다. 후보나 유효표가 없어 성립하지 않으면 24시간을 한 번 연장하고, 연장 뒤에도 성립하지 않으면 모임을 `PAUSED`로 유지합니다.
- 선거 데이터와 모임장 변경 감사 이력은 탈퇴한 기존 모임장 번호를 원본 회원 FK 없이 보존합니다.

### 독서 모임 회원 데이터 처리

- `WITHDRAWN` 회원의 모임원 자격은 유지하되 모임 접근과 알림을 중지합니다.
- `WITHDRAWN` 회원이 모임장이면 모임을 `PAUSED`로 전환해 공개 검색과 신규 가입·신청·초대를 중지하고, 복귀한 모임장이 직접 재개합니다.
- `WITHDRAWN` 또는 `DELETE_PENDING` 상태의 모임장은 모임 편집과 물리 삭제 API를 사용할 수 없습니다. 계정 상태가 복구되기 전에는 화면에도 해당 기능을 제공하지 않습니다.
- 모임장이 계정을 물리 삭제하면 소유 모임을 함께 삭제하지 않고 `RC-88`의 모임장 선거를 시작합니다. 계정 수명주기 처리는 사용자가 직접 실행한 모임 물리 삭제를 대신하지 않습니다.
- 비활성화 복귀 또는 영구 탈퇴 취소 시에는 계정 제한 동안 모임 편집·삭제가 실행되지 않았으므로 기존 모임 데이터를 별도로 복원하지 않고 유지된 모임원 자격과 운영 상태를 기준으로 접근을 재개합니다.
- 비활성화 또는 삭제 대기 회원의 기존 연결 독후감과 채팅은 남은 모임원에게 유지하되 작성자 프로필 접근을 제한합니다.
- 물리 삭제 시 회원 관심분야와 처리 중 가입 신청의 질문 사본·답변 및 식별 가능한 초대 정보를 삭제합니다. 승인·거절된 신청 답변은 신청 처리 시점에 이미 삭제되어 있어야 합니다.
- 물리 삭제 시 회원의 `TM_REPORT`를 삭제하고 모임 화면에는 삭제된 독후감으로 표시합니다.
- 물리 삭제 시 채팅 본문을 삭제하고 탈퇴한 회원의 삭제된 메시지로 표시합니다.
- 회차 참여자의 식별값과 `REPT_NUMB` 연결은 제거하되 회차 참여 건수와 목표 달성 집계는 비식별 상태로 유지합니다. 탈퇴한 달성자의 이름은 목록에서 제거합니다.

상세 기준은 [독서 모임 정책 결정 항목](reading-club-policy-decisions.md)과 [독서 모임 상세 기획 및 기술 설계](../architecture/reading-club-design.md)를 함께 따릅니다.

## 로컬 영구 탈퇴 테스트

- `loc` 프로필은 `withdrawal.hard-delete-wait-days`를 `0`으로 설정해 영구 탈퇴 요청 시 삭제 예정일을 즉시 도래시킵니다.
- `withdrawal.hard-delete-test-enabled`가 `true`이면 로컬 전용 스케줄러가 10초마다 영구 삭제 대상을 처리합니다.
- 로컬 전용 스케줄러는 `loc` 프로필에서만 생성되며 운영 프로필에서는 활성화할 수 없습니다.
- 테스트 설정은 특정 회원만 구분하지 않으므로 연결된 DB에서 삭제 예정일이 지난 모든 회원을 대상으로 합니다.
- 공용 개발 DB에서 테스트할 때는 다른 사용자가 `DELETE_PENDING` 상태인지 확인한 뒤 실행해야 합니다.

## 외부 연동 실패

- Kakao 연결 해제가 실패하면 회원 상태를 변경하지 않습니다.
- 탈퇴 이력은 `UNLINK_PENDING` 상태로 기록하고 제한된 길이의 오류 내용을 저장합니다.
- 외부 연결 해제에 성공해야 계정 비활성화 또는 영구 삭제 대기 상태를 적용합니다.

## 서비스 간 회원 상태 동기화

- 비활성화와 영구 탈퇴는 사용자 서버가 처리하므로 해당 서버의 Redis 상태를 즉시 함께 변경합니다.
- 관리자가 정지·해제한 회원 상태는 DB Outbox를 통해 사용자 서버의 Redis에 최대 5분 안에 반영합니다.
- Outbox에는 이벤트 번호·유형·내부 회원번호·등록일시만 임시 저장하고 성공 처리 후 삭제합니다.
- 회원 원본이 이미 영구 삭제된 이벤트를 처리하면 사용자 서버의 남은 로그인 정보를 제거한 뒤 이벤트를 삭제합니다.
- 상태 동기화를 위해 별도 푸시알림을 발송하지 않습니다.

## 탈퇴 상태값

| 상태 | 의미 |
| --- | --- |
| `COMPLETED` | 계정 비활성화 적용 완료 |
| `UNLINK_PENDING` | Kakao 연결 해제 실패로 재처리 필요 |
| `DELETE_PENDING` | 영구 삭제 유예기간 |
| `RESTORED` | 영구 탈퇴 신청 취소 |

## 관리자 계정 처리 이력 조회

- 관리자 `현 사용자 관리` 상세에서는 `TM_USERXM` 원본 행이 존재하는 회원의 `TH_USWTHD` 이력만 읽기 전용으로 확인합니다.
- 비활성화와 영구 탈퇴의 처리 유형, 코드화된 사유, 처리 상태, 요청일, 삭제 예정일, 처리일 및 복구일을 제공합니다.
- 자유 입력 상세 사유와 외부 연동 오류문구는 관리자 API와 화면에 제공하지 않습니다.
- 관리자 화면에서 비활성화 복구, 영구 탈퇴 취소, 유예기간 변경 및 즉시 삭제를 수행할 수 없습니다.
- 유예기간이 끝나 `TM_USERXM` 원본이 영구 삭제된 회원은 `현 사용자 관리` 대상에서 제외합니다.
- 보존된 `TH_USWTHD` 이력의 별도 감사 조회 화면은 1차 구현 범위에 포함하지 않습니다.

## 설치형 웹앱 업데이트

- 설치형 웹앱 업데이트는 서비스워커, 화면 코드, 스타일, 아이콘 및 공개 정적 이미지만 갱신합니다.
- 업데이트 확인과 정적 리소스 캐시 교체는 로그인 여부와 회원 상태에 관계없이 실행합니다.
- `WITHDRAWN` 및 `DELETE_PENDING` 회원에게도 최신 제한 상태 화면을 제공하되 계정 상태와 사용자 데이터는 변경하지 않습니다.
- 업데이트 과정에서는 인증 쿠키, 알림 데이터, 업로드 파일 및 사용자별 API 응답을 캐시에 저장하지 않습니다.
- 계정 재활성화 또는 영구 탈퇴 취소 시 정적 리소스 업데이트 이력을 기준으로 사용자 데이터를 복원하지 않습니다.
- 상세 캐시와 실패 처리 기준은 [설치형 웹앱 자동 업데이트 정책](pwa-update-policy.md)을 따릅니다.

## 비속어 검사

- 비속어 검사는 활성 계정의 콘텐츠 입력 시점에만 수행하며 검사 결과와 정규화 중간값을 별도 저장하지 않습니다.
- `WITHDRAWN` 및 `DELETE_PENDING` 계정은 기존 제한 상태 화면과 접근 제어를 적용하므로 콘텐츠 입력을 위한 별도 비속어 검사 경로를 제공하지 않습니다.
- 계정 비활성화, 영구 탈퇴, 취소 또는 복귀 시 비속어 사전과 검사 결과를 기준으로 기존 콘텐츠를 추가 삭제하거나 복원하지 않습니다.
- 비속어 검사 정책은 알림, 푸시 구독 및 소셜 관계의 삭제·보존·복원 범위를 변경하지 않습니다.
- 세부 입력 판정 기준은 [콘텐츠 및 파일 정책](content-file-policy.md)을 따릅니다.
