# 알림 및 푸시 정책

## 알림 생성

- 공통 발송 메서드는 수신자, 상황 코드, 템플릿 코드, 대상 번호, 치환 Map을 받습니다.
- 알림 템플릿에서 상황 코드와 템플릿 코드가 일치하고 사용 중인 템플릿만 사용합니다.
- 템플릿의 `#{key}` 상용구를 전달받은 Map 값으로 치환합니다.
- 템플릿 링크의 `#{targetNumb}` 자리표시자에는 검증된 대상 번호를 치환합니다. 자리표시자가 없는 기존 상세 링크는 대상 번호를 뒤에 조합하고, 대상 번호가 필요 없는 완성 링크는 그대로 저장합니다.
- 알림센터와 푸시는 발송 내역에 저장된 링크를 그대로 사용하며 템플릿 코드로 이동 경로를 다시 판별하거나 보정하지 않습니다.
- 탈퇴 또는 영구 삭제 대기 회원에게는 새 알림과 푸시를 생성하지 않습니다.
- 사용자 간 개인 소셜 알림은 내부 발신자 식별번호와 수신자 식별번호의 양방향 차단 관계를 저장 직전에 검증합니다. 어느 한쪽이라도 상대를 차단한 경우 알림 이력과 푸시를 모두 생성하지 않습니다.
- 발신자가 없는 시스템 알림과 독서 모임 초대·가입 처리·강제 퇴장처럼 모임 운영에 필요한 알림은 개인 차단 관계로 중지하지 않습니다.
- 차단 전에 생성된 알림은 보존하며, 알림 링크로 이동할 때 연결 API가 현재 차단 관계를 다시 확인합니다.
- 알림 DB 저장이 커밋된 뒤 FCM 푸시를 발송합니다.
- 푸시는 부가 기능이므로 푸시 실패가 이미 저장된 알림을 롤백하지 않습니다.
- 댓글 또는 대댓글 좋아요가 신규 등록되면 해당 댓글 작성자에게만 원본 콘텐츠 유형별 `LIKE`·댓글 좋아요 알림과 푸시를 생성합니다. 독후감은 상세 댓글 목록으로, 프로필·배경사진은 지정된 피드 카드의 댓글 목록으로 이동합니다.
- 댓글 좋아요 발신자 닉네임은 좋아요 대상 검증 시 활성 회원 원본에서 함께 조회하며 Redis 로그인 캐시 유무로 알림 생성을 생략하지 않습니다.
- 본인 댓글 좋아요, 중복 좋아요 등록 및 좋아요 취소에는 댓글 좋아요 알림을 생성하지 않습니다.
- 모임장이 활성 맞팔 회원을 초대하면 초대 대상자에게 `FOLLOW` 상황의 독서모임 초대 템플릿 알림을 저장하고, 활성 푸시 구독이 있으면 커밋 후 푸시를 발송합니다.
- 독서모임 초대 템플릿에는 `#{userName}`으로 모임장 닉네임을, `#{clubName}`으로 모임명을 전달하며 링크 대상 번호에는 모임 번호를 사용합니다.
- 모임장이 승인형 모임 가입 신청을 승인하거나 거절하면 활성 신청자에게 `FOLLOW` 상황의 `CLUB_JOIN_APPROVED` 또는 `CLUB_JOIN_REJECTED` 템플릿 알림을 저장하고, 활성 푸시 구독이 있으면 커밋 후 푸시를 발송합니다.
- 가입 신청 처리 알림에는 `#{clubName}`으로 모임명을 전달하며 링크 대상 번호에는 모임 번호를 사용합니다. 템플릿 조회나 알림 저장에 실패하면 가입 신청 처리도 같은 트랜잭션에서 롤백합니다.
- 모임장이 활성 일반 멤버를 강제 퇴장시키면 대상자에게 `FOLLOW` 상황의 `CLUB_MEMBER_EXITED` 템플릿 알림을 저장하고, 활성 푸시 구독이 있으면 커밋 후 푸시를 발송합니다.
- 강제 퇴장 알림에는 `#{clubName}`으로 모임명을, `#{exitReason}`으로 필수 퇴장 사유를 전달합니다. 템플릿 조회나 알림 저장에 실패하면 멤버 상태와 재가입 차단 변경도 같은 트랜잭션에서 롤백합니다.
- 독서 타이머 목표시간이 지나면 `독후감` 상황의 독서 타이머 기간 초과 템플릿에 `#{timerTime}`을 전달하고 `/timer`로 이동하는 알림을 저장합니다.

## 독후감별 알림 설정

- 새 독후감은 좋아요 알림 독후감 원문 좋아요 알림 여부와 댓글 알림 독후감 원문 댓글 알림 여부를 모두 `Y`로 시작합니다.
- 독후감 작성자는 상세 화면의 기록 영역 더보기 메뉴에서 공개 또는 비공개 여부와 관계없이 두 설정을 각각 켜거나 끌 수 있습니다.
- 좋아요 알림을 `N`으로 설정해도 좋아요 등록과 취소 및 좋아요 수 집계는 유지하고, 이후 독후감 좋아요에 대한 사용자 알림 발송 내역 저장과 FCM 푸시만 생성하지 않습니다.
- 댓글 알림을 `N`으로 설정해도 댓글과 답글 등록은 유지하고, 이후 해당 독후감에 등록되는 댓글과 답글의 사용자 알림 발송 내역 저장과 FCM 푸시만 생성하지 않습니다.
- 댓글 또는 답글 자체에 등록하는 좋아요 알림은 댓글 작성자의 활동 알림이므로 독후감의 좋아요·댓글 알림 설정에 포함하지 않습니다.
- 알림을 끄기 전에 이미 생성된 알림은 유지하며, 다시 켜도 꺼져 있던 기간의 활동을 소급해 알림으로 만들지 않습니다.

## 프로필·배경사진 피드 알림

다음 항목은 구현된 피드 기능에 적용하는 정책입니다. 사진 반응과 대상별 댓글 좋아요 알림 발송 소스를 반영했습니다. 2026년 8월 27일 원격 개발 DB에서 기존 독후감 댓글 좋아요 템플릿 한 건과 대상별 템플릿 일곱 건을 멱등 등록·갱신하고 총 여덟 건의 활성 상태, 링크 및 한글 문자열을 재조회 검증했습니다.

- 다른 활성 사용자가 현재 프로필 사진 또는 현재 배경사진에 좋아요를 새로 등록하면 사진 소유자에게 알림을 저장하고, 활성 푸시 구독이 있으면 커밋 후 푸시를 발송합니다.
- 다른 활성 사용자가 현재 프로필 사진 또는 현재 배경사진에 댓글이나 답글을 새로 등록하면 사진 소유자에게 알림을 저장하고, 답글의 부모 댓글 작성자가 소유자와 다르면 해당 작성자에게도 중복 없이 알림을 저장합니다. 각 수신자의 활성 푸시 구독에는 커밋 후 푸시를 발송합니다.
- 프로필 사진 좋아요, 배경사진 좋아요, 프로필 사진 댓글, 배경사진 댓글과 두 사진 유형의 댓글 좋아요는 문구와 링크가 다른 대상별 템플릿으로 구분하되 기존 좋아요·댓글 상황 분류와 아이콘을 공유합니다.
- 발신자 닉네임을 사용자명 치환값으로 사용합니다.
- 프로필·배경사진의 좋아요·댓글·댓글 좋아요 템플릿에는 `/feed`와 사진 대상 유형 및 `#{targetNumb}` 쿼리를 저장합니다. 신규 알림과 푸시는 해당 자리표시자에 현재 사진 파일 번호를 치환하여 같은 카드의 댓글 목록을 직접 엽니다.
- 본인 사진에 대한 반응, 중복 좋아요 등록 및 좋아요 취소에는 알림을 생성하지 않습니다.
- 사진 반응에는 별도 알림 켜기·끄기 설정을 추가하지 않습니다. 다만 알림센터 저장과 푸시 발송은 각각 계정 상태와 활성 푸시 구독 정책을 따릅니다.
- 사진 댓글과 답글은 서로 독립된 작성 행위이므로 한 시간 중복 차단 대상에서 제외하고, 사진 좋아요는 기존 한 시간 중복 방지를 적용합니다.
- 사진 교체로 이전 피드와 반응 원본이 삭제되어도 이미 발송된 알림은 수신자 기록으로 유지합니다. 기존 발송 링크가 가리키는 사진이 현재 대상이 아니면 피드 단건 조회에서 만료로 처리하고 일반 피드는 계속 표시합니다.

## 중복 방지

- 수신자, 상황, 템플릿, 제목, 내용, 링크가 모두 같은 알림을 비교합니다.
- 동일한 알림이 최근 1시간 이내에 있으면 새 알림 생성을 생략합니다.
- 반복적인 좋아요 또는 팔로우 조작으로 같은 알림이 누적되는 것을 방지합니다.
- 댓글 좋아요 취소 후 1시간 안에 같은 표시 내용과 링크로 다시 좋아요가 등록되면 새 알림 생성을 생략합니다.
- 독서 타이머 기간 초과는 세션마다 독립된 목표시간 이벤트이므로 댓글 등록 알림과 같이 1시간 중복 차단 대상에서 제외합니다.

## 알림센터

- 삭제되지 않은 알림을 한 번에 20개씩 조회합니다.
- 다음 페이지 존재 여부를 판단하기 위해 서버는 내부적으로 한 건을 추가 조회할 수 있습니다.
- 스크롤 시 다음 20개를 추가 조회합니다.
- 읽은 알림도 목록에 표시하지만 읽지 않은 알림보다 어둡게 표현합니다.
- 알림 항목을 눌러 링크로 이동하면 해당 알림을 읽음 처리하고 읽음 처리 일시를 기록합니다.
- 푸시 알림을 눌러 링크로 이동한 경우에도 같은 알림을 읽음 처리합니다.
- 이미 읽은 알림의 읽음 요청은 성공으로 처리하는 멱등 방식입니다.
- 미읽음 배지는 읽지 않고 삭제되지 않은 알림 수를 표시합니다.

## 모두 지우기

- 모두 지우기는 현재 화면에 로드한 알림뿐 아니라 로그인 사용자의 삭제되지 않은 모든 알림에 적용합니다.
- 삭제 여부를 `Y`로 변경해 알림센터 노출 대상에서 제외합니다.
- 읽음 여부는 모두 지우기에서 변경하지 않습니다.
- 삭제 애니메이션 이후 알림 없음 상태를 표시합니다.
- 삭제 상태 알림은 알림 삭제 스케줄러가 물리 삭제합니다.

## 푸시 구독

- 브라우저 알림 권한 요청은 사용자의 명시적인 푸시 알림 켜기 클릭 직후 실행합니다.
- 허용된 FCM 토큰과 브라우저 구독 정보를 사용자 웹 푸시 구독에 저장합니다.
- 푸시 알림 켜짐 상태는 `사용 여부 = 'Y'`입니다.
- 푸시 알림을 끄면 구독 행을 삭제하지 않고 `사용 여부 = 'N'`으로 변경합니다.
- 다시 켜면 유효한 구독을 활성 상태로 저장하거나 갱신합니다.
- 같은 브라우저 FCM token을 다른 계정에서 활성화하면 이전 계정의 같은 token은 비활성화하여 한 token이 여러 계정의 푸시를 동시에 받지 않게 합니다.
- 현재 디바이스 로그아웃은 브라우저에서 확인한 현재 FCM token만 비활성화하고, 전체 디바이스 로그아웃은 회원의 모든 token을 비활성화합니다.
- FCM이 `Device unregistered`를 반환하면 해당 토큰은 더 이상 사용할 수 없는 구독으로 처리해야 합니다.
- 푸시를 받지 못해도 알림센터의 DB 알림은 유지됩니다.

## 알림 유형 표시

- 관리자는 `알림 아이콘 관리` 화면에서 SVG 또는 PNG 아이콘을 코드별 한 행으로 등록합니다. 아이콘 코드는 사용 중인 알림 상황 코드 분류값 중에서만 선택할 수 있으며 서버에서도 같은 조건을 검증합니다.
- `알림 상황 코드.DEFAULT`는 알림 상황별 아이콘을 특정할 수 없을 때 사용하는 기본 아이콘 코드입니다.
- `알림 상황 코드.FOLLOW`는 팔로우 요청과 독서 모임 알림이 공유하며 관리자 화면에는 `팔로우 요청/모임`으로 표시합니다.
- `알림 상황 코드.LIKE`는 독후감 좋아요와 댓글·대댓글 좋아요 알림이 공유하며 관리자 화면에는 `좋아요`로 표시합니다.
- 프로필·배경사진 좋아요도 기존 좋아요 아이콘을 공유하고, 사진 댓글과 답글은 기존 댓글 아이콘을 공유합니다.
- 통합 전 알림 상황 분류값 `CLUB`과 댓글 좋아요는 템플릿, 알림 이력 및 아이콘을 각각 `FOLLOW`와 `LIKE`로 이전한 뒤 공통코드 세부 항목에서 삭제합니다.
- 같은 아이콘 상황 안에서도 문구와 링크가 다른 업무는 사용자 팔로우와 독서모임 초대, 독후감 좋아요와 댓글 좋아요처럼 별도 템플릿 코드로 구분합니다.
- 업로드 파일은 200KB 이하의 정사각형 이미지이며 한 변은 16px 이상 256px 이하여야 합니다.
- PNG는 서버에서 다시 인코딩해 메타데이터를 제거하고, SVG는 UTF-8 XML·루트 네임스페이스·크기·외부 참조 및 실행 요소를 검증한 뒤 원본을 저장합니다.
- 검증한 원본은 전용 알림 아이콘 원본의 알림 아이콘 바이너리에 저장하며 일반 파일 테이블이나 배포 서버 파일 경로를 사용하지 않습니다.
- 알림 아이콘 원본의 알림 상황 코드가 PK이며 아이콘 번호와 별도 관리명은 사용하지 않습니다. 화면 표시명은 알림 상황 코드 공통코드명을 사용합니다.
- 아이콘 이미지는 신규 버전을 만들지 않고 같은 알림 상황 코드 행을 직접 수정합니다. 따라서 같은 알림 상황의 과거 알림에도 수정된 이미지가 표시됩니다.
- 알림 템플릿과 발송 내역은 기존 알림 상황 코드로 아이콘을 결정하며 별도 아이콘 식별 컬럼을 저장하지 않습니다.
- 관리자 아이콘 목록은 알림 상황 코드의 모든 분류값을 기준으로 조회하고 아이콘 등록 여부를 함께 표시합니다.
- 사용자 알림센터 목록 조회는 페이징한 사용자 알림 발송 내역의 알림 상황 코드로 알림 아이콘 원본을 조인하여 MIME 유형과 바이너리를 함께 반환하고, 상황별 아이콘이 없으면 `DEFAULT` 행을 사용합니다. 별도 공개 아이콘 API는 사용하지 않습니다.
- `DEFAULT` 아이콘도 없거나 조인된 아이콘 표시가 실패하면 사용자 화면의 기존 기본 알림 아이콘으로 대체합니다. 브라우저 푸시스템 아이콘은 기존 고정 정적 아이콘을 유지합니다.

## 계정 수명주기

- 계정 비활성화와 영구 탈퇴 대기에는 개인 차단 관계를 보존하며 복귀 후에도 기존 관계를 그대로 적용합니다.
- 댓글 좋아요 알림은 기존 계정 수명주기 정책을 적용하며 `활성` 회원 간 신규 좋아요에만 생성합니다.
- 프로필·배경사진 반응 알림도 기존 계정 수명주기 정책을 적용하며 활성 회원 간 신규 좋아요·댓글·답글에만 생성합니다.
- `비활성화` 또는 영구 탈퇴 대기 수신자에게는 댓글 좋아요와 독서 모임 초대를 포함한 새 알림과 푸시를 생성하지 않습니다.
- 수신자가 비활성화 또는 영구 삭제 대기 상태로 전환되면 받은 알림을 삭제 상태로 변경하고 복귀 시 자동 복원하지 않습니다.
- 계정 복귀 시 유효한 독서 모임 초대가 다시 표시되더라도 기존 초대 알림을 복원하거나 재발송하지 않습니다.
- `비활성화` 또는 영구 탈퇴 대기 전환 시 모든 기기 푸시 구독을 비활성화하며, 재로그인이나 탈퇴 취소만으로 자동 활성화하지 않습니다. 사용자가 다시 명시적으로 푸시 알림을 켜야 합니다.
- 계정 상태 전환 전에 예약된 독서 타이머 기간 초과 알림은 취소하며 복귀 또는 탈퇴 취소 뒤 자동 복원하거나 재발송하지 않습니다.
- 영구 삭제 시 사용자 웹 푸시 구독의 회원 푸시 구독 행을 물리 삭제합니다.
- 댓글 좋아요 발신자가 탈퇴하거나 대상 댓글이 삭제돼도 이미 발송된 알림은 수신자의 기록으로 유지합니다.
- 사진이 교체되거나 반응을 남긴 사용자가 탈퇴해 반응 원본이 삭제되어도 사진 소유자에게 이미 발송된 알림은 수신자의 기록으로 유지합니다. 사진 소유자 본인의 계정 상태가 변경되면 수신자 알림의 기존 수명주기 정책을 우선 적용합니다.
- 유지된 알림은 수신자의 모두 지우기와 알림 삭제 스케줄러 및 영구 탈퇴 정책에 따라 정리합니다.
- 알림 아이콘 원본은 회원 소유 데이터가 아닌 서비스 전역 운영 자산이므로 회원 비활성화, 영구 탈퇴 요청·취소 및 물리 삭제와 무관하게 영구 보존합니다.
- 아이콘 이미지에는 개인정보나 민감정보를 포함하지 않으며 인증된 사용자 알림 목록 조회에서만 알림 행과 조인해 제공합니다.
- 독후감별 좋아요·댓글 알림 설정은 독후감 행과 함께 보존합니다. `비활성화` 또는 영구 탈퇴 대기 상태에서는 계정 제한과 독후감 비공개 처리로 새 활동 알림이 중지되며, 복귀 후 사용자가 독후감을 다시 공개하면 보존된 설정을 그대로 적용합니다.
- 유예기간 후 독후감이 물리 삭제되면 해당 독후감의 좋아요·댓글 알림 설정도 함께 삭제하며 복구하지 않습니다.
