# 공지사항 운영 정책

## 개요

- 적용 대상은 관리자 공지사항 작성·버전·배포 기능과 사용자 공지 목록·상세·이미지 조회 기능입니다.
- 기준일은 2026-08-19입니다.
- 이 문서는 현재 구현된 공지사항 데이터와 접근 정책의 기준 문서입니다.

## 목적과 소유권

- 공지사항은 관리자가 작성하고 사용자에게 배포하는 운영 콘텐츠입니다.
- 공지 본문과 이미지는 특정 사용자가 소유하는 콘텐츠가 아니며 사용자 계정 수명주기와 독립적으로 보존합니다.

## 버전과 배포

- 공지사항은 `NOTI_NUMB` 주키와 `VERS_NUMB` 버전 부키의 복합 기본키를 사용합니다.
- 최초 버전은 `1`이며 현재 배포 중이 아닌 버전을 편집해 저장하면 선택한 `(NOTI_NUMB, VERS_NUMB)` 행을 수정합니다.
- `DPLY_YSNO = 'Y'`인 현재 배포 버전을 편집해 저장할 때만 같은 `NOTI_NUMB`의 현재 최대 `VERS_NUMB + 1`로 새 미배포 행을 만듭니다.
- 새 버전 저장만으로 사용자에게 노출하지 않으며 현재 배포 중인 원본은 새 버전을 명시적으로 배포하기 전까지 변경하지 않습니다.
- 하나의 `NOTI_NUMB`에서는 한 버전만 `DPLY_YSNO = 'Y'`일 수 있습니다. 다른 버전을 배포하면 이전 배포본은 같은 트랜잭션에서 배포 해제합니다.
- 이전 버전 행과 과거 배포 일시는 공지가 유지되는 동안 운영 이력으로 보존하며 현재 미배포 상태인 이전 버전은 관리자 상세에서 수정하거나 다시 배포할 수 있습니다.
- 최초 등록 관리자와 등록 일시는 모든 버전에서 유지하고, 새 버전을 만든 관리자는 수정 관리자와 수정 일시로 기록합니다.
- 배포 관리자와 배포 일시는 수정 이력과 분리된 `DPLY_ADMN`, `DPLY_DATE`에 기록합니다.
- 기존 구조에서 `UPDT_ADMN`, `UPDT_DATE`에 저장한 배포 감사정보는 마이그레이션 시 `DPLY_ADMN`으로 한 번만 이전하고 수정 이력에서는 제거합니다.
- 카테고리는 `안내`, `점검`, `업데이트`, `이벤트` 공통코드 중 하나를 버전별로 저장합니다.
- 상단 고정 여부는 버전별로 저장하며 고정된 배포 공지를 일반 공지보다 먼저, 같은 고정 상태에서는 최근 배포 순으로 노출합니다.
- 관리 컬럼은 등록자, 등록일, 수정자, 수정일, 배포자, 배포일 순서로 배치합니다.

## 본문과 파일

- 관리자 본문 편집기는 Summernote를 사용합니다.
- Summernote 이미지 업로드는 JPG와 PNG만 허용하고 서버가 이미지를 디코딩한 뒤 새 파일로 재인코딩합니다.
- 공지 이미지는 사용자 프로필·배경 이미지와 분리된 `notice/yyMMdd/{UUID}.jpg|png` 객체 키에 저장합니다.
- 로컬 저장소에서는 공용 저장 루트 아래 같은 객체 키를 사용하고 S3에서는 같은 객체 키를 버킷에 사용합니다.
- 저장 본문은 허용된 HTML만 남기고 스크립트, 이벤트 속성, 외부 이미지와 위험한 CSS URL 표현을 제거합니다.
- 공지 이미지 응답은 관리자 인증 또는 `ACTIVE` 사용자 인증을 요구하며 브라우저 공유 캐시에 저장하지 않습니다.

## 계정 상태

- `ACTIVE` 사용자만 현재 배포 공지 목록, 상세와 이미지를 조회할 수 있습니다.
- `WITHDRAWN`, `DELETE_PENDING`, `SUSPENDED` 사용자는 공지 화면과 공지 이미지 URL에 접근할 수 없습니다.
- 사용자 상세 조회 시 `TB_USVIEW`에 `VIEW_TYPE = 'NOTICE'`, 공지 번호와 사용자 번호를 복합키로 한 최초 읽음 이력을 멱등하게 저장합니다.
- 읽음 이력은 해당 사용자와 시스템만 접근할 수 있으며 다른 사용자에게 공개하지 않습니다.
- 목록에서 읽음 이력이 없는 공지는 빨간 점으로 표시하고 상세 조회가 성공하면 읽음으로 전환합니다.
- 홈 화면은 현재 배포 공지 중 로그인 사용자의 읽음 이력이 없는 공지 제목만 최근 배포 순서로 조회하여 검색 영역 아래의 한 줄 가로 슬라이드에 표시합니다.
- 홈 슬라이드는 제목만 노출하며 제목을 선택하면 공지 상세로 이동하고, 상세 조회가 성공한 시점에 기존 정책과 동일하게 읽음 이력을 저장합니다.
- 홈 미읽음 공지 조회가 실패하거나 미읽음 공지가 없으면 기존 홈 콘텐츠를 유지하고 공지 슬라이드를 표시하지 않습니다.
- 새 버전을 배포하면 해당 공지 번호의 기존 읽음 이력을 삭제하여 모든 활성 사용자에게 다시 미읽음으로 표시합니다.
- `WITHDRAWN`, `DELETE_PENDING`, `SUSPENDED` 상태에서는 공지 접근과 신규 읽음 이력 생성을 중지하지만 기존 읽음 이력은 유지합니다.
- 계정 재활성화 또는 영구 탈퇴 취소 시 기존 읽음 상태를 그대로 복원합니다.
- 사용자 물리 삭제 시 외래키 연쇄 삭제로 해당 사용자의 읽음 이력을 함께 삭제합니다.
- 사용자 영구 삭제 시 공지사항과 공지 이미지에는 사용자 FK가 없으므로 삭제하거나 익명화하지 않습니다.

## 실패와 복구

- 현재 배포 버전의 새 버전 저장 또는 미배포 버전의 같은 버전 수정에 실패하면 해당 저장 트랜잭션을 롤백합니다.
- 배포 전환은 이전 버전 배포 해제와 선택 버전 배포를 한 트랜잭션에서 처리하며 일부만 실패하면 전체 변경을 롤백합니다.
- 이미지 업로드가 실패하면 본문에 이미지 URL을 삽입하지 않고 관리자가 다시 시도할 수 있습니다.
- 관리자가 공지를 삭제하면 같은 `NOTI_NUMB`의 모든 버전, 모든 계정 상태의 `TB_USVIEW` 읽음 이력과 각 버전 본문이 참조하는 공지 전용 실제 파일을 함께 삭제합니다.
- 공지 삭제는 계정 재활성화나 영구 탈퇴 취소 시 복원하지 않으며 알림, 푸시 구독과 소셜 관계에 별도 변화를 만들지 않습니다.
- 저장소 파일 삭제가 실패하면 데이터베이스의 공지와 읽음 이력 삭제를 롤백하여 관리자가 같은 삭제를 다시 시도할 수 있게 합니다. 이미 삭제된 저장 객체의 재삭제는 멱등하게 처리합니다.
