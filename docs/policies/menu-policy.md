# 메뉴 및 화면 노출 정책

## URL별 헤더

- 사용자가 화면 URL에 접근하면 사용자 화면 메뉴에서 현재 URL과 일치하는 메뉴를 조회합니다.
- 정확히 일치하는 URL을 우선합니다.
- 메뉴 URL이 `/`로 끝나는 경로형 메뉴는 하위 URL의 접두사로 일치할 수 있습니다.
- 여러 메뉴가 일치하면 더 긴 URL을 우선해 가장 구체적인 메뉴를 선택합니다.
- 일치하는 메뉴가 있으면 홈 화면을 제외하고 헤더에 메뉴명을 표시합니다.
- 일치하는 메뉴가 없으면 기존 서비스 로고를 표시합니다.
- 홈 화면은 메뉴 조회 결과와 관계없이 서비스 로고를 헤더 왼쪽부터 표시합니다.
- 공통 헤더 하단에는 그림자를 표시하지 않습니다.
- 하단 내비게이션의 루트 화면인 `/home`, `/peed`, `/timer`, `/mypage/profile`에서는 뒤로가기 버튼 영역을 만들지 않고 메뉴명을 헤더 왼쪽부터 표시합니다.
- 하단 내비게이션 루트가 아닌 공통 레이아웃 화면에서는 뒤로가기 버튼을 표시하고 메뉴명을 버튼 영역 오른쪽부터 표시합니다.

## 화면 URL 네임스페이스

- 독후감 등록, 상세 및 공개 독후감 목록 화면은 `/report` 하위 경로를 사용합니다.
- `/book` 하위 화면 경로는 도서 검색과 도서 정보 화면에만 사용합니다.
- 사용자 화면 메뉴의 메뉴 URL, 알림 템플릿의 알림 템플릿 링크와 사용자 알림 발송 내역의 발송 알림 링크는 프론트엔드 라우터 경로와 동일하게 유지합니다.

## 햄버거 메뉴

- `화면 노출 여부 = 'Y'`이고 `사용 여부 = 'Y'`인 메뉴만 목록에 표시합니다.
- 상위 메뉴 번호는 메뉴 한 건의 단일 식별자이고 상위 메뉴 번호는 바로 위 상위 메뉴를 참조합니다.
- 메뉴 단계는 1부터 3까지만 허용하며, 상위 메뉴가 없으면 1단계이고 하위 메뉴는 상위 메뉴 단계보다 정확히 1만큼 큽니다.
- 사용자 메뉴 API는 `childList`를 가진 최대 3단계 트리로 응답합니다.
- 메뉴 정렬은 최상위 목록과 각 상위 메뉴의 직계 하위 목록마다 정렬 순서, 상위 메뉴 번호 순으로 독립 적용합니다.
- 숨김 또는 미사용 상위 메뉴 아래의 하위 메뉴는 자신의 노출·사용 여부가 Y여도 사용자 메뉴 트리에 단독으로 표시하지 않습니다.
- URL이 없는 메뉴는 하위 메뉴를 묶는 그룹으로 사용할 수 있으며, 하위 메뉴가 있으면 클릭 시 화면 이동 대신 아코디언을 펼치거나 접습니다.
- 메뉴명과 이동 URL은 하드코딩하지 않고 사용자 메뉴 API 응답을 사용합니다.
- 설정, 알림, 로그아웃처럼 별도 고정 기능으로 관리되는 항목은 사용자 메뉴 목록과 독립적으로 표시할 수 있습니다.

## 관리자 계층 관리

- 관리자는 사용자 메뉴 상세에서 상위 메뉴를 선택해 1·2·3단계 메뉴를 등록하거나 수정합니다.
- 자기 자신 또는 자신의 하위 메뉴를 상위 메뉴로 선택하는 순환 참조는 허용하지 않습니다.
- 기존 하위 트리를 이동했을 때 하나라도 3단계를 넘으면 수정하지 않습니다.
- 하위 메뉴가 있는 메뉴는 삭제하지 않으며, 하위 메뉴를 먼저 이동하거나 삭제해야 합니다.
- 자기참조 외래키는 `ON DELETE RESTRICT`로 구성해 서비스 검증을 우회한 트리 단절도 차단합니다.

## 설정 화면 메뉴

- `설정`은 사용자 화면 메뉴의 1단계 기준 메뉴로 유지하고 `알림 설정`, `사용자 관리`, `계정 비활성화 및 탈퇴`를 직계 2단계 메뉴로 관리합니다.
- `팔로우 관리`, `팔로워 관리`, `차단 관리`는 `사용자 관리` 아래의 3단계 메뉴로 관리합니다.
- 설정 화면은 메뉴명, 이동 URL, 정렬 순서와 하위 구조를 하드코딩하지 않고 `/api/user-menu/children` 응답을 사용합니다.
- 설정 기준 메뉴는 햄버거 노출 여부와 무관하게 조회할 수 있으며, 화면에 표시하는 하위 메뉴는 `화면 노출 여부 = 'Y'`이고 `사용 여부 = 'Y'`인 항목으로 제한합니다.

## 계정 상태와 데이터 보존

- 사용자 메뉴 구성은 특정 회원의 소유 데이터가 아닌 서비스 전역 운영 설정으로 보존합니다.
- `비활성화`, 영구 탈퇴 대기, `이용정지` 계정은 기존 계정 제한 전용 화면을 사용하며 일반 햄버거 메뉴에 접근하지 않습니다.
- 계정 재활성화 또는 영구 탈퇴 취소 뒤에는 과거 개인 메뉴 상태를 복원하지 않고 당시 최신 사용자 메뉴 트리를 조회합니다.
- 메뉴 구성 변경은 알림, 푸시 구독, 소셜 관계 및 회원 데이터의 보존·삭제 범위를 변경하지 않습니다.

## 역할 구분

- URL에 따른 메뉴명과 메뉴 목록은 서버가 데이터베이스 기준으로 제공합니다.
- 실제 화면 이동과 헤더 렌더링은 프론트엔드 라우터와 헤더 컴포넌트가 담당합니다.
- 이 기능은 화면 표시 정책이며, 보안이 필요한 URL의 최종 접근 권한은 Spring Security에서 별도로 검증해야 합니다.
- Swagger와 API 문서는 관리자 역할만 접근할 수 있습니다.

## 등록되지 않은 URL

- 로그인 사용자가 프론트엔드 라우터에 등록되지 않은 URL에 접근하면 전용 안내 알럿을 표시합니다.
- 안내는 공통 SweetAlert의 경고 알럿으로 표시하며 페이지를 찾을 수 없다는 설명과 홈 이동 버튼만 제공합니다. 공통 헤더와 하단 내비게이션은 표시하지 않습니다.
- 영구 삭제 대기와 관리자 이용 정지 등 일반 화면 접근이 제한된 계정은 URL 안내보다 기존 제한 전용 화면을 우선 표시합니다.
- 미인증 사용자는 기존 인증 정책에 따라 로그인 화면으로 이동합니다.
- 등록되지 않은 URL 안내는 사용자 데이터를 생성·수정·보존·삭제·복원하지 않으며 알림, 푸시 구독 및 소셜 관계에도 영향을 주지 않습니다.
