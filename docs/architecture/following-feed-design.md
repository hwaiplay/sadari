# 본인·팔로잉 피드 기능 설계

## 개요

- 기준일: 2026년 8월 31일
- 상태: 피드 소스 구현 및 원격 개발 DB 템플릿 적용 완료, 사용자 차단 연계는 확정 정책을 반영한 미구현 설계
- 목적: 로그인 사용자 본인과 현재 팔로우 중인 활성 회원의 공개 독후감 및 프로필·배경사진 변경을 확인하고 좋아요·댓글로 교류할 수 있는 피드를 제공한다.
- 적용 범위: 사용자 하단 내비게이션의 피드 화면, 팔로우 관계 기반 활동 조회, 독후감 최초 공개 시각, 프로필·배경사진 변경 시각, 범용 좋아요·댓글과 알림 연계이다.
- 구현 여부: 피드 조회 API와 화면, 범용 좋아요·댓글, 사진 변경 시각, 독후감 최초 공개 시각, 이전 사진 반응 정리 및 알림번호 기반 대상 라우팅 소스를 적용했다.

## 확정 범위

### 포함 기능

- 현재 로그인 사용자 본인과 팔로우 중인 회원의 피드 대상 활동을 조회한다.
- 작성자의 계정 상태가 활성인 경우에만 노출한다.
- 공개 상태인 완독 및 중단 독후감을 모두 노출한다.
- 읽는 중 독후감과 비공개 독후감은 노출하지 않는다.
- 팔로우 시작 전에 작성된 공개 독후감도 노출한다.
- 독후감이 처음 공개된 시각을 기준으로 최신순 정렬한다.
- 사용자가 프로필 사진을 변경하면 새 프로필 사진 피드를 노출한다.
- 사용자가 배경사진을 변경하면 새 배경사진 피드를 노출한다.
- 사진 교체로 이전 파일이 삭제되면 이전 사진 피드와 연결된 좋아요·댓글도 함께 삭제한다.
- 모든 피드 유형에서 좋아요, 댓글, 답글 및 댓글 좋아요를 제공한다.
- 작성자 프로필과 독후감 상세 화면으로 이동할 수 있다.

### 제외 기능

- 독서 시작 및 독서 완료를 별도 활동으로 생성하는 기능
- 독서 모임 활동
- 팔로우, 좋아요 또는 댓글 행위 자체를 별도 피드 항목으로 노출하는 기능
- 추천 알고리즘과 광고성 콘텐츠
- 별도 피드 활동 이력 저장소
- 회원가입 및 외부 로그인 과정에서 자동으로 저장된 최초 프로필 사진 노출

## 현행

- 사용자 간 팔로우 관계, 공개 독후감, 독후감 좋아요, 댓글·답글 및 관련 알림 기능이 구현되어 있다.
- 공개 독후감 목록은 활성 작성자의 공개된 완독 및 중단 기록을 제공한다.
- 독후감 등록일과 일반 수정일은 저장하지만 독후감이 처음 공개된 시점을 독립적으로 구분하지 않는다.
- 프로필과 배경사진은 사용자 기본정보가 각각 현재 파일을 참조하며, 사진 교체 시 새 파일을 저장하고 이전 파일 메타정보와 물리 파일을 삭제한다.
- 파일 메타정보에는 등록 시각이 있지만 회원가입·외부 로그인 자동 저장과 사용자 직접 변경을 구분하는 사진별 변경 시각은 없다.
- 좋아요 저장 구조는 대상 유형과 대상 번호를 사용하지만 현재 서비스 검증과 알림은 독후감만 허용한다.
- 댓글 저장 구조와 API는 독후감 번호에 종속되어 있어 사진 피드에 그대로 사용할 수 없다.
- 하단 내비게이션에는 피드 진입 항목이 있으나 팔로잉 활동 피드 조회와 화면은 미구현 상태이다.

## 목표 사용자 흐름

1. 로그인 사용자가 하단 내비게이션의 피드에 진입한다.
2. 서버는 로그인 사용자 본인과 현재 팔로우 관계를 기준으로 작성자 범위를 결정한다.
3. 서버는 공개 완독·중단 독후감과 현재 프로필·배경사진 변경 항목을 하나의 활동 목록으로 구성한다.
4. 화면은 활동 시각 내림차순으로 카드와 좋아요·댓글 상태를 표시한다.
5. 사용자는 카드에서 좋아요를 토글하거나 댓글 화면을 열어 댓글과 답글을 작성한다.
6. 카드 또는 작성자 영역을 선택하면 독후감 상세나 작성자 프로필로 이동한다.
7. 사용자가 작성자를 언팔로우하면 이후 조회부터 해당 작성자의 모든 활동이 피드에서 제외된다.

## 피드 유형

| 유형 | 생성 기준 | 활동 시각 | 대상 번호 | 유지 조건 |
| --- | --- | --- | --- | --- |
| 공개 독후감 | 완독·중단 독후감이 처음 공개됨 | 최초 공개 시각 | 독후감 식별번호 | 독후감이 공개 상태로 존재함 |
| 프로필 사진 변경 | 사용자가 프로필 편집에서 새 사진으로 교체함 | 프로필 사진 변경 시각 | 현재 프로필 파일 식별번호 | 현재 프로필이 해당 파일을 참조함 |
| 배경사진 변경 | 사용자가 프로필 편집에서 새 사진으로 교체함 | 배경사진 변경 시각 | 현재 배경 파일 식별번호 | 현재 배경사진이 해당 파일을 참조함 |

회원가입이나 외부 로그인 복구 과정에서 자동으로 저장한 최초 프로필 사진은 변경 활동으로 취급하지 않는다. 한 요청에서 프로필과 배경사진을 모두 변경하면 서로 다른 대상 번호를 가진 피드 두 건을 같은 활동 시각으로 생성한다.

## 노출 정책

### 작성자 조건

| 조건 | 피드 노출 |
| --- | --- |
| 현재 팔로우 중인 활성 회원 | 노출 |
| 팔로우하지 않는 회원 | 일반 목록에서 제외하되 유효한 알림 대상 단건은 조회 허용 |
| 로그인 사용자 본인 | 노출 |
| 계정 비활성화 회원 | 제외 |
| 영구 탈퇴 대기 회원 | 제외 |
| 이용정지 회원 | 제외 |
| 물리 삭제된 회원 | 제외 |

팔로우 등록일은 독후감 조회 범위를 제한하지 않는다. 새로 팔로우한 회원이 과거에 공개한 독후감도 피드에 포함한다.

### 독후감 조건

| 조건 | 피드 노출 |
| --- | --- |
| 공개 완독 독후감 | 노출 |
| 공개 중단 독후감 | 노출 |
| 공개 읽는 중 기록 | 제외 |
| 비공개 독후감 | 제외 |
| 삭제된 독후감 | 제외 |

독후감 상태와 공개 범위는 클라이언트 입력이 아니라 서버의 현재 원본을 기준으로 다시 검증한다.

### 사진 조건

| 조건 | 피드 노출 |
| --- | --- |
| 사용자가 직접 변경한 현재 프로필 사진 | 노출 |
| 사용자가 직접 변경한 현재 배경사진 | 노출 |
| 회원가입·외부 로그인에서 자동 저장된 최초 사진 | 제외 |
| 교체되어 현재 사용자 정보가 참조하지 않는 사진 | 제외 |
| 삭제되었거나 접근할 수 없는 사진 | 제외 |

사진 피드는 별도 활동 이력을 저장하지 않고 사용자 기본정보의 현재 사진 참조와 사진별 변경 시각을 조회해 구성한다. 따라서 사용자별로 프로필 사진 피드와 배경사진 피드는 각각 최대 한 건만 존재한다.

## 최초 공개 시각 정책

독후감 등록일이나 일반 수정일과 별개로 최초 공개 시각을 저장한다.

| 변경 상황 | 최초 공개 시각 처리 |
| --- | --- |
| 공개 독후감 신규 등록 | 등록 시각 저장 |
| 비공개 독후감 신규 등록 | 저장하지 않음 |
| 비공개 독후감을 처음 공개 | 공개 변경 시각 저장 |
| 공개 독후감 내용·평점·기간 수정 | 기존 시각 유지 |
| 공개 독후감을 비공개로 변경 | 기존 시각 유지하고 피드에서 숨김 |
| 비공개 전환 뒤 재공개 | 기존 시각 유지하고 원래 정렬 위치에 노출 |
| 독후감 삭제 | 원본과 함께 제거 |

재공개 시 최초 공개 시각을 갱신하지 않아 공개 여부를 반복 변경하는 방식으로 피드 상단에 재노출되는 것을 방지한다.

기존 데이터 이관 시 현재 공개된 완독 및 중단 독후감에는 기존 등록 시각을 최초 공개 시각으로 적용한다. 비공개 독후감과 읽는 중 기록에는 값을 적용하지 않는다.

## 사진 변경 시각 정책

사용자 기본정보에 프로필 사진 변경 시각과 배경사진 변경 시각을 각각 선택값으로 저장한다. 닉네임·한줄소개·계정 상태 등의 일반 수정 시각 하나만으로는 어느 사진이 변경되었는지 구분할 수 없으므로 공통 수정 시각을 사진 피드 생성 기준으로 사용하지 않는다.

| 변경 상황 | 프로필 사진 변경 시각 | 배경사진 변경 시각 |
| --- | --- | --- |
| 회원가입·외부 로그인에서 최초 사진 자동 저장 | 저장하지 않음 | 저장하지 않음 |
| 프로필 사진만 직접 변경 | 현재 시각으로 갱신 | 유지 |
| 배경사진만 직접 변경 | 유지 | 현재 시각으로 갱신 |
| 두 사진을 함께 직접 변경 | 같은 업무 시각으로 갱신 | 같은 업무 시각으로 갱신 |
| 닉네임·한줄소개만 수정 | 유지 | 유지 |
| 기존 사진을 새 사진으로 교체 | 현재 시각으로 갱신 | 해당하는 경우 현재 시각으로 갱신 |

사진 파일 저장, 사용자 참조 교체, 사진별 변경 시각 갱신, 이전 사진의 좋아요·댓글 정리는 하나의 트랜잭션에서 처리한다. 물리 파일 삭제는 현재 구현처럼 커밋 이후에 수행한다.

## 정렬과 페이지 조회

- 독후감의 최초 공개 시각과 사진별 변경 시각을 공통 활동 시각으로 변환하여 내림차순 정렬한다.
- 활동 시각이 같으면 피드 유형의 고정 순서와 대상 식별번호의 내림차순으로 순서를 고정한다.
- 활동 시각, 유형과 대상 번호의 고정 정렬을 적용하고 열 건 단위 페이지 조회를 사용한다.
- 새 활동이 등록된 뒤 최신 목록이 필요하면 첫 페이지부터 다시 조회한다.
- 피드 보존기간을 별도로 제한하지 않고 현재 조회 조건을 만족하는 전체 독후감을 페이지 단위로 제공한다.

## 피드 카드

모든 피드 카드는 다음 공통 정보를 제공한다.

- 작성자 프로필 이미지와 닉네임
- 활동 유형과 활동 시각
- 좋아요 수와 로그인 사용자의 좋아요 여부
- 댓글 수
- 좋아요 및 댓글 진입 명령

독후감 카드는 다음 정보를 추가로 제공한다.

- 도서 표지, 제목과 저자
- 독서 상태
- 별점
- 독후감 내용 미리보기

프로필 사진과 배경사진 카드는 각각 변경된 현재 이미지와 `프로필 사진을 변경했습니다`, `배경사진을 변경했습니다` 문구를 제공한다.

내용 미리보기는 목록 가독성을 위해 제한된 영역에 표시하고 전체 내용은 독후감 상세에서 제공한다. 서버 응답에는 화면에서 필요한 원문 범위만 포함하고 비공개 데이터는 포함하지 않는다.

## 상호작용 정책

- 범용 좋아요 구조에 프로필 사진과 배경사진 대상 유형을 추가한다.
- 좋아요 요청은 대상 유형별로 실제 독후감 또는 현재 사진이 존재하고 접근 가능한지 서버에서 검증한다.
- 독후감 전용 댓글 구조를 대상 유형과 대상 번호 기반의 범용 댓글 구조로 전환한다.
- 기존 독후감 댓글·답글 데이터는 독후감 대상 유형으로 이관한다.
- 댓글의 대상 유형은 공개 독후감, 현재 프로필 사진, 현재 배경사진만 허용한다.
- 피드와 독후감 상세에서 좋아요 또는 댓글을 변경하면 같은 원본 상태가 갱신된다.
- 댓글 깊이, 논리 삭제, 수정 충돌 방지, 비속어 검사 및 댓글 좋아요 정책은 기존 댓글 정책을 유지한다.
- 독후감별 좋아요 및 댓글 알림 설정을 그대로 적용한다.
- 프로필·배경사진에 다른 활성 사용자가 좋아요를 새로 등록하면 사진 소유자에게 좋아요 알림과 푸시를 보낸다.
- 프로필·배경사진에 다른 활성 사용자가 댓글 또는 답글을 새로 등록하면 사진 소유자에게 댓글 알림과 푸시를 보낸다. 답글은 사진 소유자와 부모 댓글 작성자가 다르면 부모 댓글 작성자에게도 알림을 보낸다.
- 본인 반응, 중복 좋아요 및 좋아요 취소에는 알림을 만들지 않는다.
- 사진 반응에는 독후감별 설정과 같은 개별 알림 켜기·끄기 기능을 추가하지 않는다.
- 프로필 사진 좋아요, 배경사진 좋아요, 프로필 사진 댓글, 배경사진 댓글과 각 사진 댓글 좋아요는 대상별 템플릿을 사용하되 기존 좋아요·댓글 상황 분류와 아이콘을 공유한다.
- 사진 반응 알림은 사진 유형과 현재 파일 번호를 이동 대상 정보로 저장한다. 알림번호 공통 경로에서 클릭 시점의 접근 권한을 확인한 뒤 사진 소유자 본인이면 마이페이지, 타인이면 사진 소유자의 공개 프로필에서 현재 사진과 댓글 목록을 연다. 교체되어 현재 사진이 아니거나 소유자가 정상 이용 상태가 아니면 대상 만료 안내 후 일반 알림 목록으로 복귀한다.
- 댓글과 답글은 각각 독립된 작성 행위이므로 같은 문구가 한 시간 안에 반복되어도 알림을 만들며, 좋아요는 기존 중복 방지 정책을 적용한다.
- 본인의 공개 완독·중단 독후감과 현재 사진도 피드 조회 대상이며 기존 상세 화면의 본인 상호작용 정책은 변경하지 않는다.

## 상태 변경과 삭제

### 팔로우 변경

- 팔로우가 생성되면 다음 피드 조회부터 대상 회원의 기존 공개 독후감을 포함한다.
- 언팔로우가 완료되면 다음 피드 조회부터 대상 회원의 모든 독후감을 제외한다.
- 이미 발송된 좋아요·댓글 알림과 독후감 원본 데이터는 팔로우 변경으로 수정하지 않는다.

### 독후감 변경

- 공개 독후감이 비공개로 변경되면 즉시 피드에서 제외한다.
- 비공개 전환만으로 기존 좋아요와 댓글을 삭제하지 않는다.
- 재공개하면 기존 좋아요와 댓글을 유지하며 최초 공개 시각의 원래 위치에 다시 노출한다.
- 독후감이 삭제되면 기존 정책에 따라 연결된 좋아요와 댓글·답글을 정리하고 피드에서도 제거한다.

### 사진 변경

- 프로필 또는 배경사진을 새 파일로 교체하면 새 대상 번호와 변경 시각으로 새 피드를 노출한다.
- 이전 사진은 현재 사용자 정보의 참조가 해제되는 즉시 피드 조회 대상에서 제외한다.
- 이전 파일을 삭제하기 전에 해당 사진을 대상으로 저장된 좋아요, 댓글·답글 및 댓글 좋아요를 함께 삭제한다.
- 이전 사진의 반응을 새 사진으로 이전하지 않는다.
- 사진 교체 전에 이미 발송한 반응 알림은 삭제하지 않는다. 해당 알림을 선택했을 때 저장된 파일 번호가 더 이상 현재 사진이 아니면 대상 만료를 안내하고 일반 알림 목록으로 복귀한다.
- 물리 파일 삭제에 실패해 저장소 객체가 남더라도 사용자 참조가 없으므로 이전 사진을 피드에 다시 노출하지 않는다.

### 계정 수명주기

- 계정 비활성화와 영구 탈퇴 대기 전환 시 작성자의 독후감은 기존 정책에 따라 비공개 처리되므로 피드에서 제외한다.
- 비활성화·영구 탈퇴 대기·이용정지 상태에서는 작성자의 현재 사진 피드도 노출하지 않는다.
- 활성 상태가 아닌 발신자 또는 수신자에 대해서는 새 사진 반응 알림과 푸시를 만들지 않는다.
- 계정이 다시 활성화되어도 독후감 공개 상태를 자동 복원하지 않는다.
- 복귀한 사용자가 독후감을 직접 재공개하면 최초 공개 시각을 유지한 원래 위치에 노출한다.
- 영구 삭제가 완료되면 회원 원본, 독후감 및 정책상 보존하지 않는 연결 데이터를 삭제하며 피드에서 복원하지 않는다.
- 이용정지 상태에서는 작성자의 콘텐츠를 피드에 노출하지 않는다.

## 조회 계약

### 요청

피드 목록 조회 API는 인증된 로그인 사용자를 기준으로 동작하며 다음 선택값을 받을 수 있다.

- 조회할 페이지 번호

작성자 번호, 공개 여부 또는 계정 상태를 클라이언트가 조회 범위로 지정하지 않는다.

### 응답

응답은 공통 응답 구조 안에 다음 정보를 포함한다.

- 독후감 카드 목록
- 다음 페이지 존재 여부
- 현재 페이지 번호

각 카드에는 피드 유형, 대상 번호, 활동 시각, 화면 표시 정보와 좋아요·댓글 상태를 포함한다. 내부 인증값, 비공개 독후감 정보와 저장소 내부 경로는 응답하지 않는다.

## 서버 검증과 보안

- 인증 사용자 번호로 본인과 팔로우 관계를 서버에서 조회한다.
- 알림 이동은 대상 유형과 대상 번호를 받는 단건 API를 사용한다. 단건 조회는 활성 작성자의 현재 공개 콘텐츠인지 다시 검증하며 일반 목록의 팔로우 여부와 무관하게 해당 알림 수신자가 원래 참여한 공개 콘텐츠를 열 수 있다.
- 사용자 차단 기능을 구현한 뒤에는 로그인 사용자와 작성자 사이에 어느 방향의 차단 관계라도 있으면 해당 작성자의 모든 피드 카드를 원본 조회에서 제외한다.
- 같은 구현에서 프로필·배경사진 직접 경로도 인증 사용자와 사진 소유자의 양방향 차단 관계를 확인하므로 피드에서 숨긴 사진을 알려진 경로로 다시 조회할 수 없게 한다.
- 작성자 계정 상태, 독후감 공개 범위와 사진의 현재 참조 여부를 원본 데이터에서 검증한다.
- 좋아요와 댓글 요청에서도 대상 유형에 따라 독후감 공개 범위 또는 사진의 현재 참조 여부와 작성자 상태를 다시 확인한다.
- 조회 중 독후감이 비공개 또는 삭제 상태로 변경되면 상세 진입과 상호작용 요청을 거부하고 최신 피드를 다시 조회할 수 있게 한다.
- 목록 조회에서 비공개 필드를 조회한 뒤 화면에서만 숨기는 방식을 사용하지 않는다.
- 동적 정렬 조건을 외부 입력으로 받지 않고 확정된 최신 공개순을 서버에서 적용한다.

## 동시성과 실패 처리

- 독후감 최초 공개 시각 저장과 공개 상태 변경은 하나의 트랜잭션에서 처리한다.
- 사진 저장, 사용자 사진 참조와 변경 시각 갱신, 이전 사진 반응 정리는 하나의 트랜잭션에서 처리한다.
- 공개 상태 수정이 실패하면 최초 공개 시각만 저장되는 부분 성공을 허용하지 않는다.
- 기존 독후감 수정 충돌 검증을 유지하여 다른 탭이나 기기의 변경을 덮어쓰지 않는다.
- 피드 조회 실패 시 기존 목록을 임의로 비우거나 성공으로 처리하지 않고 재시도 가능한 오류 상태를 표시한다.
- 추가 페이지 조회 실패 시 이미 조회한 카드는 유지하고 추가 조회만 다시 시도할 수 있게 한다.
- 좋아요·댓글 변경 실패 시 화면의 낙관적 상태를 서버 원본으로 복원한다.

## 화면 상태

### 최초 조회

- 현재 사용자 메뉴에 등록된 피드 메뉴명을 사용한 공통 페이지 조회 상태를 표시한다.
- 조회 완료 뒤 카드 목록을 표시한다.

### 빈 상태

다음 상황에는 피드가 비어 있음을 안내한다.

- 본인과 팔로우 중인 사용자에게 표시할 공개 활동이 없음

두 상황은 필요하면 서로 다른 안내와 사용자 탐색 진입 동작을 제공할 수 있지만 데이터 조회 결과를 노출하지 않는다.

### 추가 조회

- 목록 끝에 도달하면 다음 페이지를 조회한다.
- 추가 조회 중에는 공통 소형 로딩 표시를 사용한다.
- 다음 페이지가 없으면 추가 요청을 중지한다.

## 대안과 선택 이유

### 별도 피드 활동 저장소

여러 차례의 프로필 변경 이력을 모두 보존하려면 별도 활동 저장소가 필요하다. 이번 정책은 이전 사진 파일이 삭제될 때 기존 피드도 삭제하므로 과거 이력을 보존하지 않는다. 따라서 독후감 원본, 현재 사진 참조와 팔로우 관계를 조합해 조회하며 별도 활동 저장소를 추가하지 않는다.

### 사용자 공통 수정 시각

사용자 공통 수정 시각 하나만 추가하면 닉네임·한줄소개 변경이 사진 피드로 오인될 수 있고 프로필과 배경 중 어느 사진이 변경되었는지 알 수 없다. 사진별 변경 시각 두 개를 분리해 저장하는 방식을 선택한다.

### 일반 수정일 기준 정렬

일반 수정일로 정렬하면 오탈자나 평점 수정만으로 오래된 독후감이 피드 상단에 반복 노출될 수 있다. 이를 방지하기 위해 최초 공개 시각을 별도로 저장하고 수정 시 유지한다.

### 팔로우 등록일 이후 데이터만 조회

팔로우 등록일 이후의 활동만 조회하면 새로 팔로우한 회원의 기존 공개 콘텐츠를 발견하기 어렵다. 현재 팔로우 관계를 기준으로 기존 공개 독후감과 현재 유지 중인 사진 변경 피드도 함께 제공하는 정책을 선택한다.

## 구현 영향 범위

### 데이터 계층

- 독후감 원본에 선택적인 최초 공개 시각을 추가한다.
- 사용자 기본정보에 선택적인 프로필 사진 변경 시각과 배경사진 변경 시각을 각각 추가한다.
- 기존 공개 완독 및 중단 독후감의 등록 시각을 최초 공개 시각으로 이관한다.
- 기존 회원의 현재 사진은 직접 변경 여부를 신뢰할 수 없으므로 사진별 변경 시각을 일괄 이관하지 않는다.
- 댓글 원본을 대상 유형과 대상 번호 기반으로 전환하고 기존 독후감 댓글을 이관한다.
- 팔로우 관계, 활성 작성자, 공개 독후감, 현재 사진과 좋아요·댓글 집계를 한 번의 목록 조회 흐름으로 구성한다.
- 최신 공개순 페이지 조회에 필요한 복합 인덱스를 적용한다.

### 백엔드

- 피드 조회 전용 Controller, Service, Mapper와 응답 DTO를 추가한다.
- 독후감 등록·수정 처리에서 최초 공개 시각 정책을 적용한다.
- 프로필 수정 처리에서 변경된 사진 종류별 시각 갱신과 이전 사진 반응 정리를 적용한다.
- 범용 좋아요의 허용 대상과 대상별 검증을 확장한다.
- 댓글 API와 데이터 계약을 대상 유형·대상 번호 기반으로 전환한다.
- 사진 좋아요·댓글 및 사진 댓글 좋아요 등록 처리에서는 반응 종류별 템플릿을 선택하고 사진 유형과 파일 번호를 이동 대상 정보로 저장한다.
- 알림센터와 푸시는 알림번호 공통 경로를 사용하고, 서버가 클릭 시점의 대상 및 권한 상태로 최종 피드 경로를 계산한다.
- 독후감 공개 범위, 사진의 현재 참조 여부와 작성자 상태 검증을 피드 조회와 상호작용에 동일하게 적용한다.

### 프론트엔드

- 하단 내비게이션 피드 경로에 전용 페이지를 연결한다.
- 피드 API와 타입, 무한 조회 상태 및 카드 목록을 추가한다.
- 기존 프로필 이미지, 도서 표지, 좋아요 및 댓글 컴포넌트를 재사용한다.
- 독후감, 프로필 사진과 배경사진 유형별 카드 표현을 추가한다.
- 최초 조회, 빈 상태, 추가 조회, 오류 및 재시도 상태를 제공한다.

## 검증 계획

### 서버 검증

- 로그인 사용자 본인과 현재 팔로우 중인 활성 작성자의 공개 완독·중단 독후감 및 현재 사진 변경만 일반 목록에 반환하는지 검증한다.
- 팔로우 이전에 공개된 독후감도 반환하는지 검증한다.
- 본인은 포함하고 비팔로우 사용자와 제한 상태 작성자의 독후감은 일반 목록에서 제외하는지 검증한다.
- 사용자 차단 기능을 구현할 때 어느 한쪽이 상대를 차단한 작성자의 독후감과 사진 카드가 양쪽 피드에서 제외되는지 검증한다.
- 같은 구현에서 차단 상대의 알려진 프로필·배경사진 경로를 직접 요청해도 이미지 바이트가 반환되지 않는지 검증한다.
- 읽는 중과 비공개 독후감을 제외하는지 검증한다.
- 최초 공개 시각과 고정 보조키로 순서가 안정적인지 검증한다.
- 비공개 독후감의 최초 공개 전환과 재공개가 확정 정책대로 정렬되는지 검증한다.
- 사용자 직접 사진 변경만 피드에 노출되고 회원가입·외부 로그인 자동 저장은 제외되는지 검증한다.
- 프로필과 배경사진을 각각 또는 동시에 변경했을 때 올바른 유형과 시각으로 노출되는지 검증한다.
- 닉네임·한줄소개 수정이 사진 피드를 생성하거나 상단으로 이동시키지 않는지 검증한다.
- 사진 교체 직후 이전 피드와 연결 반응이 제거되고 새 피드가 생성되는지 검증한다.
- 프로필·배경사진의 좋아요·댓글·댓글 좋아요가 각각 올바른 템플릿과 이동 대상 정보를 생성하는지 검증한다.
- 본인 반응, 중복 좋아요, 좋아요 취소 및 제한 상태 회원에 대해서는 새 알림이 생성되지 않는지 검증한다.
- 사진 교체 뒤 기존 반응은 삭제되지만 이미 발송된 알림은 유지되며 알림 대상 조회가 만료 상태를 반환하는지 검증한다.
- 언팔로우, 비공개 전환, 삭제와 계정 상태 변경이 다음 조회에 즉시 반영되는지 검증한다.
- 페이지 경계에서 중복과 누락이 없는지 검증한다.
- 좋아요·댓글 변경 후 피드와 상세의 집계가 일치하는지 검증한다.
- 대상 유형을 위조하거나 다른 사용자의 현재 사진이 아닌 파일 번호로 상호작용할 수 없는지 검증한다.

### 화면 검증

- 피드 카드, 최초 조회, 빈 상태, 추가 조회 및 오류 상태를 확인한다.
- 독후감, 프로필 사진과 배경사진 카드가 유형에 맞게 표시되는지 확인한다.
- 작성자 프로필과 독후감 상세 이동을 확인한다.
- 좋아요 토글과 댓글·답글 흐름을 확인한다.
- 프로필 이미지와 도서 표지 실패 시 공통 대체 이미지를 표시하는지 확인한다.
- 모바일 화면과 키보드 및 보조기기 접근성을 확인한다.

### 마이그레이션 검증

- 이관 전후 공개 독후감 건수가 일치하는지 확인한다.
- 기존 공개 완독·중단 독후감에만 최초 공개 시각이 설정되는지 확인한다.
- 비공개 및 읽는 중 기록의 최초 공개 시각이 비어 있는지 확인한다.
- 기존 회원의 사진별 변경 시각이 비어 있어 과거 자동 저장 사진이 신규 피드로 나타나지 않는지 확인한다.
- 기존 독후감 댓글이 대상 유형과 대상 번호를 유지하고 답글 관계와 댓글 좋아요가 보존되는지 확인한다.
- 한글 원문과 기존 좋아요·댓글 데이터가 변경되지 않았는지 확인한다.

## 완료 기준

- 피드가 로그인 사용자 본인과 현재 팔로우 중인 활성 회원의 공개 완독·중단 독후감 및 현재 프로필·배경사진 변경을 제공한다.
- 팔로우 이전에 공개된 독후감도 조회된다.
- 최초 공개 시각 기준 최신순과 페이지 경계가 안정적이다.
- 비공개, 삭제, 언팔로우 및 제한 계정 상태가 다음 조회에 반영된다.
- 사용자 차단 기능을 구현한 뒤에는 차단과 해제가 다음 조회에 반영되고, 차단 해제 뒤 팔로우 관계는 자동 복원되지 않으며 보존된 좋아요와 댓글만 양방향 차단 해제 후 다시 표시된다.
- 사진 교체 시 이전 사진 피드와 반응이 삭제되고 새 사진 피드가 생성된다.
- 좋아요·댓글·답글·댓글 좋아요가 대상 유형별 동일 원본을 사용한다.
- 관련 정책 문서, 데이터 정의, API 문서와 테스트가 구현 결과와 동기화된다.
