# 독서 모임 기능 설계

## 개요

- 목적: 비공개 초대형 모임과 공개 가입형 모임에서 같은 도서와 목표 기간을 공유하고, 개인 독서 기록과 모임 독후감을 연결해 반복 독서를 운영하는 기능을 설계한다.
- 적용 범위: 관심분야 설정, 모임 탐색·개설·가입·초대·퇴장, 회차, 개인 독서 기록, 독후감 공유, 다음 도서 추천·투표, 채팅·알림 및 모임장 선거이다.
- 기준일: 2026년 8월 20일이다.
- 구현 상태: 2026년 8월 14일 기준 관심분야 필수 선택 팝업, 모임 생성·찾기·가입, 모임장의 맞팔 초대와 가입 승인, 모임 독서 회차 및 활성 멤버별 `읽는 중` 독후감 일괄 생성을 구현한다. 기반 테이블은 회원 독서 관심분야, 독서 모임, 독서 모임 카테고리, 모임 회원 및 초대 예약석, 모임 가입 질문, 승인형 모임 가입 신청, 독서 모임 회차, 독서 모임 회차 참여이다.
- 정책 상태: 1차 출시의 정원, 가입·초대, 회차, 독후감, 퇴장, 다음 도서, 채팅, 메뉴, 관리자 운영, 모임장 선거 및 계정 수명주기 정책을 [독서 모임 정책 결정 항목](../policies/reading-club-policy-decisions.md)의 확정값으로 적용한다. 공통 신고의 대상·보존 정책은 [신고 접수 및 처리 정책](../policies/abuse-report-policy.md)에, 사용자 차단의 모임 공동 운영 예외는 [사용자 차단 기능 설계](user-blocking-design.md)에 확정했으며 구현은 후속 출시로 분리한다.

## 설계 결론

독서 모임은 계속 유지되는 공간이고 공동 독서는 반복되는 회차이다. 모임과 회차를 분리하고, 공개 여부와 가입 방식을 별도 속성으로 관리한다. 개인 책장 기록은 기존 독후감을 재사용하되 모임 독후감 열람 권한은 독후감의 공개 여부와 분리한다.

핵심 결론은 다음과 같다.

1. 모임은 `비공개`와 `공개`을 지원한다. 비공개 모임은 초대형이고 공개 모임은 즉시 가입형 `OPEN` 또는 승인형이다.
2. 공개 모임은 단일 공지사항 카테고리 분류 아래의 1뎁스 분류값을 대분류로, 그 자식 분류값을 실제 카테고리로 사용한다. 회원 관심분야와 모임별 1~3개 카테고리에 공지사항 카테고리 분류와 자식 분류값을 함께 저장하고 정확히 일치한 코드 수가 많은 모임을 먼저 노출한다.
3. 신규 회원은 최초 로그인 온보딩에서 관심분야를 선택할 수 있지만 관심분야 저장 여부와 온보딩 완료 여부 완료 처리는 분리한다. 관심분야가 없는 회원도 `내 모임`은 이용할 수 있으나 `모임 찾기`에서는 관심분야를 하나 이상 저장해야 공개 모임을 탐색할 수 있다.
4. 모임 도서와 목표 기간이 확정되면 그 시점의 모든 활성 모임원을 별도 선택 없이 참여자로 고정하고, 회원별 독후감을 `읽는 중` 상태로 생성해 같은 도서 번호, 목표 시작일 및 목표 종료일을 기록한다.
5. 참여자가 실제 독서 시작일과 종료일을 입력하면 연결된 하나의 독후감을 수정한다. 개인 화면과 모임 화면은 같은 행을 조회하므로 실제 기간을 이중 저장하지 않는다.
6. 모임 회차에 연결된 독후감은 전역 공개 여부가 `N`이어도 공개 시점 이후 권한이 있는 활성 모임원에게 보인다. 비회원과 외부 공개 화면에는 계속 보이지 않는다.
7. 독서 모임 회차 참여의 독후감 번호와 독후감 번호를 조인해 해당 독후감이 모임 회차에서 생성되었는지 판별한다. 독후감에 모임 구분 컬럼을 추가하지 않는다.
8. 도서 마스터에 없는 도서는 회차 확정 시 한 번만 멱등 등록하고 반환된 도서 번호를 모든 참여자 기록에 재사용한다.
9. 공개 여부와 관계없이 모임장은 맞팔 회원만 초대할 수 있다. 초대 발송 시 유효기간 동안 좌석 한 자리를 예약하는 안을 우선한다.
10. 일반 즉시 가입과 신청 승인은 활성 회원과 예약 좌석을 제외한 자리만 사용할 수 있다. 유효한 초대의 수락은 예약 좌석을 회원 좌석으로 전환하므로 정원 마감 사유로 실패하지 않는다.
11. 모임장은 모임원을 퇴장시킬 수 있다. 퇴장 즉시 모임 상세, 채팅 및 모임 전용 독후감 접근을 차단한다.
12. 다음 도서 추천과 선정 수명주기 및 모임장 선거 수명주기는 각각 유지하되, 투표 이벤트·선택지·유권자·투표용지는 공통 투표 모델로 관리한다. 다음 도서 선정 결과는 다음 회차 생성으로, 모임장 선거 결과는 권한 이전으로 각각 반영한다.
13. 사용자 사이드 메뉴는 `독서 모임` 상위 메뉴 아래 `내 모임`, `모임 찾기`를 두는 2뎁스로 구성한다. 관심분야 필수 정책은 기존 자격을 확인하는 `내 모임`에는 적용하지 않고 공개 모임을 추천·탐색하는 `모임 찾기`에만 적용한다.
14. 회원은 활성 세부 관심분야를 개수 제한 없이 선택할 수 있다.
15. 물리 삭제, 복구 불가능한 영구 이용 제한, 모임장의 자발적 승계 요청 또는 모임장 전용 다음 도서 확정 상태 시작 후 14일 미확정 등 확정 부재 사유가 발생하면 활성 모임원 선거로 다음 모임장을 선출한다.
16. 승인형 모임의 현재 가입 질문은 모임당 모임 가입 질문 한 행과 최대 5개 질문 컬럼으로 관리하고 모임이 존재하는 동안 유지한다. 신청 당시 질문 사본과 장문형 답변은 독서모임 승인 가입 신청 한 행에 함께 저장하되 승인·거절과 동시에 답변을 삭제한다.
17. 신고 저장은 독후감, 댓글, 모임 및 사용자를 포괄하는 공통 신고 이력을 사용한다. 신고 API·관리자 심사와 사용자 차단 구현은 후속 출시하고 1차 독서 모임 범위에서는 제외한다. 사용자 차단을 구현한 뒤에도 같은 모임의 운영 콘텐츠와 제3자인 모임장의 초대는 유지하고 개인 프로필 이동과 직접 상호작용만 제한한다.
18. 회차 목표 결과는 개인 독후감의 현재 상태와 분리해 마감한다. 목표 종료 전 `완독`인 회원만 달성자로 고정하고, 미달성자의 개인 독후감은 `읽는 중` 상태로 계속 유지한다.

## 자체 검토 결과와 정정 사항

기존 기획과 현행 구현을 다시 대조해 다음 오류와 충돌을 정정했다.

| 검토 항목 | 확인한 오류 또는 충돌 | 정정 설계 |
| --- | --- | --- |
| 정책 문서 무결성 | `reading-club-policy-decisions.md`가 설계 문서 내용으로 잘못 복제되어 정책 결정표가 사라져 있었다. | 설계 문서와 정책 결정 문서를 분리해 다시 작성한다. |
| 문서 완결성 | 기존 설계 문서가 신규 구현 영역 목록 중간에서 끝나 전체 흐름과 데이터 설계가 누락되어 있었다. | 사용자 흐름, 권한, 데이터, 동시성, 실패 처리 및 검증 기준까지 복원한다. |
| 공개 모임 | 비공개 맞팔 초대만 전제로 해 공개 탐색과 가입 승인 요구를 수용할 수 없었다. | 모임 공개 범위와 가입 방식을 분리한다. |
| 독후감 열람자 | 회차 참여자만 비공개 독후감을 본다는 안은 모든 모임원에게 보여야 한다는 확정 요구와 충돌했다. | 모임 공개 시점 이후 활성 모임원에게 공개하되 과거 회차 열람 범위는 별도 정책으로 남긴다. |
| 전역 공개와 모임 공개 | 독후감의 공개 여부를 바꾸면 개인이 비공개로 정한 독후감이 서비스 전체에 노출될 수 있다. | 전역 공개 플래그는 유지하고 모임 전용 API에서 모임원 권한을 별도로 검사한다. |
| 목표 기간과 실제 기간 | 공동 목표일과 개인 실제 독서일을 같은 의미로 계속 유지하면 조기 완독자의 실제 기간을 잃는다. | 회차가 목표 기간의 기준 원본이고, 개인 독후감은 최초 목표값을 받은 뒤 실제 기간 입력 시 갱신한다. |
| 실제 기간 이중 저장 | 모임 참여 테이블에도 실제 기간을 저장하면 개인 독후감과 불일치할 수 있다. | 회차 참여가 독후감 번호를 참조하고 개인·모임 화면 모두 독후감의 실제 기간을 조회한다. |
| 도서 다중 저장 | 현행 `setReport`를 참여자 수만큼 호출하면 같은 미등록 도서에 대해 중복 등록 경쟁과 외부 처리 반복이 발생한다. | 회차 확정 전에 도서를 한 번만 확보하고 참여자 독후감은 확정된 도서 번호만 사용한다. |
| 도서 동시성 | 현행 `dupBook` 조회 후 `setBook`을 수행하는 구조는 동시 요청 사이에 다른 트랜잭션이 같은 ISBN을 넣을 수 있다. | 업무 중복 방지 고유 제약을 이용한 멱등 등록 후 ISBN 재조회 방식으로 단일 도서 번호를 확정한다. |
| 회차 생성 시점 | 회차 시작 시 독후감을 만들면 도서와 기간이 정해진 즉시 개인 독후감에도 등록되어야 한다는 요구를 만족하지 못한다. | 도서·목표 기간을 확정하는 시점의 모든 활성 모임원을 자동 명단으로 고정하고 독후감을 일괄 생성한다. |
| 관심분야와 카테고리 | 대분류만 저장하면 문학 안의 소설과 시처럼 서로 다른 관심을 같은 값으로 판정하고, 모임에 한 조합만 저장하면 복합 성격의 모임을 표현하기 어렵다. | 회원 관심분야의 관련 업무 데이터 항목 하위 관심분야 분류값에는 대분류의 자식 분류값을 저장한다. 모임은 별도 관계 테이블에 1~3개 코드를 저장하고 같은 코드의 개수로 추천 우선순위를 계산한다. |
| 관심분야와 온보딩 완료 | 관심분야 저장 실패를 온보딩 실패로 취급하면 웰컴 화면을 본 회원이 관심분야 때문에 서비스 전체에 진입하지 못한다. | 웰컴 완료와 관심분야 저장을 분리한다. 관심분야가 없거나 저장에 실패해도 웰컴 완료 조건을 충족하면 `온보딩 완료 여부 = 'Y'`로 처리한다. |
| 공개 가입 정원 | 즉시 가입과 승인 처리에서 정원을 조회만 하면 동시 요청으로 초과 가입이 가능하다. | 모임 행 잠금 또는 원자적 정원 갱신으로 가입·승인을 직렬화한다. |
| 퇴장 권한 | 공개 가입만 추가하고 강제 퇴장을 정의하지 않으면 운영자가 부적절한 회원의 접근을 끊을 수 없다. | 모임장 전용 퇴장 기능과 즉시 접근 회수 및 감사 이력을 설계한다. |
| 공개 모임 초대 | 비공개 모임만 맞팔 초대를 지원하면 공개 모임장이 기존 관계의 회원을 직접 초대할 수 없다. | 공개 범위와 관계없이 모임장이 맞팔 회원을 초대할 수 있게 한다. 모든 초대 대상은 맞팔로 제한한다. |
| 초대와 정원 경합 | 초대 수락 시점에만 정원을 검사하면 초대 후 일반 가입이나 신청 승인이 마지막 자리를 사용해 초대 수락이 실패할 수 있다. | 초대 발송 시 좌석을 예약하고 일반 가입·승인은 예약석을 사용할 수 없게 한다. 초대 수락은 예약석을 활성 회원석으로 전환한다. |
| 별도 제출본 | 독후감과 제출본에 본문·상태·평점을 중복 저장하면 두 데이터가 달라질 수 있고 수정·삭제·탈퇴 정책이 복잡해진다. | 별도 독서모임 참여 신청 정보를 만들지 않고 독서 모임 회차 참여의 독후감 번호로 원본 독후감을 직접 조회한다. |
| 모임 생성 독후감 식별 | 독후감만 조회하면 개인이 직접 만든 독후감과 모임에서 자동 생성한 독후감을 구분할 수 없다. | 독서 모임 회차 참여의 독후감 번호에 고유 제약을 두고 회차·참여자·독후감을 조인한다. |

## 요구사항

### 필수 요구사항

- 한 사용자는 여러 모임을 개설하고 여러 모임에 참여할 수 있어야 한다.
- 모임은 공지사항 카테고리 분류 아래의 서로 다른 자식 관심분야 코드를 1~3개 선택하고 공개 범위 및 가입 방식을 가져야 한다.
- 공개 여부와 관계없이 모임장은 맞팔 회원만 초대할 수 있고 초대받은 회원은 수락 또는 거절할 수 있어야 한다.
- 공개 모임은 검색·추천 목록에 나타나야 하며 즉시 가입과 승인 가입을 지원해야 한다.
- 승인형 공개 모임은 모임장이 최대 5개의 자유 형식 가입 질문을 설정하고 참가 신청자는 모든 질문에 장문형 텍스트로 답해야 한다.
- 모임장은 활성 모임원을 퇴장시킬 수 있어야 한다.
- 모임은 같은 도서와 목표 기간을 공유하는 회차를 반복할 수 있어야 한다.
- 회차가 확정되면 참여자별 개인 독서 기록이 생성되어 기존 책장에 표시되어야 한다.
- 참여자의 실제 독서 기간은 개인 독후감과 모임 회차 화면에 동일하게 나타나야 한다.
- 공개 시점 이후 모임 연결 독후감은 개인의 전역 공개 여부와 관계없이 권한이 있는 모임원에게 보여야 한다.
- 모임원은 다음 도서를 추천하고 투표할 수 있어야 한다.
- 활성 모임원은 모임 채팅을 사용할 수 있어야 한다.
- 계정 상태, 모임 상태, 역할, 가입 상태 및 회차 상태에 따른 서버 접근 검증이 있어야 한다.

### 전제조건

- 맞팔은 사용자 팔로우 관계에 두 방향 관계가 모두 존재하는 상태로 판단한다.
- 도서 식별은 기존 도서 마스터의 도서 번호와 ISBN 고유 제약 업무 중복 방지 고유 제약을 사용한다.
- 개인 독서 기록은 기존 독후감을 기준으로 유지한다.
- 현재 독후감의 독서 시작일과 독서 종료일 또는 목표 종료일은 문자열 날짜를 저장하므로 구현 시 형식 검증과 날짜형 컬럼 전환 여부를 별도 검토한다.
- 기존 온보딩 완료 여부는 사용자 계정과 프로필의 온보딩 완료 여부를 기준으로 한다.
- 알림 저장과 푸시는 기존 알림 템플릿, 사용자 알림 발송 내역, 사용자 웹 푸시 구독 흐름을 재사용한다.
- 계정이 `활성`인 회원만 모임 가입, 초대 수락, 회차 참가 및 채팅이 가능하다.

## 주요 사용자 흐름

### 신규 회원 관심분야 설정

1. 신규 회원은 현행 `/welcome` 흐름으로 서비스 소개와 닉네임 설정을 진행한다.
2. 마지막 완료 전에 관심분야 선택 단계를 제공하되 건너뛸 수 있게 한다.
3. 닉네임과 웰컴 완료 조건을 충족하면 관심분야 선택 여부와 관계없이 `온보딩 완료 여부 = 'Y'`로 저장한다.
4. 관심분야를 선택한 경우 별도 저장 요청으로 처리한다.
5. 관심분야 저장에 실패하면 안내만 표시하고 온보딩 완료를 되돌리지 않는다.
6. 관심분야가 없는 회원은 이후 `모임 찾기` 진입 시 관심분야를 하나 이상 저장하라는 안내를 받는다.

현행 온보딩 완료 계약은 유지하고 관심분야 선택 UI와 별도 저장 API만 추가하는 제안이다.

### 기존 회원 관심분야 보완

1. `모임 찾기` 진입 API에서 활성 관심분야 존재 여부를 조회한다.
2. 관심분야가 없으면 필수 선택 안내 뒤 `/reading-clubs/interests` 독립 페이지로 이동한다.
3. 선택 화면을 닫거나 건너뛰어 일반 공개 모임 목록으로 진입할 수 없게 한다.
4. 활성 공지사항 카테고리 분류 아래의 활성 대분류와 자식 분류값로 구성된 유효한 관심분야가 하나 이상 저장된 뒤에만 모임 추천 목록을 조회한다.
5. 저장에 실패하거나 선택값이 없으면 선택 화면에 머물며 공개 모임 목록 API를 호출하지 않는다.
6. 이후 회원은 마이페이지에서 관심분야를 수정할 수 있다.
7. `내 모임`, 받은 초대, 내 가입 신청 및 이미 가입한 모임 상세는 관심분야 유무와 관계없이 조회할 수 있다.
8. 가입하지 않은 공개 모임 상세의 직접 접근은 `모임 찾기` 흐름으로 간주하여 같은 관심분야 필수 조건을 적용한다.
9. 회원은 활성 세부 관심분야를 개수 제한 없이 선택할 수 있으며 같은 조합의 중복 저장만 차단한다.

### 모임 개설

1. 회원이 모임명, 소개, 대표 대분류와 그 자식 분류값, 정원 및 공개 범위를 입력한다.
2. `비공개`이면 가입 방식은 `INVITE`로 고정한다.
3. `공개`이면 `OPEN` 또는 승인형을 선택한다.
4. 승인형이면 모임장이 1~5개의 자유 형식 가입 질문을 입력한다.
5. 서버는 모임, 모임장 회원 행 및 필요한 모임 가입 질문 한 행을 하나의 트랜잭션으로 생성한다.
6. 공개 여부와 관계없이 모임장은 생성 후 맞팔 회원을 초대할 수 있다.

### 공개 모임 탐색과 가입

1. 추천 목록은 내 관심분야 관련 업무 데이터 항목 하위 관심분야 분류값과 공지사항 카테고리 분류 모임 카테고리의 관련 업무 데이터 항목 하위 관심분야 분류값이 정확히 일치한 개수가 많은 공개 모임을 우선 노출한다.
2. `OPEN` 모임은 가입 요청 시 활성 회원 수와 유효한 예약 초대 수를 포함해 남은 자리를 확인하고 즉시 회원으로 등록한다.
3. 승인형 모임은 모임 가입 질문의 현재 질문을 보여주고 신청자가 질문별 장문형 답변을 모두 입력하게 한다.
4. 신청 시점의 질문과 답변을 승인형 모임 가입 신청 한 행에 함께 복사해 `대기` 신청을 생성한다.
5. 모임장은 신청 목록에서 신청 당시 질문과 답변을 확인한 뒤 승인 또는 거절한다.
6. 승인 시점에 예약 초대를 제외한 일반 가입 가능 좌석을 다시 확인하고 여석이 없으면 승인하지 않는다.
7. 승인·거절 상태, 처리자 및 처리 일시를 기록하면서 승인형 모임 가입 신청의 첫 번째부터 다섯 번째까지의 가입 답변을 같은 트랜잭션에서 Null로 갱신한다. 답변 삭제가 실패하면 신청 처리도 롤백한다.
8. 처리된 신청 상세에는 질문 사본과 처리 결과만 남고 신청 답변은 다시 노출하지 않는다.
9. 처리 결과를 신청자에게 알림으로 전달한다.

### 모임장 맞팔 초대

1. 공개·비공개 모임장은 맞팔 회원 중 현재 모임원, 처리 중 신청자 및 유효 초대자를 제외한 후보를 조회한다.
2. 초대 발송 트랜잭션에서 모임 행을 잠그고 활성 회원 수와 다른 유효 초대의 예약 좌석 수를 계산한다.
3. 선택한 초대 대상 수만큼 자리가 있을 때만 모임 회원 및 초대 예약석에 `모임원 또는 초대 상태 = 'INVITED'`인 행을 일괄 생성하고 각 행이 한 자리를 예약한다.
4. 선택한 대상 수가 남은 자리보다 많으면 일부만 발송하지 않고 전체 요청을 거절해 모임장이 대상을 다시 선택하게 한다.
5. 초대받은 회원은 만료 전 수락 또는 거절한다.
6. 수락 시에는 초대 유효성, 대상 회원 및 계정 상태를 검사한 뒤 같은 모임 회원 및 초대 예약석 행을 초대됨에서 `활성`로 조건부 갱신하고 회원 가입 일시를 기록한다. 정원은 다시 경쟁하지 않는다.
7. 초대를 거절하거나 모임장이 취소하거나 유효기간이 만료되면 해당 초대됨 행을 즉시 물리 삭제해 예약 좌석을 해제한다. 초대 처리 이력은 별도로 남기지 않는다.
8. 승인형 공개 모임에서 모임장이 먼저 보낸 맞팔 초대는 가입 신청과 승인을 생략하고 발송 시점부터 3일 동안 좌석을 예약한다.
9. 팔로우 관계가 나중에 끊겨도 이미 수락한 모임 자격은 자동 해제하지 않는 안을 우선한다.

### 회차 확정과 개인 독후감 생성

1. 모임원은 도서를 추천하고 필요하면 투표한다.
2. 모임장이 도서, 목표 시작일 및 목표 종료일을 확정한다. 참여 여부를 묻거나 참여 명단을 수동 편집하지 않는다.
3. 서버는 확정 트랜잭션에서 해당 시점의 모든 활성 모임 회원 및 초대 예약석 회원을 조회해 회차 참여 명단으로 고정한다. 모임장도 활성 회원이면 포함한다.
4. 도서가 도서 마스터에 없으면 같은 트랜잭션에서 한 번만 멱등 등록해 도서 번호를 확보한다.
5. 회차를 예정 상태로 생성한다.
6. 참여자별 독후감을 `읽는 중`, 비공개 `N`, 같은 도서 번호, 같은 목표 시작일 및 종료일로 생성한다.
7. 독서 모임 회차 참여에 회원별 독후감 번호를 연결하고 목표 달성 여부는 아직 미판정인 Null로 저장한다.
8. 한 건이라도 실패하면 회차, 참여 관계 및 자동 생성 독후감을 모두 롤백한다.

모임 상세는 활성 모임원에게만 현재 예정 또는 독서 진행 중 회차와 연결 도서 요약을 제공한다. 현재 회차가 없으면 마지막 모임별 회차 번호에 1을 더한 다음 독서 순번을 표시하고 `/reading-clubs/books/search/{clubNumb}`로 이동할 수 있게 한다. 해당 경로는 개인 책 검색과 같은 검색 컴포넌트를 렌더링하지만 책 선택 동작은 `/reading-clubs/history/{clubNumb}/set?isbn={isbn}`로 분기한다. 독서 등록 화면은 목표 기간만 입력받고 `POST /api/reading-clubs/history/{clubNumb}`가 회차와 활성 멤버별 독후감을 생성한다.

참여 선택, 참여 응답 마감, 불참 및 휴식 상태는 두지 않는다. 회차 확정 뒤 가입한 회원은 현재 회차에 소급 포함하지 않고 다음 회차부터 자동 참여시킨다.

### 실제 독서 기간과 독후감 작성

1. 회차 확정 직후 개인 독후감의 시작일·종료일에는 공동 목표 기간이 들어 있다.
2. 참여자는 실제로 읽은 기간을 개인 독후감 화면 또는 모임 회차 화면에서 입력한다.
3. 어느 화면에서 수정하더라도 연결된 동일 독후감의 독서 시작일과 독서 종료일 또는 목표 종료일을 갱신한다.
4. 모임 화면은 독서 모임 회차 참여의 독후감 번호로 독후감을 조회하므로 개인 화면과 같은 실제 기간을 표시한다.
5. 진행 회차에 연결된 독후감의 도서 변경과 임의 삭제는 제한한다.
6. 독후감 본문, 상태, 평점 및 실제 기간은 기존 개인 독후감 수정 흐름으로 같은 독후감에 저장한다.

모임 화면에 별도 독후감 사본을 만들지 않는다. 실제 독서 기간과 독후감 내용 모두 독후감을 단일 기준으로 사용해 개인 화면과 모임 화면의 불일치를 차단한다.

### 회차 목표 달성 판정

1. 목표 종료 전 개인 독후감이 `완독`으로 전환되면 같은 쓰기 트랜잭션에서 해당 독서 모임 회차 참여의 목표 달성 여부를 `Y`로 갱신하고 달성 확인 일시를 기록한다.
2. 목표 종료 전 회원이 `완독`을 취소해 다시 `읽는 중`로 바꾸면 목표 달성 여부와 달성 확인 일시를 미판정 상태로 되돌린다.
3. 목표 종료 스케줄러는 아직 미판정인 참여자를 목표 미달성 `N`으로 확정하고 회차 결과를 마감한다.
4. 목표 종료 뒤에는 개인 독후감 상태가 `읽는 중`에서 `완독`으로 바뀌거나 실제 독서 기간이 수정되어도 독서 모임 회차 참여의 확정 결과를 변경하지 않는다.
5. 목표 종료까지 끝내지 못한 회원의 독후감은 강제로 `완독` 또는 중단 상태로 바꾸지 않고 `읽는 중`와 작성 내용을 그대로 유지한다.
6. 회차 목표 요약에는 전체 참여 인원, 목표 달성 인원 및 목표 달성자 목록만 제공한다. 미달성 인원은 두 수의 차이로 계산할 수 있지만 미달성자 명단과 참여·불참 상태는 노출하지 않는다.

독후감의 독서 종료일 또는 목표 종료일은 사용자가 입력하는 실제 독서 종료일이므로 이것만으로 마감 준수 여부를 나중에 재계산하지 않는다. 사용자가 과거 날짜를 입력하거나 스케줄러가 늦게 실행돼도 결과가 바뀌지 않도록 목표 종료 전 `완독` 전환 사실을 회차 참여 관계에 기록한다.

### 독후감 공개

1. 목표 종료 시각 전에는 작성자만 자신의 개인 독후감 본문을 볼 수 있다.
2. 목표 종료 시각 이후에는 열람 자격이 있는 활성 모임원에게 독서 모임 회차 참여로 연결된 독후감을 공개한다.
3. 이때 원본 독후감의 공개 여부가 `N`이어도 모임 전용 열람은 허용한다.
4. 비회원, 퇴장 회원 및 일반 공개 독후감 API에는 `공개 여부 = 'N'` 독후감을 노출하지 않는다.
5. 독후감 공유 목록과 목표 달성 요약은 분리한다. 공유 목록에는 정책상 열람 가능한 연결 독후감을 제공하고, 목표 요약에는 전체 참여 인원과 달성 인원·달성자만 표시한다.

### 모임원 퇴장

1. 모임장이 활성 모임원에 대해 퇴장을 요청한다.
2. 서버는 요청자가 현재 모임장인지, 대상이 모임장 본인이 아닌지, 대상이 활성 회원인지 확인한다.
3. 회원 상태와 퇴장 일시를 갱신하고 진행 회차의 접근 토큰·구독·채팅 권한을 즉시 회수한다.
4. 퇴장 이후 해당 회원은 전역 비공개 독후감을 포함한 모임 전용 콘텐츠를 볼 수 없다.
5. 대상 회원에게 퇴장 알림을 보낸다.
6. 개인 독후감은 본인 기록이므로 자동 삭제하지 않는다.

퇴장 회원의 기존 모임 연결 독후감은 남은 모임원에게 유지한다. 퇴장 회원은 모임장이 재가입 차단 여부를 해제한 뒤에만 새 가입 또는 초대 절차를 진행할 수 있으며, 그전에는 모임 콘텐츠에 접근할 수 없다.

### 모임장 확정 부재와 선거

1. 물리 삭제, 복구 불가능한 영구 이용 제한, 모임장의 자발적 승계 요청, 모임장 전용 다음 도서 확정 상태 시작 후 14일 미확정 또는 관리자가 같은 수준으로 확정한 사유가 발생한다.
2. 시스템은 확정 부재 사유와 근거를 기록하고 모임별 진행 중 선거가 없는지 확인한다.
3. 모임 상태를 모임장 선출으로 전환하고 선거 시작 시점의 활성 모임원 유권자 명부를 생성한다.
4. 세부 정책에 따라 후보 동의를 받고 유권자가 한 표씩 투표한다.
5. 마감 시 선거 행을 잠그고 정족수, 동률 및 당선자 활성 자격을 검증한다.
6. 당선자가 확정되면 모임장 번호, 이전·신임 모임원의 역할, 선거 상태와 감사 이력을 한 트랜잭션에서 변경한다.
7. 선거가 무산되면 정책 결정에 따라 연장 또는 모임 일시 중지를 적용한다.

최근 미활동, `비활성화`, 기간제 정지 및 영구 탈퇴 대기만으로는 이 흐름을 시작하지 않는다.

다음 도서 지연은 일반적인 모임 미활동과 구분한다. 추천·투표가 진행 중인 동안에는 14일을 계산하지 않고, 선정 도서가 모임장 지정 필요로 전환되어 모임장만 다음 도서를 확정할 수 있게 된 시각을 역할 시작일로 저장한다. 역할 종료일은 시작 시각부터 14일 뒤로 저장한다. 마감 시각 전에 도서가 확정되면 지연 판정을 종료하고, 마감 시각에도 모임장 지정 필요이면 조건부 갱신으로 독서 기간 초과 부재 사유와 선거를 한 번만 생성한다.

모임장 지정 필요는 첫 회차, 추천 후보 없음, 결선 재동률 등 확정된 다음 도서 정책에 따라 모임장의 최종 결정이 필요한 경우에만 사용한다. 회원 투표 결과로 도서가 자동 확정되면 이 상태와 14일 기한을 생성하지 않는다.

## 독후감 공개 권한

### 공개 판단 순서

모임 독후감 상세 API는 다음 순서로 권한을 판정한다.

1. 요청 계정이 `활성`인지 확인한다.
2. 작성자 본인이면 개인 독후감 권한으로 허용한다.
3. 일반 공개 요청이면 기존과 같이 `공개 여부 = 'Y'` 및 공개 가능한 독서 상태를 검사한다.
4. 모임 전용 요청이면 독서 모임 회차 참여의 독후감 번호 연결, 활성 모임원 자격, 공개 시각 및 열람 가능한 회차 범위를 검사한다.
5. 4번을 통과한 경우에만 `공개 여부 = 'N'` 독후감을 허용한다.

모임 전용 권한을 기존 공개 독후감 조회 조건에 OR 조건 하나로 섞지 않는다. 전용 서비스에서 모임·회차·회원 관계를 먼저 검증해 다른 모임의 비공개 독후감이 노출되는 것을 방지한다.

### 열람 매트릭스

| 조회자 | 목표 종료 전 | 목표 종료 후 | 전역 `공개 여부 = 'N'` | 비고 |
| --- | --- | --- | --- | --- |
| 작성자 | 가능 | 가능 | 가능 | 개인 소유 권한 |
| 해당 회차 시작 당시부터 자격이 있던 현재 활성 모임원 | 본문 불가 | 연결 독후감 가능 | 모임 안에서만 가능 | 신규 가입자는 가입 이후 회차만 열람 |
| 공개 모임 비회원 | 불가 | 불가 | 불가 | 모임 소개만 열람 |
| 퇴장·탈퇴 모임원 | 불가 | 불가 | 불가 | 퇴장 즉시 권한 회수 |
| 일반 서비스 사용자 | 기존 공개 정책 적용 | 기존 공개 정책 적용 | 불가 | 기존 공개 목록 계약 유지 |

### 별도 제출본 테이블을 사용하지 않는 이유

독서모임 참여 신청 정보 같은 별도 제출본은 목표 종료 시점의 본문과 평점을 고정하거나 수정 이력을 남기고, 원본 독후감 삭제 후에도 당시 모임 기록을 보존해야 할 때 의미가 있다. 그러나 현재 요구사항은 개인 독후감과 모임 독후감이 같은 내용과 실제 독서 기간을 공유하는 것이므로 별도 사본을 두면 다음 문제가 생긴다.

- 개인 독후감 수정 후 어느 값을 모임 화면에 보여줄지 결정해야 한다.
- 본문, 평점, 상태 및 기간을 두 테이블에 동기화해야 한다.
- 회원 퇴장, 회차 취소 및 계정 삭제 시 두 데이터를 각각 처리해야 한다.
- 현재 요구하지 않은 마감본·버전 기능 때문에 저장 구조가 복잡해진다.

따라서 1차 설계에서는 독후감을 단일 원본으로 사용하고 독서 모임 회차 참여의 독후감 번호로 모임 회차와 연결한다. 향후 마감본 보존이나 수정 이력이 실제 요구사항이 되면 일반 제출본이 아니라 변경 이력 전용 테이블을 추가하는 방식을 다시 검토한다.

### 모임 생성 독후감 판별 조인

독서 모임 회차 참여에는 모임 번호, 모임별 회차 번호, 회차별 모임 회차별 참여 번호, 사용자 번호, 독후감 번호, 회차 목표 달성 여부·확인 일시, 비식별 여부 및 등록·수정 일시를 저장한다. 전원이 자동 참여하므로 별도 참여 상태 컬럼은 두지 않는다. 독후감 번호에는 고유 제약과 독후감 번호 FK를 둔다. 물리 삭제 후에도 참여 수와 목표 달성 집계를 유지할 수 있도록 사용자 번호, 독후감 번호는 Null을 허용하고 기본키에는 포함하지 않는다.

| 데이터 항목 | 필수 | 키 | 역할 |
| --- | --- | --- | --- |
| 모임 번호 | Y | PK, FK | 모임 번호이자 독서 모임 회차 복합 외래키의 선두 컬럼 |
| 모임별 회차 번호 | Y | PK, FK | 모임 안에서 발급한 회차 번호 |
| 모임 회차별 참여 번호 | Y | PK | 모임·회차 안에서 `MAX + 1`로 발급하는 참여 번호 |
| 사용자 번호 | N | UK, FK | 회차 참여 회원 번호. 물리 삭제 시 Null |
| 독후감 번호 | N | UK, FK | 모임 회차가 생성한 독후감 번호. 물리 삭제 또는 회차 연결 해제 시 Null |
| 회차 목표 달성 여부 | N |  | 목표 종료 전 미판정 Null, 달성 `Y`, 마감 시 미달성 `N` |
| 목표 달성 확정 일시 | N |  | 목표 종료 전에 `완독`을 확인한 일시. `회차 목표 달성 여부 = 'Y'`일 때만 저장 |
| 비식별 참여 여부 | Y |  | 계정 제한 또는 물리 삭제로 사용자·독후감 연결을 제거한 비식별 참여 여부 |
| 등록 일시 | Y |  | 회차 참여 등록 일시 |
| 수정 일시 | Y |  | 회차 참여 수정 일시 |
| 수정 일시 | Y |  | 회차 참여 수정 일시 |

회차 목표 달성 여부의 Null은 목표 미달성이 아니라 아직 마감되지 않은 미판정 상태를 뜻한다. `Y`이면 목표 달성 확정 일시가 필수이고 Null 또는 `N`이면 목표 달성 확정 일시는 Null이어야 한다. 회차별 달성 인원과 달성자 조회를 위해 모임 번호, 모임별 회차 번호, 회차 목표 달성 여부 순서의 인덱스를 둔다.

조회 관계는 다음과 같다.

1. `독후감 번호 = 독서 모임 회차 참여의 독후감 번호`로 개인 독후감과 회차 참여 관계를 연결한다.
2. `독서 모임 회차 참여.(모임 번호, 모임별 회차 번호) = 독서 모임 회차.(모임 번호, 모임별 회차 번호)`로 공동 목표 기간과 모임을 조회한다.
3. `독서 모임 회차의 모임 번호 = 모임 번호`로 모임 공개·가입 정책을 조회한다.

이 조인 결과가 있으면 모임에서 자동 생성된 독후감이고, 없으면 일반 개인 독후감이다. 개인 책장에는 조인 결과를 이용해 `모임 독서` 표시와 모임명을 제공할 수 있다. 하나의 자동 생성 독후감은 하나의 회차에만 속하도록 독서 모임 회차 참여의 독후감 번호를 유일하게 유지한다. 진행 중인 회차의 참여 인원은 활성·비식별 제외 독서 모임 회차 참여 행 수, 달성 인원은 연결된 `독후감의 독서 상태 코드 = '완독'`인 행으로 계산한다. 마감된 과거 회차의 달성 인원과 달성자 목록은 확정된 `회차 목표 달성 여부 = 'Y'`인 행으로 계산한다.

같은 회원이 같은 도서를 서로 다른 모임 또는 회차에서 읽으면 회차별 목표·실제 기간과 독후감이 다를 수 있으므로 독후감은 회차별로 별도 생성한다. 각 행은 서로 다른 독서 모임 회차 참여에 연결된다.

## 도서 저장 설계

### 현행 문제

현행 `ReportServiceImpl.setReport`는 한 독후감 등록 트랜잭션 안에서 `BookMapper.dupBook`으로 ISBN 존재 여부를 확인하고 없으면 `BookMapper.setBook`을 호출한다. 이 방식은 단일 요청에는 단순하지만 다음 문제가 있다.

- 참여자 수만큼 같은 도서 중복 조회가 발생한다.
- 동시에 실행된 두 요청이 모두 미등록으로 판단한 뒤 같은 ISBN을 INSERT할 수 있다.
- 업무 중복 방지 고유 제약이 중복 행은 막지만 한 요청이 예외로 실패할 수 있다.
- 표지 색상 계산이나 도서 정규화를 참여자별로 반복할 수 있다.

### 개선안

도서 저장 책임을 개별 독후감 등록이 아니라 회차 확정 서비스에 둔다.

1. 선택된 도서의 ISBN, 제목, 저자 및 표지 정보를 한 번 검증하고 정규화한다.
2. ISBN을 기준으로 기존 도서 번호를 조회한다.
3. 없으면 업무 중복 방지 고유 제약을 이용한 멱등 INSERT를 실행한다. MySQL 구현에서는 `ON DUPLICATE KEY UPDATE 도서 번호 = LAST_INSERT_ID(도서 번호)`와 같은 자기 대입 방식 또는 동일 효과의 전용 Mapper를 검토한다.
4. ISBN으로 다시 조회해 정확히 하나의 도서 번호를 확정한다.
5. 회차가 이 도서 번호를 참조한다.
6. 참여자별 독후감 INSERT에는 도서 상세가 아니라 같은 도서 번호만 전달한다.
7. 표지 기반 기본 색상이 필요하면 회차 확정 시 한 번 계산해 참여자 초기값으로 재사용한다.

기존 도서가 있으면 회차 요청의 제목·저자·표지 정보로 마스터를 자동 덮어쓰지 않는다. 도서 정정은 별도 관리 흐름으로 분리한다.

### 트랜잭션과 실패 처리

- 도서 확보, 회차 생성, 활성 모임원 명단 고정, 참여자 독후감 생성 및 참여 연결은 하나의 Service 쓰기 트랜잭션에서 처리한다.
- 외부 도서 검색 API 호출과 표지 이미지 다운로드는 DB 트랜잭션 전에 완료해 장기 잠금을 피한다.
- 참여자별 INSERT는 배치로 실행하되 생성된 독후감 번호와 참여자를 안정적으로 매핑해야 한다.
- 중간 실패 시 고아 회차, 고아 참여 관계 및 일부 회원에게만 생성된 독후감을 남기지 않는다.
- 재시도 요청에는 요청 멱등키 또는 `회차 + 회원` 고유 제약을 적용해 중복 독후감 생성을 막는다.

## 관심분야와 추천

### 공지사항 카테고리 분류 계층형 공통코드

옵션코드를 사용하지 않는다. 공통코드 그룹에는 공지사항 카테고리 분류 한 행만 만들고 대분류는 공통코드 세부 항목의 최상위 분류값, 실제 관심분야는 해당 대분류 코드를 상위 분류값로 가진 자식 분류값로 관리한다.

| 상위 분류 | 표시명 | 하위 분류와 표시명 |
| --- | --- | --- |
| 문학 분야 | 문학 | 소설, 시, 에세이 |
| 인문 분야 | 인문 | 철학, 심리, 언어 |
| 사회 분야 | 사회 | 정치, 사회학, 교육 |
| 과학기술 분야 | 과학·기술 | 자연과학, 공학, 정보기술 |
| 경제 분야 | 경제·경영 | 경제, 투자, 창업, 경영 |
| 역사 분야 | 역사 | 한국사, 세계사, 인물사 |
| 예술 분야 | 예술·문화 | 미술, 음악, 영화, 대중문화 |
| 자기계발 분야 | 자기계발 | 습관, 진로, 생산성 |
| 아동 분야 | 어린이·청소년 | 아동, 청소년, 학습 |
| 기타 분야 | 기타 | 기타 주제 |

- 공통코드 그룹의 공통코드, 공통코드 이름은 각각 공지사항 카테고리 분류, `독서 관심분야`다.
- 공통코드 세부 항목의 상위 분류값, 분류값, 분류값 이름, 정렬 순서, 사용 여부는 부모 관계, 코드, 표시명, 형제 노출 순서 및 사용 여부다.
- 세부 카테고리를 추가할 때 해당 대분류 코드를 상위 분류값로 지정한 공통코드 세부 항목 행을 추가하므로 깊이와 개수 제한 없이 확장할 수 있다.
- API는 대분류의 `groupCode`, `groupName`과 활성 분류값의 `code`, `name` 배열을 반환한다.
- 사용 중인 대분류와 분류값은 참조 데이터가 존재하는 동안 삭제하거나 다른 의미로 변경하지 않는다. 신규 선택을 막을 때는 사용 여부를 비활성화하고 기존 연결의 표시명은 유지한다.
- 새 대분류는 공지사항 카테고리 분류의 최상위 분류값로 추가하고 그 자식을 관심분야로 연결한다.
- 관심분야 공통코드 식별자는 Service 공통 상수 공지사항 카테고리 분류 한 곳에서 관리한다.
- 대분류와 하위 관심분야의 형제 노출 순서는 모두 공통코드 세부 항목의 정렬 순서로 관리한다.

공통코드명과 초기 분류는 운영 전 최종 확정한다. 1차 구현에서는 위 분류를 `승인된 비공개 기준정보 패키지` 초기 데이터에 반영했으며 실제 운영 데이터 반영 여부는 배포 단계에서 별도로 검증한다.

### 회원 관심분야 테이블 제안

회원 독서 관심분야는 회원과 관심분야의 다대다 관계를 저장한다.

| 데이터 항목 | 필수 | 역할 |
| --- | --- | --- |
| 사용자 번호 | Y | 사용자 계정과 프로필 회원 번호 |
| 관련 업무 데이터 항목 하위 관심분야 분류값 | Y | 공지사항 카테고리 분류 아래에서 선택한 세부 카테고리의 공통코드 세부 항목의 분류값 |
| 등록 일시 | Y | 선택 등록 일시 |

- 기본키는 사용자 번호, 관련 업무 데이터 항목 하위 관심분야 분류값 복합키로 같은 세부 관심분야의 중복 선택을 막는다.
- 사용자 번호는 사용자 계정과 프로필의 사용자 번호를 참조한다.
- 관련 업무 데이터 항목 하위 관심분야 분류값은 공통코드 세부 항목의 분류값과 같은 `varchar(20)`을 사용한다.
- 공지사항 카테고리 분류는 모든 회원 관심분야에 동일하므로 테이블과 API 요청에 중복 저장하지 않는다. Service는 요청한 관련 업무 데이터 항목 하위 관심분야 분류값이 활성 공지사항 카테고리 분류 대분류의 활성 하위 코드인지 검증한다.
- 공통코드 세부 항목은 다른 공통코드 그룹에서 같은 분류값을 사용할 수 있으므로 관련 업무 데이터 항목 하위 관심분야 분류값 단독 외래키는 생성하지 않는다. 코드 유효성은 전체 교체 트랜잭션에서 저장 전에 검증한다.
- 추천 조회를 위해 관련 업무 데이터 항목 하위 관심분야 분류값, 사용자 번호 순서의 인덱스를 둔다.
- 회원의 선택 개수에는 업무상 상한을 두지 않는다. 교체 저장 요청에는 서버 공통 요청 크기 제한을 적용하고 같은 코드는 한 행만 유지한다.

### 추천 정렬 제안

`내 모임`과 `모임 찾기`를 분리한다. `모임 찾기`는 `공개`, 모집 가능, 활성 상태인 모임을 대상으로 다음 순서를 사용한다.

1. 회원 관련 업무 데이터 항목 하위 관심분야 분류값과 공지사항 카테고리 분류 모임 카테고리의 관련 업무 데이터 항목 하위 관심분야 분류값이 같은 조합 수 내림차순
2. `정렬 순서 = 1`인 대표 카테고리의 정확 일치 여부 내림차순
3. 공통코드 세부 항목의 상위 분류값로 계산한 대분류가 같은 모임 카테고리 조합 수 내림차순
4. 모집 가능 여부 내림차순
5. 최근 회차 활동 일시 내림차순
6. 모임 생성 일시 내림차순
7. 모임 번호 내림차순

동점 정렬까지 고정해 페이지 사이에 중복·누락이 생기지 않게 한다. 회원 관심분야와 독서 모임 카테고리의 정확 일치 및 대분류 부분 일치는 모임 번호로 미리 집계한 인라인 뷰를 `JOIN`하여 계산하고, 한 회원의 관심분야가 많아도 같은 모임 행이 중복되지 않게 한다. SELECT 절의 행별 스칼라 서브쿼리는 사용하지 않는다. 대분류만 같고 분류값이 다른 경우는 별도의 부분 일치로 집계하며 정확 일치 건수에 포함하지 않는다.

## 공개 모임 가입 설계

### 가입 방식

| 공개 범위 | 가입 방식 | 처리 |
| --- | --- | --- |
| `비공개` | `INVITE` | 모임장이 맞팔 회원을 초대하고 수락 시 가입 |
| `공개` | `OPEN` | 회원 요청 즉시 정원 검증 후 가입 |
| `공개` | 승인형 | 모임장이 설정한 최대 5개 질문에 모두 답한 뒤 모임장 승인 시 가입 |

공개 모임도 가입 방식과 별개로 모임장이 맞팔 회원을 초대할 수 있다. 초대 후보는 항상 맞팔로 제한한다.

### 좌석 계산 기준 제안

초대를 수락했는데 정원이 먼저 마감되는 모순을 막기 위해 유효한 초대가 좌석을 예약하는 방식을 우선한다.

`일반 가입 가능 좌석 = 최대 정원 - 활성 모임원 수 - 유효한 INVITED 회원 행 수`

- `모임원 또는 초대 상태 = 'INVITED'`이고 초대 만료 일시가 현재 시각보다 뒤인 회원 행 한 건은 초대 발송 시점부터 만료·거절·취소·수락 시점까지 한 자리를 예약한다.
- 초대됨 행은 예약석일 뿐 모임원이 아니므로 모임 상세, 채팅, 회차, 독후감 공유 등 활성 모임원 권한을 부여하지 않는다.
- 승인 대기 신청은 좌석을 예약하지 않는다. 신청은 여러 건 받을 수 있지만 모임장은 일반 가입 가능 좌석 범위에서만 승인한다.
- `OPEN` 즉시 가입도 일반 가입 가능 좌석이 있을 때만 성공한다.
- 초대 수락은 이미 확보한 예약석을 활성 모임원 좌석으로 바꾸므로 일반 가입 가능 좌석 수를 추가로 줄이지 않는다.
- 초대 수락은 정원 마감을 이유로 실패하지 않는다. 초대 만료, 취소, 대상 불일치, 비활성 계정, 중복 가입 또는 모임 종료는 별도 실패 사유가 될 수 있다.
- 유효한 초대가 있는 회원이 공개 모임의 일반 가입 버튼을 눌러도 별도 일반 좌석을 사용하지 않고 초대 수락 흐름으로 전환해 자신의 예약석을 소비한다.
- 유효한 초대가 있는 회원은 같은 모임에 승인 가입 신청을 중복 등록할 수 없다.
- 모임 최대 정원은 활성 모임원 수와 유효한 예약 좌석 수의 합보다 작게 줄일 수 없다.
- 공개 목록과 모임 상세의 남은 자리 수는 예약 좌석을 차감한 일반 가입 가능 좌석을 표시한다.

초대가 공공 모집 좌석을 일정 기간 점유하는 trade-off가 있으므로 초대 만료 기간과 동시 유효 초대 수는 정책으로 확정한다.

### 승인 신청 규칙 제안

- 모임 가입 질문은 모임 번호를 기본키로 사용해 승인형 모임당 정확히 한 행만 저장한다.
- 질문은 별도 유형과 선택지 구조 없이 첫 번째부터 다섯 번째까지의 가입 질문까지 최대 5개 자유 형식 컬럼으로 저장한다.
- 첫 번째 가입 질문은 필수이고 사용하지 않는 후속 질문 컬럼은 Null로 저장한다.
- 객관식처럼 사용하려면 모임장이 질문 본문에 번호와 선택지를 직접 적고 신청자가 장문형 답변에 선택 번호를 작성한다.
- 신청자는 현재 값이 있는 모든 질문에 답해야 하며 답변을 공백 정규화한 뒤 하나라도 비어 있으면 신청을 거절한다.
- 질문과 답변의 길이, 재신청 대기 기간 및 모임당 동시 신청 수는 정책에서 확정한다.
- 질문과 답변에는 비속어와 스크립트 입력에 대한 기존 공통 텍스트 검증을 적용한다.
- 신청 생성 시 모임 가입 질문의 질문 1~5와 신청자의 답변 1~5를 승인형 모임 가입 신청 한 행에 함께 저장한다.
- 모임장이 모임 가입 질문의 현재 질문을 수정해도 이미 제출된 승인형 모임 가입 신청의 질문 사본과 답변은 변경하지 않는다.
- 모임 가입 질문은 모임의 현재 질문 설정이므로 모임이 존재하는 동안 유지한다. 승인형 모집을 잠시 사용하지 않거나 가입 방식을 바꿔도 행을 삭제하지 않고 신규 신청에만 사용하지 않는다.
- 승인 또는 거절 시 승인형 모임 가입 신청의 첫 번째부터 다섯 번째까지의 가입 답변을 상태 변경과 같은 트랜잭션에서 즉시 Null로 갱신한다. 처리 상태·처리자·처리 일시와 질문 사본은 남기되 답변은 복구하거나 다시 조회하지 않는다.
- 동일 회원의 동일 모임 `대기` 신청은 하나만 허용한다.
- 이미 활성 모임원이거나 유효 초대가 있는 경우 중복 신청을 막는다.
- 승인·거절 처리자는 현재 모임장이어야 한다.
- 신청 상태 변경은 조건부 UPDATE로 처리해 두 번 승인되지 않게 한다.

### 정원 동시성

초대 발송, 즉시 가입, 신청 승인, 초대 수락, 초대 취소 및 정원 변경은 같은 모임 행 잠금 기준을 사용한다. 초대 발송은 활성 회원과 유효한 초대됨 행 수를 확인한 뒤 예약 회원 행을 생성하고, 즉시 가입과 신청 승인은 예약석을 제외한 자리만 확보한다. 초대 수락은 자신의 초대됨 행을 `활성`로 조건부 갱신한다. 화면의 남은 자리 수는 안내 값이며 서버가 각 쓰기 요청에서 다시 계산한다.

| 모임 투표 자격 | 모임 번호, 투표 번호, 사용자 번호 | 유권자의 최종 대상 번호, 투표당 1인 1표 및 마감 전 변경 기준 |
| 모임 채팅 | 채팅 메시지 번호 | 전역 자동 증가 채팅 번호, 모임 번호, 본문, 발신자, 메시지 유형, 등록 일시 |
| 독서모임 강제 퇴장 이력 | 모임 번호, 강제 퇴장 이력 번호 | 퇴장 대상, 처리자, 처리 일시 감사 이력 |
| 회원 독서 관심분야 | 사용자 번호, 관련 업무 데이터 항목 하위 관심분야 분류값 | 회원이 선택한 공지사항 카테고리 분류 하위 세부 관심분야 |
| 모임장 변경 이력 | 모임 번호, 이력 번호 | 모임장 변경 전후 회원, 승계 사유, 선거와 처리자 감사 이력 |
| 독서모임 관리자 변경 이력 | 모임 번호, 이력 번호 | 관리자 모임 상태 조치의 전후 상태, 사유, 처리 관리자 및 일시 감사 이력 |

### 복합키와 모임별 번호 발급

- 모임 자체의 모임 번호는 전역 `AUTO_INCREMENT` 단일 기본키로 발급한다.
- 채팅을 제외한 모임 종속 테이블은 기본키와 부모 참조 외래키가 모임 번호로 시작하도록 한다. 따라서 다른 모임에서 같은 지역 번호가 발급되어도 서로 충돌하지 않는다.
- 독서 모임 카테고리, 모임 회원 및 초대 예약석, 모임 가입 질문처럼 자연스럽게 유일성을 판별할 수 있는 관계는 별도 순번을 만들지 않고 자연 복합키를 사용한다.
- 가입 신청, 회차, 회차 참여, 도서 선정, 도서 추천, 퇴장 이력, 모임장 선거, 공통 투표, 모임장 변경 이력 및 관리자 조치 이력처럼 번호가 필요한 데이터는 모임별 지역 번호를 사용한다. 초대는 `모임 회원 및 초대 예약석(모임 번호, 사용자 번호)` 자연 복합키로 식별하므로 별도 초대 번호를 발급하지 않는다. 회차 참여의 모임 회차별 참여 번호는 같은 모임·회차 범위에서 발급하고, 나머지 지역 번호는 같은 모임 범위에서 발급한다. 지역 번호는 해당 부모 범위 안에서만 유일하며 화면 정렬 순서나 누락 없는 업무 번호를 의미하지 않는다.
- 지역 번호는 별도 발급 테이블을 두지 않고 각 대상 테이블의 등록문 안에서 같은 모임 번호 범위의 `COALESCE(MAX(지역 번호), 0) + 1`을 계산해 저장한다. 번호 조회와 등록을 분리하지 않고 하나의 `INSERT ... SELECT` 문으로 처리한다.
- 기본키 또는 고유 제약을 최종 중복 방어선으로 둔다. 같은 모임·같은 데이터 종류에 등록이 정확히 동시에 발생해 중복키가 나면 해당 트랜잭션을 롤백하고 요청을 재시도할 수 있게 한다.
- 물리 삭제된 행이 당시 최대 번호였다면 그 번호가 나중에 다시 발급될 수 있다. 지역 번호는 모임 내부의 기술 식별자이므로 영구 불변 업무 번호로 노출하지 않고, 장기 감사 추적이 필요한 이력 행은 물리 삭제하지 않는다.
- 채팅은 예외로 모임 채팅의 채팅 메시지 번호를 전역 `AUTO_INCREMENT` 단일 기본키로 사용하고 모임 번호는 일반 외래키로 둔다. 메시지 양과 동시 쓰기가 많으므로 `MAX + 1`을 사용하지 않으며, 모임별 커서 조회를 위해 `(모임 번호, 채팅 메시지 번호)` 인덱스를 둔다.
- 채팅 번호가 전역 키여도 조회·수정·삭제 권한 검증에서는 요청의 모임 번호, 채팅 메시지 번호 및 활성 모임원 자격을 함께 확인한다.
- 모임 투표의 투표 번호는 같은 모임 번호 범위의 `MAX(투표 번호) + 1`로 발급한다. 모임 투표 선택지는 대상 번호 자체가 투표 안의 선택지 식별자이므로 투표 선택지 번호를 발급하지 않는다.

모임 회원 및 초대 예약석의 좌석 예약 판단에는 모임 번호, 사용자 번호, 모임원 또는 초대 상태, 초대 만료 일시를 사용한다. `모임원 또는 초대 상태 = 'INVITED'`이고 초대 만료 일시가 현재 시각보다 뒤인 행만 유효한 예약으로 계산한다. 만료 삭제 스케줄러가 늦더라도 지난 초대가 좌석을 계속 점유하지 않도록 상태와 만료 시각을 함께 검사한다. 예약 좌석 집계와 만료 대상을 찾기 위해 모임 번호, 모임원 또는 초대 상태, 초대 만료 일시 인덱스를 둔다. 초대 거절·모임장 취소·만료 시 초대됨 행은 물리 삭제하며 별도 초대 상태나 처리 이력을 보존하지 않는다.

모임 회원 및 초대 예약석에는 회원의 가입 경로를 나타내는 가입 경로를 저장하지 않는다. 공개 범위와 가입 정책은 모임 공개 범위, 모임 가입 방식으로 판단하며, 개별 회원이 어떤 경로로 들어왔는지는 현재 업무와 권한 판정에 필요하지 않다. 초대됨 행은 항상 `모임원 역할 = 'MEMBER'`, `회원 가입 일시 = Null`, 초대를 발송한 모임장 사용자 번호·초대 발송 일시·초대 만료 일시 필수로 저장한다. `활성` 전환 시 회원 가입 일시를 기록하고 초대 전용 값은 Null로 정리한다.

동일 모임·회원의 모임 회원 및 초대 예약석은 현재 관계를 나타내는 한 행만 유지한다. 탈퇴 또는 퇴장 뒤 재가입·재초대가 허용되면 기존 탈퇴 또는 차단이 해제된 강제 퇴장 행을 새 상태로 갱신하고 최신 가입 주기의 일시를 저장한다. 강제 퇴장 감사 이력은 독서모임 강제 퇴장 이력에 별도로 유지하지만 자발적 탈퇴와 재가입 주기별 이력은 모임 회원 및 초대 예약석에 누적하지 않는다.

독서 모임 카테고리와 회원 독서 관심분야는 공지사항 카테고리 분류 하위의 세부 관련 업무 데이터 항목 하위 관심분야 분류값만 저장한다. 공통코드 그룹과 대분류는 중복 저장하지 않고 공통코드 세부 항목의 상위 분류값로 조회한다. 모임 생성·수정 시 모든 코드가 활성 세부 관심분야인지 먼저 검증하며 하나라도 잘못되면 요청 전체를 실패 처리한다.

독서 모임 카테고리의 기본키는 모임 번호, 관련 업무 데이터 항목 하위 관심분야 분류값로 같은 모임의 중복 분류값을 막는다. 모임 번호, 정렬 순서에는 별도 고유 제약을 두고 정렬 순서는 1부터 연속된 값만 허용한다. `정렬 순서 = 1`인 행은 대표 카테고리이며 모임당 정확히 하나 존재해야 한다. Service는 모임별 행 수가 1~3개인지 검증하고 모임 행 잠금 아래에서 기존 관계 삭제와 신규 관계 배치 등록을 한 트랜잭션으로 처리한다.

가입 신청은 `setJoin` 트랜잭션에서 독서 모임 원본을 먼저 잠근 뒤 동일 모임·사용자의 처리 대기 신청을 조회하고 저장한다. 모임 단위 잠금으로 신청 처리를 직렬화하여 별도 중복 방지 항목 없이 중복 신청과 모임별 순번 충돌을 함께 방지한다.

추천 조회를 위해 독서 모임 카테고리에 관련 업무 데이터 항목 하위 관심분야 분류값, 모임 번호 순서의 인덱스를 두고 공개 범위와 모임 상태는 독서 모임 인덱스에서 처리한다. 카테고리 관계와 모임 마스터의 서로 다른 선택도를 한 복합 인덱스에 억지로 결합하지 않는다.

### 공통 투표와 모임장 선거 데이터 제안

다음 도서 선정과 모임장 선거는 업무 발생 원인과 결과 반영 대상이 다르므로 선정 도서, 도서 추천, 모임장 선거, 모임장 변경 이력을 각각 유지한다. 투표에서 공통으로 필요한 이벤트, 선택지, 유권자 및 투표용지만 하나의 모델로 통합한다.

- 모임 투표의 기본키는 모임 번호, 투표 번호다. 투표 유형은 `BOOK` 또는 모임장, 투표 차수는 본선 1과 결선 2, 결선 투표의 이전 투표 번호는 결선의 원 투표 번호를 저장한다.
- `BOOK` 투표는 선정 도서 번호만, 모임장 투표는 선거 번호만 저장한다. 두 업무 번호 중 정확히 하나만 존재해야 하며 같은 모임의 유효한 선정 도서 또는 모임장 선거를 참조하는지 검증한다.
- 모임 투표에는 시작·마감 일시, 상태, 비밀투표 여부, 마감 전 변경 허용 여부 및 결과 투표 결과 번호를 저장한다. 투표 결과 번호는 `BOOK`이면 선정된 도서 번호, 모임장이면 당선된 사용자 번호다.
- 모임 투표 선택지의 기본키는 모임 번호, 투표 번호, 대상 번호다. 별도 투표 선택지 번호와 대상 유형을 두지 않고 부모 모임 투표의 투표 유형에 따라 도서 번호 또는 후보 사용자 번호로 해석한다.
- 도서 투표의 같은 책이 여러 회원에게 추천되어도 `대상 번호 = 도서 번호`인 선택지는 한 건만 만든다. 추천자와 추천 문구는 도서 추천에 각각 유지한다.
- 모임장 후보가 본인 등록에 동의하면 `대상 번호 = 사용자 번호`인 선택지를 생성한다. 철회하거나 자격을 잃으면 선택지 상태를 변경하며 확정 부재인 기존 모임장은 후보 선택지로 등록할 수 없다.
- 대상 번호는 `BOOK`과 모임장에서 서로 다른 마스터를 참조하는 다형 값이므로 도서 마스터 또는 사용자 계정과 프로필에 단일 물리 FK를 연결하지 않는다. 선택지 생성 트랜잭션에서 투표 유형별 원본 존재와 자격을 검증하고 처리 대상 표시명에 당시 도서명 또는 닉네임을 보존한다.
- 모임 투표 참여 기록의 기본키는 모임 번호, 투표 번호, 사용자 번호다. 투표 시작 시점의 활성 모임원을 도서 투표와 모임장 선거의 유권자로 고정하며, 이후 탈퇴·퇴장·정지된 회원은 명부에 남더라도 후속 투표와 당선 자격을 잃는다.
- 모임 투표 자격의 기본키는 모임 번호, 투표 번호, 사용자 번호다. 모임 번호, 투표 번호, 대상 번호는 같은 투표의 모임 투표 선택지를 참조하고 마감 전 변경은 동일 행의 대상 번호를 갱신하는 UPSERT로 처리한다.
- 결선은 새 투표 번호를 발급하고 결선 투표의 이전 투표 번호로 본선을 연결한다. 도서 결선은 동률 도서만, 모임장 결선은 동률 후보 회원만 선택지로 복사한다.
- 모임장 선거는 한 모임의 진행 중 선거가 하나만 존재하도록 활성 선거 고유 제약 또는 조건부 쓰기를 둔다. 물리 삭제 사유의 기존 모임장 번호와 부재 확정 감사값은 삭제 후에도 남아야 하므로 모임장 선거와 모임장 변경 이력의 과거 모임장 식별값을 사용자 계정과 프로필에 물리 FK로 연결하지 않는다.
- 모임장 변경 이력은 이전·다음 모임장, 확정 부재 사유, 연결된 선거, 처리 일시를 보존한다. 선거 데이터 삭제 정책과 별개로 권한 변경 감사 이력은 운영 보존 기준을 적용한다.
- 선거 종료 시 모임장 선거와 해당 모임 투표를 잠그고 당선자의 활성 자격을 재검증한 다음 모임장, 회원 역할, 선거·투표 상태와 감사 이력을 한 트랜잭션에서 변경한다.

선정 도서의 역할 시작일과 역할 종료일은 `도서 선정 방식 = '모임장 지정 필요'`일 때만 필수로 저장한다. 추천·투표 단계에서는 Null이고, 선정 완료나 취소 후에는 당시 판정 근거를 위해 값을 유지한다. 모임장 선거의 독서 기간 초과 사유에는 모임 번호, 선정 도서 번호를 함께 보존하여 14일 지연의 원본 선정 건을 추적한다.

### 가입 질문과 답변 컬럼 제안

모임 가입 질문은 승인형 모임의 현재 질문 양식을 모임당 한 행으로 저장한다.

| 데이터 항목 | Null | 역할 |
| --- | --- | --- |
| 모임 번호 | N | 모임 번호이자 기본키 및 독서 모임 외래키 |
| 첫 번째 가입 질문 | N | 첫 번째 가입 질문 |
| 두 번째 가입 질문 | Y | 두 번째 가입 질문 |
| 세 번째 가입 질문 | Y | 세 번째 가입 질문 |
| 네 번째 가입 질문 | Y | 네 번째 가입 질문 |
| 다섯 번째 가입 질문 | Y | 다섯 번째 가입 질문 |
| 등록·수정 감사 컬럼 | N | 등록자·등록일시·수정자·수정일시 |

- `비공개`, `공개 + OPEN`으로 처음 생성한 모임은 가입 질문을 사용하지 않으므로 모임 가입 질문 행을 만들지 않는다.
- `공개 + APPROVAL` 모임은 모임 가입 질문 한 행과 하나 이상의 질문이 필수이다.
- 한 번 생성된 모임 가입 질문은 모임이 존재하는 동안 유지한다. 가입 방식이 바뀌면 현재 질문을 숨기고 신규 신청에서 사용하지 않을 뿐 행을 삭제하지 않는다.
- 질문 사이에 빈 순서를 허용하지 않는다. 예를 들어 세 번째 질문이 있으면 첫 번째와 두 번째 질문도 있어야 한다.
- 질문의 표시 순서는 컬럼 순서로 고정하므로 별도 순서 컬럼을 두지 않는다.

승인형 모임 가입 신청은 신청 자체와 신청 당시 질문·답변을 신청당 한 행으로 저장한다.

| 컬럼 묶음 | 역할 |
| --- | --- |
| 첫 번째 가입 질문~다섯 번째 가입 질문 | 신청 버튼을 누른 시점의 질문 사본 |
| 첫 번째부터 다섯 번째까지의 가입 답변 | 각 질문에 대응하는 신청자의 장문형 답변 |

현재 질문과 답변을 배열이나 JSON으로 저장하지 않는다. 최대 개수가 5개로 고정되어 있고 질문·답변 위치가 일대일로 대응하므로 명시적 컬럼을 사용한다. 모임장이 질문을 수정하면 새 신청부터 변경된 질문을 복사하고 이미 제출된 `대기` 신청은 기존 질문 사본과 답변을 유지한다. 승인·거절 시 답변 컬럼만 즉시 Null로 만들며 질문 사본과 처리 이력은 유지한다.

### 주요 고유 제약

- 모임 회원 및 초대 예약석: 모임별 회원 한 행
- 독서 모임 회차 참여: 모임·회차별 회원 한 행, 독후감 번호 한 번만 연결
- 모임 가입 질문: 모임별 질문 양식 한 행
- 승인형 모임 가입 신청: 동일 모임·회원의 처리 중 신청 한 건
- 회원 독서 관심분야: 회원별 같은 관련 업무 데이터 항목 하위 관심분야 분류값 한 건
- 독서 모임 카테고리: 모임별 같은 관련 업무 데이터 항목 하위 관심분야 분류값 한 건 및 같은 정렬 순서 한 건
- 모임장 선거: 모임별 진행 중 선거 한 건
- 모임 투표: 모임별 투표 번호 한 건 및 같은 업무 원본·차수의 투표 한 건
- 모임 투표 선택지: 모임·투표별 같은 대상 번호 선택지 한 건
- 모임 투표 참여 기록: 모임·투표별 유권자 한 행
- 모임 투표 자격: 모임·투표별 유권자 한 표

처리 중 상태만 유일해야 하는 제약은 MySQL 인덱스 특성을 고려해 별도 활성 키 컬럼 또는 Service 조건부 쓰기로 구현한다.

## 화면 구성 제안

### 사이드 메뉴와 사용자 화면 메뉴 제안

사용자가 확정한 메뉴 구조는 다음과 같다. 상위 메뉴 클릭은 펼침·접힘만 수행하고 `내 모임`은 `/reading-clubs/mine`, `모임 찾기`는 `/reading-clubs/find`를 사용한다. 두 탐색 메뉴만 사이드 메뉴에 노출하고, 나머지 화면은 공통 헤더에서 페이지명을 조회할 수 있도록 `화면 노출 여부 = 'N'`, `사용 여부 = 'Y'`인 하위 메뉴로 등록한다.

| 구분 | 상위 메뉴 번호 | 상위 메뉴 번호 | 메뉴 단계 | 메뉴명 | URL 제안                                              | 정렬 해석 |
| --- | --- | --- | --- | --- |-----------------------------------------------------| --- |
| 상위 | `12` | `NULL` | `1` | 독서 모임 | `/reading-clubs`                                    | 전체 1뎁스 안의 순서 `2` |
| 하위 | 개별 단일 번호 | `12` | `2` | 내 모임 | `/reading-clubs/mine`                               | 독서 모임 안의 순서 `1` |
| 하위 | 개별 단일 번호 | `12` | `2` | 모임 찾기 | `/reading-clubs/find`                               | 독서 모임 안의 순서 `2` |
| 숨김 하위 | 개별 단일 번호 | `12` | `2` | 관심분야 선택 | `/reading-clubs/interests`                          | 공통 헤더 제목 조회 전용 |
| 숨김 하위 | 개별 단일 번호 | `12` | `2` | 새 모임 만들기 | `/reading-clubs/set`                                | 공통 헤더 제목 조회 전용 |
| 숨김 하위 | 개별 단일 번호 | `12` | `2` | 독서 모임 상세 | `/reading-clubs/:clubNumb`                          | 경로 변수 패턴으로 공통 헤더 제목 조회 |
| 숨김 하위 | 개별 단일 번호 | `12` | `2` | 다음 독서 시작 | `/reading-clubs/:clubNumb/rounds/new`               | 경로 변수 패턴으로 공통 헤더 제목 조회 |
| 숨김 하위 | 개별 단일 번호 | `12` | `2` | 함께 읽은 기록 | `/reading-clubs/:clubNumb/rounds/:rondNumb/reports` | 경로 변수 패턴으로 공통 헤더 제목 조회 |
| 숨김 하위 | 개별 단일 번호 | `12` | `2` | 모임 편집 | `/reading-clubs/update/:clubNumb`                     | 경로 변수 패턴으로 공통 헤더 제목 조회 |

- `/reading-clubs`는 상위 메뉴의 구조용 경로로 두고 직접 접근하면 `/reading-clubs/mine`로 이동시킨다.
- 상위 메뉴 클릭은 화면 이동이 아니라 펼침·접힘으로 처리하고, 하위 메뉴가 활성화되어 있으면 상위 메뉴도 활성 상태로 표시한다.
- 사용자 메뉴 API는 평면 `menuList`를 그대로 노출하지 않고 각 메뉴에 `childList`를 가진 최대 3단계 계층 응답을 제공한다.
- 현재 경로 메뉴 조회는 정확한 URL, 콜론 경로 변수 패턴, 레거시 접두 URL 순으로 가장 구체적인 하위 메뉴를 선택해 모든 독서 모임 페이지명을 공통 헤더에 표시한다.
- 상위 메뉴와 하위 메뉴를 모두 `화면 노출 여부 = 'Y'`로 저장하더라도 상위 메뉴는 한 번만 렌더링하고 자식은 그 아래에서만 렌더링한다.
- 화면 내부에는 공통 헤더 제목과 중복되는 `h1`을 두지 않는다. 모임명, 도서명처럼 업무 콘텐츠의 제목은 `h2` 이하로 표현한다.
- 화면과 라우트가 배포된 상위 메뉴, `내 모임`, `모임 찾기`는 `화면 노출 여부 = 'Y'`로 운영하고 헤더 제목 전용 하위 메뉴는 계속 `N`으로 유지한다.

### 내 모임

- 내가 모임장인 모임과 참여 중인 모임을 구분하되 한 화면에서 함께 조회한다.
- 운영 중 회차, 미작성 독후감 및 읽지 않은 채팅이 있는 모임을 우선 표시한다.
- 받은 초대와 내 승인 가입 신청의 처리 상태를 별도 영역에 표시한다.
- 관심분야가 없어도 접근을 허용한다.
- 검색창은 홈·도서 검색 화면의 캡슐형 검색창과 같은 컴포넌트 스타일을 사용한다.
- 목록 카드와 상세 소개에는 모임명 첫 글자를 크게 표시하는 문자 표식을 두지 않는다.
- 화면 상단의 원형 `+` 버튼 대신 목록 아래에 설정 화면의 메뉴 행과 같은 `새 모임 만들기` 진입 영역을 둔다.

### 모임 찾기

- 회원 관심분야와 상위·세부 카테고리 조합이 정확히 일치하는 공개 모임을 먼저 표시한다.
- 대분류와 선택된 세부 카테고리를 함께 표시하고 카테고리, 가입 방식, 모집 상태 및 검색어 필터를 제공한다.
- 관심분야가 없으면 잘릴 수 있는 모달 대신 `/reading-clubs/interests` 독립 페이지로 이동하고 하나 이상 저장하기 전에는 공개 모임 목록을 표시하지 않는다.
- 관심분야 저장 실패 시 선택 화면에 머물며, 가입하지 않은 공개 모임 상세 직접 접근에도 같은 조건을 적용한다.
- 비공개 모임은 검색 결과에 포함하지 않는다.

### 모임 상세

- 소개: 대표 상위·세부 카테고리, 공개·가입 방식, 모임장, 정원, 모집 상태
- 현재 회차: 도서, 공동 목표 기간, 내 실제 독서 기간, 내 작성 상태
- 목표 결과: 전체 참여 인원, 목표 달성 인원 및 달성자 목록. 미달성자 이름과 참여·불참 상태는 표시하지 않음
- 모임 독후감: 공개 시점 전 잠금 상태, 공개 후 모임원별 연결 독후감
- 다음 도서: 추천 등록, 후보 목록, 투표 및 선정 결과
- 채팅: 메시지 목록, 전송 상태, 시스템 메시지
- 관리: 가입 신청, 초대, 회원 목록, 퇴장, 모임 설정

### 상태별 빈 화면과 오류

- 관심분야 없음
- 추천 모임 없음
- 가입 신청 처리 중
- 정원 마감
- 회차 없음
- 아직 독후감 공개 전
- 작성한 독후감 없음
- 퇴장 또는 접근 권한 없음
- 채팅 연결 실패와 재연결 중

### Figma 화면 설계 기준

독서 모임 화면은 현재 프런트엔드의 Vanilla Extract CSS와 디자인 토큰을 유지하면서 기존 홈, 도서 검색, 독후감 등록 및 설정 화면의 배치와 상호작용을 우선 재사용한다. 파란 브랜드 색은 선택 상태처럼 의미가 필요한 곳에만 제한하고 버튼·카드의 기본 강조색으로 강제하지 않는다. 모임 개설 화면은 Figma 노드 `2979:4263`의 입력 순서를 유지하되 선택 카드, 카테고리 팝업 및 정원 조절은 현재 서비스 공통 화면 패턴을 우선한다. 페이지명은 화면 본문에서 제거하고 사용자 화면 메뉴의 현재 메뉴명을 공통 헤더가 표시한다.

| 모서리 | 작은 요소 `7px`, 일반 카드 `12px`, 강조 카드 `22px`, 칩·버튼 `999px` |
| 그림자 | 헤더는 그림자를 사용하지 않고 카드에만 `0 8px 22px rgba(0,0,0,0.05)` 사용 |
| 터치 영역 | 아이콘 버튼 최소 `32px`, 주요 버튼 높이 `40px` 또는 `48px` |

Figma 설계 화면은 다음 사용자 흐름을 한 세트로 제공한다.

| 그룹 | 화면 | 반드시 표현할 정책 |
| --- | --- | --- |

| 탐색 | 모임 찾기 | 관심분야 일치 우선, 검색·카테고리·가입 방식·모집 상태 필터 |
| 탐색 | 관심분야 필수 선택 | 하나 이상 저장하기 전 목록 접근 불가, 대분류별 분류값 다중 선택 |

| 운영 | 모임 홈·현재 회차 | 자동 참여, 공동 목표 기간, 내 실제 기간, 내 독후감 상태, 채팅 진입 |
| 운영 | 신청·회원 관리 | 신청 질문·답변 심사, 맞팔 초대, 초대 좌석 3일 예약, 모임원 강제 퇴장 |
| 회차 | 목표 결과 | 전체 참여 수, 달성 수와 달성자만 표시하고 미달성자 명단은 숨김. 모임원 독후감 목록 진입 제공 |
| 회차 | 모임원 독후감 목록 | 회차 도서·목표 기간·작성 수, 작성자, 현재 독서 상태, 목표 달성 여부, 본문 일부와 수정일을 카드로 표시 |
| 회차 | 모임원 독후감 상세 | 선택한 작성자의 전체 본문, 평점, 실제 독서 기간과 모임 전용 공개 안내 표시 |
| 다음 도서 | 추천·투표 | 1인 최대 3권 추천, 1인 1표, 마감 전 변경, 동률 결선 흐름 |
| 소통 | 모임 채팅 | 활성 모임원 전용, 전송 상태, 시스템 메시지, 1차 출시에는 신고·차단 미노출 |
| 승계 | 모임장 선거 | 확정 부재 사유, 비밀투표, 종료 후 득표수 공개, 실패 시 모임 일시중지 |

- 모임 독후감은 개인 공개 설정이 비공개여도 공개 시점 이후 활성 모임원에게 보이는 상태를 화면 문구로 구분한다.
- 독서 모임 화면 하단에는 `내 모임`, `모임 찾기` 텍스트 탭을 두지 않는다. 기존 `Navigation.tsx`의 홈 아이콘, 가운데 돌출된 기록하기 버튼과 프로필 이미지 버튼을 동일하게 사용한다.
- 공개 모임 개설 화면은 `OPEN`과 승인형을 한 열의 선택 카드로 제공하고 승인형을 선택했을 때만 가입 질문 설정 단계로 이동한다.
- 모임 개설의 공개 설정과 가입 방식은 `settings/withdrawal`의 실제 라디오 입력을 포함한 선택 카드 스타일을 재사용하고, 항목 제목과 선택 카드 사이에는 최소 `14px` 간격을 둔다.
- 모임 카테고리는 본문에 전체 목록을 펼치지 않고 팝업에서 대분류별 세부 카테고리를 구분해 최대 3개까지 선택한다. 본문에는 선택된 카테고리와 팝업 진입 버튼만 표시한다.
- 모임 정원은 `select`를 사용하지 않고 마이페이지 독서 목표 설정처럼 감소 버튼, 숫자 직접 입력, 증가 버튼을 제공하며 `2`명부터 `30`명까지로 제한한다.
- 독서 모임 페이지는 공통 `Container`가 제공하는 좌우 여백을 그대로 사용하고 페이지 내부에서 별도 수평 패딩을 중복 적용하지 않는다.
- 목표 결과와 모임원 독후감 목록을 한 화면에 축약하지 않는다. 목표 결과에서 `모임원 독후감 보기`를 선택해 작성자별 목록으로 이동하고 각 카드에서 전체 독후감 상세로 이동한다.
- 본문이 없는 연결 독후감은 작성자 카드로 만들지 않고 미작성 건수만 이름 없이 안내한다.
- 회차 참여 여부를 별도 선택하는 UI는 두지 않는다. 도서 확정 시 모든 활성 모임원의 개인 독후감이 자동 생성된다는 안내를 제공한다.
- 다음 독서 시작의 도서 선택은 기존 도서 검색 API·검색창·결과 카드와 상세 화면을 재사용한다. 모임 검색 경로와 개인 검색 경로를 분리해 모임에서 선택한 책은 독서 등록 URL로 전달하고, 개인 검색의 독후감 등록 흐름은 유지한다. 독서 등록 화면에는 선택 도서 한 건과 책 변경 동작 및 공동 목표 기간만 표시한다.
- 다음 독서 목표 기간은 독후감 등록 화면의 기간 범위 달력을 재사용하고 시작일·종료일이 모두 선택된 경우에만 생성 요청을 허용한다.
- 회차 종료 후 미완료 회원은 개인 독후감의 `읽고 있어요` 상태를 유지하며, 모임 결과 화면에서는 이름을 노출하지 않는다.
- 1차 출시에서 제외한 공통 신고·차단 버튼이나 관리자 신고 심사 화면은 시안에 포함하지 않는다.

## API 초안

URI는 구현 시 프로젝트의 기존 API 버전 정책과 조정하되 명사형 하이픈 경로를 사용한다.

| Method | 경로 | 역할 |
| --- | --- | --- |
| `GET` | `/api/reading-interests` | 공지사항 카테고리 분류의 활성 대분류와 활성 자식 분류값 조회 |
| `GET` | `/api/users/me/reading-interests` | 내 대분류·세부 관심분야 조합 조회 |
| `PUT` | `/api/users/me/reading-interests` | 내 대분류·세부 관심분야 조합을 개수 제한 없이 교체 저장 |
| `GET` | `/api/users/me/reading-clubs` | 소유·참여 모임, 받은 초대 및 내 가입 신청 조회 |
| `GET` | `/api/reading-clubs` | 관심분야 보유 회원의 공개 추천·검색 목록 조회 |
| `POST` | `/api/reading-clubs` | 모임 개설 |
| `GET` | `/api/reading-clubs/{clubNumb}` | 모임 상세 조회 |
| `PUT` | `/api/reading-clubs/{clubNumb}` | 활성 모임장의 모임 정보 수정 |
| `DELETE` | `/api/reading-clubs/{clubNumb}` | 활성 모임장의 모임 및 종속 데이터 물리 삭제 |
| `POST` | `/api/reading-clubs/{clubNumb}/members` | 공개 즉시 가입 |
| `DELETE` | `/api/reading-clubs/{clubNumb}/members/{userNumb}` | 모임장 퇴장 처리 또는 본인 탈퇴 |
| `POST` | `/api/reading-clubs/{clubNumb}/applications` | 승인 가입 신청 |
| `PUT` | `/api/reading-clubs/{clubNumb}/applications/{applNumb}` | 신청 승인·거절 |
| `POST` | `/api/reading-clubs/{clubNumb}/invitations` | 맞팔 회원 초대 |
| `PUT` | `/api/reading-club-invitations/{invtNumb}` | 초대 수락·거절 |
| `POST` | `/api/reading-clubs/history/{clubNumb}` | 활성 모임장의 회차 확정과 활성 멤버별 `읽는 중` 독후감 일괄 생성 |

| `GET` | `/api/reading-club-rounds/{rondNumb}/reports` | 작성자·상태·목표 달성 여부·본문 일부를 포함한 모임 연결 독후감 목록 조회 |

| `POST` | `/api/reading-clubs/{clubNumb}/book-recommendations` | 다음 도서 추천 |
| `PUT` | `/api/reading-club-book-selections/{seltNumb}/vote` | 현재 `BOOK` 투표의 `대상 번호 = 도서 번호` 투표용지 등록·변경 |
| `PUT` | `/api/reading-club-book-selections/{seltNumb}` | 모임장 지정 필요 선정 건의 다음 도서를 현 모임장이 최종 확정 |
| `GET` | `/api/reading-clubs/{clubNumb}/chat-messages` | 이전 채팅 조회 |

| `GET` | `/api/reading-clubs/{clubNumb}/owner-election` | 진행 중 모임장 선거, 내 자격 및 후보 조회 |

| `PUT` | `/api/reading-club-owner-elections/{elctNumb}/my-vote` | 현재 모임장 투표의 후보 대상 번호 투표용지 등록·변경 |

각 API는 `ResultData`를 사용하고 URL의 모임·회차·회원 번호와 로그인 사용자의 권한을 서버에서 다시 검증한다. 외부 API는 도서 선정과 모임장 선거의 업무 경계를 유지하지만 투표 쓰기는 모두 현재 업무 원본에 연결된 모임 투표, 모임 투표 선택지, 모임 투표 참여 기록, 모임 투표 자격을 사용한다. `GET /api/reading-clubs`는 활성 관심분야가 하나 이상인 회원에게만 목록을 반환한다. `GET /api/reading-clubs/{clubNumb}`는 소유·가입·초대·신청 관계가 없는 공개 모임을 조회할 때 같은 관심분야 조건을 검사하여 화면 경로 우회를 막는다.

## 관리자 운영 설계

현행 관리자에는 사용자 메뉴, 공통코드, 알림 템플릿, 팝업, 회원 상태·이용 정지 및 스케줄러 로그 관리가 있다. 독서 모임 도메인 자체를 조회·제재하는 화면은 없으므로 다음 범위를 구분해 추가한다.

### 출시 필수 관리 범위

| 관리 영역 | 관리자 기능 | 제한과 감사 기준 |
| --- | --- | --- |
| 사용자 메뉴 | 사용자 화면 메뉴의 독서 모임 상·하위 메뉴명, URL, 노출·사용 여부 및 계층별 정렬 관리 | 상위 메뉴 삭제 전 하위 메뉴 존재 여부를 검사하고 존재하면 삭제를 차단한다. 연결 라우트가 없으면 노출 전환을 경고한다. |
| 모임 조회 | 모임명, 번호, 모임장, 공개 범위, 가입 방식, 카테고리, 상태, 정원, 활성 회원 수, 예약 초대 수 및 생성일 검색 | 관리자는 원칙적으로 회원 작성 소개를 직접 수정하지 않고 상태 조치와 이력 조회만 수행한다. |
| 모임 조치 | 운영 확인 또는 기존 고객 문의로 확인된 약관 위반 모임의 모집 중지, 이용 정지, 해제 및 종료 | 사유, 관리자, 처리 전후 상태, 일시를 감사 이력으로 남기고 모임장·영향 회원에게 알린다. 1차 출시에는 인앱 신고 접수를 연결하지 않는다. |
| 회원 조치 연계 | 현행 회원 이용 정지 시 모임 가입·초대·채팅·관리 권한을 즉시 차단 | 모임장 정지 시 공개 노출과 임시 운영 상태는 계정 수명주기 정책에 따라 처리한다. |
| 공통코드 | 공지사항 카테고리 분류의 대분류·자식 분류값 및 모임 상태·가입·회차·선거 코드를 등록·사용 중지하고 계층별 코드를 정렬 | 계층과 형제 순서는 공통코드 세부 항목의 상위 분류값, 공통코드 세부 항목의 정렬 순서로 관리한다. 회원이나 모임이 참조하는 분류값은 삭제하거나 다른 의미로 변경하지 않는다. |
| 초대·신청 운영 | 만료되지 않은 예약 초대, 좌석 계산, 처리 중 신청 및 중복 상태 조회 | 일반 관리자가 승인·거절을 대신하지 않고 데이터 불일치 복구는 별도 권한과 사유를 요구한다. |
| 스케줄러 | 초대 만료, 회차 상태 전환, 목표 달성 결과 마감, 목표 종료 공개, 다음 도서 14일 미확정 판정 및 알림 작업의 실행·실패 내역 조회 | 현행 스케줄러 로그 관리와 연결하고 재처리는 멱등키 단위로 제한한다. 목표 마감은 미판정 회차 목표 달성 여부만 `N`으로 바꾸며 이미 확정된 결과를 재계산하지 않는다. 도서 지연 판정은 `(모임 번호, 선정 도서 번호)` 단위로 멱등 처리한다. |
| 알림 템플릿 | 초대, 신청 결과, 퇴장, 회차 확정, 독후감 공개 및 제재 알림 관리 | 템플릿 비활성화가 필수 운영 알림을 누락시키지 않도록 필수 여부를 구분한다. |
| 데이터 진단 | 정원 초과, 고아 독서 모임 회차 참여, 중복 독후감 번호, 목표 종료 뒤 Null인 회차 목표 달성 여부, 존재하지 않는 도서·회원 참조 및 장기 `대기` 탐지 | 자동 수정하지 않고 진단 결과와 복구 작업 결과를 감사 로그에 남긴다. |
| 모임장 승계 | 확정 부재 사유와 근거, 도서 확정 책임 시작·마감 시각과 선정 상태, 진행 중 선거·후보·유권자·결과 및 권한 변경 이력 조회 | 관리자는 정상 선거의 당선자나 자동 확정된 독서 기간 초과를 임의 변경하지 않는다. 비가역적 제한과 관리자 확인 완료 사유 확정에는 별도 권한과 감사 사유가 필요하다. |

### 후속 공통 신고·차단 운영 범위

신고와 사용자 차단 구현은 1차 독서 모임 관리자 범위에 포함하지 않는다. 후속 출시에서는 독후감, 댓글, 모임, 사용자, 채팅 메시지 및 향후 추가 대상을 공통 신고 대상 유형으로 처리한다. 신고 접수·증거·심사·제재·이의 제기와 개인 차단 관계·노출 제한을 서로 분리하며, 차단 관계여도 공동 모임 참여와 제3자인 모임장의 초대를 허용하고 운영에 필요한 회원·회차·투표·독후감·댓글을 표시한다. 상대의 개인 프로필 이동과 직접 팔로우·좋아요·댓글·답글만 제한하며, 독서 모임 관리 화면은 공통 신고 관리 기능의 대상 상세로 연결한다.

### 모임장 부재와 승계 설계 기준

정책 결정의 부재는 최근 로그인이나 게시 활동이 없다는 사실만으로 판정하지 않는다. 물리 삭제, 복구 불가능한 영구 이용 제한, 모임장의 자발적 승계 요청, 모임장 전용 다음 도서 확정 상태의 14일 미이행 및 관리자가 같은 수준으로 확정한 권한 상실을 확정 부재로 본다. `비활성화`, 기간이 정해진 이용 정지, 해제 가능성이 남은 무기한 이용 정지 및 영구 탈퇴 대기는 그 자체만으로 확정 부재가 아니다.

물리 삭제 뒤에는 소유 모임을 다시 조회할 수 없으므로 영구 삭제 Service는 사용자 계정과 프로필 삭제 직전에 모임장인 모임을 조회하고 모임별 확정 부재 이벤트, 선거 및 감사값을 멱등하게 남긴다. 모든 모임의 기록이 성공하면 선거 완료를 기다리지 않고 계정을 삭제하고, 하나라도 실패하면 계정 삭제 전체를 재시도 대상으로 남긴다.

도서 미확정 사유의 14일은 `선정 도서의 도서 선정 방식 = '모임장 지정 필요'`로 변경된 역할 시작일부터 계산한다. 모임원 추천·투표가 진행 중이거나 모임이 이미 일시 중지이면 책임 상태를 시작하지 않는다. 책임 시작 뒤 모임이 일시 중지되면 계산을 멈추고 재개 시 남은 기간을 이어서 계산한다. 도서 확정과 지연 판정이 동시에 실행되면 같은 선정 행을 잠그며, 도서 확정이 먼저 완료되면 선거를 만들지 않고 지연 판정이 먼저 완료되면 기존 모임장의 후속 확정을 차단한다.

확정 부재가 기록되면 모임 상태를 모임장 선출으로 전환하고 선거 시작 시점의 활성 모임원 명부로 24시간 비밀투표를 시작한다. 선거 중에는 신규 가입·초대·신청 승인, 회차 확정 및 모임장 전용 설정 변경을 중지하고 기존 모임원의 조회·채팅·후보 등록·투표는 허용한다. 본인이 동의한 활성 모임원만 후보가 되며 유효표 최다 득표자가 당선된다. 동률이면 결선 투표를 한 번 진행하고, 후보나 유효표가 없어 24시간 연장 뒤에도 성립하지 않으면 모임을 일시 중지로 전환한다. 선거 종료 시 당선자의 활성 자격을 다시 확인하고 모임장과 회원 역할을 원자적으로 변경한 뒤 `활성`로 복귀한다.

### 후속 통계 범위

- 신규·활성·종료 모임 수, 공개·비공개 비율 및 카테고리 분포
- 가입 전환율, 승인 대기 시간, 초대 수락률 및 예약 좌석 만료율
- 회차 목표 달성률, 독후감 작성률, 다음 도서 추천·투표 참여율
- 퇴장률, 관리자 조치 건수 및 스케줄러 실패율

통계는 운영에 필요한 집계만 제공하고 개인 채팅 내용이나 비공개 독후감 본문을 분석 대상으로 사용하지 않는다.

## 채팅 설계

- 이전 메시지는 REST 커서 페이지네이션으로 조회한다.
- 실시간 송수신은 WebSocket을 우선 검토하고 연결 실패 시 재연결 상태를 표시한다.
- 서버는 연결 시점과 메시지 전송 시점 모두 활성 모임원 여부를 검사한다.
- 공개 모임 비회원과 처리 중 신청자는 채팅을 구독하거나 전송할 수 없다.
- 퇴장, 탈퇴 또는 계정 상태 변경 시 채널 구독을 즉시 종료한다.
- 메시지는 공통 텍스트 정규화와 비속어 정책을 적용한다.
- 읽음 기준과 보존 기간 및 삭제 정책은 추가로 확정한다. 채팅 신고는 공통 신고 도메인에서 후속 출시하고, 채팅의 사용자 차단 표시 범위는 시스템 메시지·모임장 공지와 일반 대화를 구분해 출시 전에 별도로 확정한다.

## 보안과 개인정보

- 모임 소개와 모집 정보 외의 회원 목록, 채팅 및 모임 독후감은 활성 모임원만 조회한다.
- 공개 모임 목록에는 가입 답변과 비공개 독후감 내용을 포함하지 않는다.
- 가입 신청 당시 질문 사본과 `대기` 답변은 모임장과 신청자 본인만 조회한다. 승인·거절 뒤에는 답변을 삭제하므로 어느 사용자에게도 반환하지 않는다.
- 모임장 권한은 화면 숨김이 아니라 모든 관리 API에서 검증한다.
- 회원 번호, 모임 번호 및 회차 번호를 바꿔 다른 모임에 접근하는 수평 권한 상승을 차단한다.
- 채팅과 가입 질문·답변에 스크립트 제거, 길이 제한, 비속어 검사 및 출력 이스케이프를 적용한다.
- 강제 퇴장 처리 이력은 일반 모임원에게 공개하지 않는다.

## 계정 수명주기 확정 정책

- `비활성화` 회원의 모임원 자격은 유지하되 모임 접근과 알림을 중지한다.
- `비활성화` 회원이 모임장이면 모임을 일시 중지로 전환하고 공개 검색과 신규 가입·신청·초대를 중지한다. 복귀한 모임장이 직접 재개한다.
- 영구 탈퇴 대기 30일 유예 중에는 모임장 선거를 시작하지 않고 해당 회원의 모임 접근과 운영 권한을 중지한다.
- 물리 삭제 직전에 모임별 확정 부재 이벤트, 선거 및 감사값을 모두 기록한 뒤 선거 완료를 기다리지 않고 계정을 삭제한다. 한 모임이라도 기록에 실패하면 계정 삭제 전체를 재시도한다.
- 물리 삭제 시 관심분야, 처리 중 신청의 질문 사본·답변, 식별 가능한 초대, 개인 독후감 및 채팅 본문을 삭제한다.
- 모임 화면에는 삭제된 독후감·메시지로 표시하고 회차 참여 건수와 목표 달성 집계는 식별값과 독후감 번호 연결을 제거한 비식별 상태로 유지한다.
- 재활성화 또는 영구 탈퇴 취소 시 모임원 자격은 복원하되 비활성화된 푸시 구독과 개인 공개 설정은 자동 복원하지 않는다.

상세 기준은 [계정 비활성화 및 영구 탈퇴 정책](../policies/withdrawal-policy.md)과 [독서 모임 정책 결정 항목](../policies/reading-club-policy-decisions.md)을 단일 구현 기준으로 함께 적용한다.

## 구현 단계 제안

1. 구현 명세화: 확정 정책을 DDL, API 계약, 화면 상태, 스케줄러 및 테스트 시나리오로 변환한다.
2. 스키마·공통코드: 대분류별 관심분야, 모임, 회원, 가입, 회차, 참여·독후감 연결, 추천, 공통 투표, 모임장 선거 및 채팅 구조를 추가한다.
3. 관심분야: 온보딩과 독립된 관심분야 저장, 기존 회원 보완 흐름 및 추천 정렬을 구현한다.
4. 모임 기본: 개설, 공개 검색, 즉시 가입, 승인 가입, 초대 및 퇴장을 구현한다.
5. 회차·도서: 도서 1회 확보, 회차 확정 및 개인 독후감 일괄 생성을 구현한다.
6. 독후감: 독서 모임 회차 참여 조인, 실제 기간 동기화, 공개 시점 및 모임 전용 권한을 구현한다.
7. 다음 도서와 공통 투표: 추천, `BOOK` 투표, 선정 및 다음 회차 생성을 구현하고 공통 선택지·유권자·투표용지 처리를 검증한다.
8. 채팅·알림: 실시간 채팅, 이전 내역, 시스템 메시지 및 푸시를 구현한다.
9. 모임장 선거: 확정 부재 이벤트, 모임장 후보 선택지, 공통 투표·개표, 권한 이전 및 감사 이력을 구현한다.
10. 관리자 운영: 모임 조회·상태 조치, 공통코드, 승계 이력, 알림 및 스케줄러 진단을 구현한다. 공통 신고·차단 관리는 후속 단계로 분리한다.
11. 운영 검증: 동시성, 접근 제어, 계정 상태, 데이터 마이그레이션 및 부하를 검증한다.

## 인수 기준

- 비공개 개인 독후감이 일반 공개 목록에는 없고 공개 시점 이후 허용된 모임원에게만 보인다.
- 승인형 모임의 현재 모임 가입 질문은 가입 방식 변경이나 모집 중지로 삭제되지 않고 모임이 존재하는 동안 유지된다.
- 가입 신청을 승인하거나 거절하면 처리 상태와 일시는 남지만 승인형 모임 가입 신청의 첫 번째부터 다섯 번째까지의 가입 답변은 같은 트랜잭션에서 즉시 Null이 되어 다시 조회되지 않는다.
- 회차 확정 시 별도 참여 응답 없이 그 시점의 활성 모임원 수만큼 독후감과 독서 모임 회차 참여가 생기며 모두 같은 도서 번호와 목표 기간을 가진다.
- 자동 생성한 모든 개인 독후감의 초기 상태는 `읽는 중`이고 회차 참여 선택이나 불참 상태 데이터는 생기지 않는다.
- 자동 생성된 독후감은 독서 모임 회차 참여의 독후감 번호 조인으로 모임명과 회차를 식별할 수 있다.
- 한 참여자가 실제 독서 기간을 바꾸면 개인 화면과 모임 화면에 같은 값이 보인다.
- 목표 종료 전에 `완독`이 확인된 회원만 `회차 목표 달성 여부 = 'Y'`로 확정되고, 나머지는 마감 시 `N`이 된다.
- 목표를 달성하지 못한 회원의 개인 독후감은 `읽는 중` 상태로 유지되며 나중에 `완독`으로 바뀌어도 종료된 회차 결과는 바뀌지 않는다.
- 회차 목표 요약 응답에는 전체 참여 인원, 달성 인원 및 달성자만 있고 미달성자 이름이나 참여·불참 상태는 없다.
- 미등록 ISBN으로 참여자 여러 명의 회차를 만들어도 도서 마스터에는 한 행만 생긴다.
- 같은 ISBN의 두 회차를 동시에 확정해도 한 도서만 참조하고 중복 키 오류로 사용자 요청이 불완전하게 남지 않는다.
- 관심분야가 없는 기존 회원은 `모임 찾기` 진입 시 필수 선택 안내를 받고 하나 이상 저장하기 전에는 공개 모임 목록이나 미가입 공개 모임 상세에 접근할 수 없다.
- 회원이 활성 세부 관심분야를 다수 선택해도 업무상 개수 제한으로 거절되지 않고 회원 독서 관심분야에는 조합별 한 행만 저장된다.
- 같은 대분류의 서로 다른 분류값을 선택하면 회원 독서 관심분야에 서로 다른 관련 업무 데이터 항목 하위 관심분야 분류값을 가진 두 행이 저장되고 같은 코드의 중복 행은 생기지 않는다.
- 존재하지 않거나 공지사항 카테고리 분류의 활성 대분류 자식이 아닌 분류값로 관심분야 또는 모임을 저장하면 전체 요청이 거절된다.
- 회원 관심분야와 정확히 일치하는 독서 모임 카테고리 조합 수가 많은 공개 모임이 먼저 정렬되고, 일치 수가 같으면 대표 카테고리 일치 여부와 대분류 부분 일치 수를 차례로 적용한다.
- `OPEN` 모임은 여석이 있을 때 즉시 가입되고 승인형 모임은 현재 질문 전체에 답하지 않으면 신청되지 않는다.
- 유효한 초대됨 회원 행이 예약한 자리는 즉시 가입과 신청 승인에 사용되지 않는다.
- 초대 수락은 정원 마감 오류 없이 예약 좌석을 활성 회원 좌석으로 전환한다.
- 마지막 일반 가입 가능 자리에 동시 가입·승인이 발생해도 정원을 초과하지 않는다.
- 모임장이 퇴장시킨 회원은 즉시 채팅과 모임 전용 비공개 독후감에 접근할 수 없다.
- 한 계정이 여러 모임의 모임장과 회원 역할을 동시에 가질 수 있다.
- 사이드 메뉴는 `독서 모임` 아래 `내 모임`, `모임 찾기`를 2뎁스로 표시하고 두 하위 메뉴의 활성 상태와 키보드 조작이 동작한다.
- 관심분야가 없는 회원도 `내 모임`, 받은 초대, 내 가입 신청 및 가입한 모임 상세를 확인할 수 있고 `모임 찾기`에서만 하나 이상의 관심분야 저장을 요구한다.
- 사용자 메뉴 노출 시점에는 `/reading-clubs`, `/reading-clubs/mine`, `/reading-clubs/find`, `/reading-clubs/interests`, `/reading-clubs/set`와 상세·회차 경로가 모두 유효한 라우트이다.
- 독서 모임의 모든 라우트는 사용자 화면 메뉴의 정확 URL 또는 콜론 경로 변수 패턴으로 현재 메뉴를 찾고, 본문에 중복 페이지 제목 없이 공통 헤더에 메뉴명을 표시한다.
- 관리자의 모임 상태 조치에는 처리 사유와 전후 상태가 감사 이력으로 남으며 1차 독서 모임 화면에는 신고·차단 기능이 노출되지 않는다.
- 관심분야 조회 응답은 공지사항 카테고리 분류의 활성 최상위 대분류와 각 대분류의 활성 자식 분류값을 순서대로 노출한다. 회원과 모임 관심분야 저장 요청은 관련 업무 데이터 항목 하위 관심분야 분류값만 전달하며, 모임은 서로 다른 코드 1~3개와 1부터 시작하는 노출 순서를 함께 저장한다.
- 자발적 승계 요청, 물리 삭제, 복구 불가능한 영구 제한 또는 모임장 전용 다음 도서 확정 상태의 14일 미이행이 확정되면 모임장 선거가 한 건만 시작되고 기존 모임장 대신 관리자 임의 지정 없이 투표 결과가 적용된다.
- 추천·투표 중에는 도서 확정 14일 기한이 시작되지 않고 모임장 지정 필요 전환 시 역할 시작일, 역할 종료일이 정확히 14일 간격으로 저장된다.
- 도서와 모임장 투표가 각각 모임 투표에 생성되고 투표 유형에 따라 동일한 대상 번호가 도서 번호 또는 후보 회원 번호로 정확히 해석된다.
- 모임 투표 선택지에는 같은 투표·대상 선택지가 한 건만 생기고, 한 책을 여러 회원이 추천해도 도서 선택지는 도서 번호 기준 한 건만 생성된다.
- 모임 투표 자격에는 같은 투표·유권자의 행이 한 건만 유지되며 마감 전 변경은 새 행 추가가 아니라 대상 번호 갱신으로 반영된다.
- 결선 투표는 새 투표 번호와 결선 투표의 이전 투표 번호를 사용하고 동률 선택지만 포함한다.
- 마감 직전 도서 확정과 지연 판정이 동시에 실행돼도 선정과 독서 기간 초과가 함께 확정되지 않는다.
- 선거 마감과 권한 이전이 성공하면 모임장, 두 회원의 역할, 선거 상태와 모임장 변경 감사 이력이 모두 함께 반영되며 일부만 변경되지 않는다.

### 현행과 제안의 구분

- 현행 소스에는 독서 모임 화면, 메뉴, 모임 생성·가입·회차·공유 API가 없다.
- 최초 로그인 사용자는 `온보딩 완료 여부 = 'N'`인 동안 웰컴 화면에서 활성 공지사항 카테고리 분류 관심분야를 선택하거나 건너뛸 수 있다. 관심분야 저장 실패 여부와 관계없이 웰컴 완료 요청이 성공하면 온보딩 완료 여부는 `Y`가 된다.
- 현행 데이터베이스에는 독서 모임 공통코드와 공통코드 세부 항목의 상위 분류값 계층을 유지한다.
- 현행 독서 모임 기반 테이블은 회원 독서 관심분야, 독서 모임, 독서 모임 카테고리, 모임 회원 및 초대 예약석, 모임 가입 질문, 승인형 모임 가입 신청, 독서 모임 회차, 독서 모임 회차 참여 여덟 개이다.
- 이 문서의 나머지 화면, API 및 테이블은 재구현 전 제안이며 현재 기능으로 해석하지 않는다.
