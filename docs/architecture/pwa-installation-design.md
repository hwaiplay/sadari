# PWA 설치 권장 알럿 기획

## 개요

- 기준일은 2026년 8월 27일이다.
- 문서 상태는 확정 설계이며 사용자 웹과 데이터베이스에는 아직 적용하지 않았다.
- 웹 환경으로 로그인한 활성 회원에게 계정 단위로 PWA 설치 권장 알럿을 한 번만 표시하는 구조를 정의한다.
- 실제 설치 여부와 설치 전환 행동은 수집하지 않으며 관리자 통계 기능도 제공하지 않는다.

## 요구사항

1. 웹 환경으로 로그인한 활성 회원에게 PWA 설치 권장 알럿을 계정당 한 번 표시한다.
2. 설치형 PWA로 실행 중인 화면에는 알럿을 표시하지 않는다.
3. 사용자가 알럿의 확인 버튼을 선택하면 계정에 확인 일시를 저장한다.
4. 확인 일시가 저장된 계정에는 다른 브라우저나 기기에서도 알럿을 다시 표시하지 않는다.
5. 알럿의 확인 버튼은 브라우저 설치 대화상자나 다운로드를 실행하지 않는다.
6. 설치 여부, 설치 버튼 선택, 플랫폼, 브라우저 및 기기 정보는 저장하지 않는다.
7. 관리자 화면과 사용자 통계에는 PWA 설치 관련 지표를 추가하지 않는다.

## 현행 구조

- 사용자 웹은 서비스워커를 등록하고 앱 셸과 정적 자원의 업데이트를 관리하지만 설치 권장 알럿은 아직 제공하지 않는다.
- OAuth 완료 화면은 인증 상태와 온보딩 및 제한 상태를 확인한 뒤 홈 또는 전용 화면으로 이동한다.
- 사용자 기본정보에는 PWA 설치 권장 알럿의 확인 여부를 판정할 데이터가 없다.

## 확정 정책

| 항목 | 결정 |
| --- | --- |
| 권장 단위 | 사용자 계정 단위 |
| 노출 횟수 | 확인 완료 전까지 로그인 후 노출, 확인 완료 후 영구 미노출 |
| 다른 기기 로그인 | 같은 계정의 확인 일시를 사용하므로 미노출 |
| 설치형 실행 | 알럿 미노출, 확인 일시는 자동 저장하지 않음 |
| 확인 버튼 | 안내 확인 상태만 저장하고 설치 동작은 실행하지 않음 |
| 실제 설치 추적 | 수집하지 않음 |
| 관리자 통계 | 제공하지 않음 |
| 알림과 소셜 영향 | 없음 |

세부 사용자 정책은 [설치형 웹앱 설치 권장 알럿 정책](../policies/pwa-installation-policy.md)을 따른다.

## 데이터 설계

별도 상태, 이벤트 이력 및 일별 집계 테이블을 생성하지 않는다. 사용자 기본정보에 확인 일시 항목 하나만 추가한다.

| 논리 항목 | 타입 | Null | 역할 |
| --- | --- | --- | --- |
| PWA 설치 권장 알럿 확인 일시 | 마이크로초 정밀도 일시 | 허용 | Null이면 권장 대상, 값이 있으면 확인 완료로 판정 |

- 기존 회원은 초기값을 Null로 두어 최초 로그인 이후 알럿을 표시한다.
- 확인 일시는 최초 확인 시각만 유지하며 재요청으로 덮어쓰지 않는다.
- 사용자 원본에 포함되는 항목이므로 별도 외래키, 인덱스 및 정리 작업은 필요하지 않다.
- 알럿 확인 여부는 설치 여부를 의미하지 않으며 설치 상태로 사용하지 않는다.

## 데이터 처리 흐름

1. 로그인, 계정 상태 판정, 최초 로그인 안내와 홈 이동을 완료한다.
2. 프론트엔드는 현재 화면이 설치형 PWA인지 확인한다.
3. 설치형 PWA이면 권장 판정을 종료한다.
4. 웹 환경이고 서버의 확인 일시가 Null이면 설치 권장 알럿을 표시한다.
5. 사용자가 확인 버튼을 선택하면 서버에 확인 완료를 요청한다.
6. 서버는 인증된 사용자 계정의 확인 일시가 Null일 때만 현재 시각을 저장한다.
7. 저장에 성공하면 알럿을 닫고 이후 로그인부터 표시하지 않는다.

알럿을 확인하지 않고 브라우저나 화면을 종료하면 확인 일시를 저장하지 않으므로 다음 로그인에서 다시 표시할 수 있다.

## API 기획

- 기존 인증 또는 사용자 정보 응답에 설치 권장 알럿 확인 여부를 추가해 별도 조회 요청을 만들지 않는다.
- 확인 버튼 선택 시 로그인 사용자 본인의 확인 일시를 저장하는 멱등 쓰기 API 하나를 제공한다.
- API 경로와 응답 필드는 구현 단계에서 기존 사용자 API 규칙, Swagger 및 프론트 타입과 함께 확정한다.
- 서버는 요청 본문의 사용자 식별값을 받지 않고 인증 정보에서 저장 대상을 결정한다.

## 사용자 화면 기획

### 노출 시점

- 로그인과 온보딩 및 계정 복귀 안내가 끝난 뒤 홈 화면에서 표시한다.
- 비활성화, 영구 탈퇴 대기 및 이용정지 전용 화면에는 표시하지 않는다.
- 같은 화면 렌더링 중 중복 표시되지 않도록 클라이언트 세션에서도 노출 상태를 제어한다.

### 알럿 구성

- 제목과 PWA 이용 이점을 설명하는 짧은 본문을 제공한다.
- 확인 버튼 하나를 기본 동작으로 제공한다.
- 확인 버튼은 안내를 닫고 서버에 확인 일시를 저장할 뿐 설치 또는 다운로드를 시작하지 않는다.
- 브라우저별 설치 방법을 추가로 안내해야 하면 별도 정책 변경 후 범위에 포함한다.

### 접근성

- 알럿 제목과 설명을 연결하고 최초 초점을 확인 버튼에 둔다.
- 키보드와 보조기기로 확인 버튼을 실행할 수 있게 한다.
- 알럿을 닫으면 열기 전 요소로 초점을 복원한다.

## 서버 처리와 동시성

- 확인 API는 인증된 활성 회원만 호출할 수 있다.
- 확인 일시가 Null인 경우에만 현재 시각으로 갱신해 최초 확인 시각을 보존한다.
- 여러 탭이나 기기에서 동시에 요청해도 이미 확인된 상태는 성공으로 처리하고 값을 다시 쓰지 않는다.
- 확인 저장은 단일 사용자 행 갱신이므로 별도 이벤트 트랜잭션이나 집계 보상 처리가 필요하지 않다.

## 계정 수명주기

- 계정 비활성화와 영구 탈퇴 대기 중에는 알럿을 표시하거나 확인 일시를 변경하지 않는다.
- 계정이 다시 활성화되거나 영구 탈퇴를 취소하면 기존 확인 일시를 그대로 사용한다.
- 유예기간 뒤 사용자 원본이 물리 삭제되면 확인 일시도 함께 삭제된다.
- 재가입 계정에는 삭제된 계정의 확인 일시를 복원하거나 연결하지 않는다.

## 보안과 개인정보

- 확인 요청에는 기존 Cookie 인증과 CSRF 검증을 적용한다.
- 서버는 인증 주체에서 사용자 식별값을 결정한다.
- 설치 여부, 원본 User-Agent, IP 주소, 광고 식별자와 브라우저 지문을 저장하지 않는다.
- 확인 일시는 권한, 계정 상태 또는 서비스 접근을 결정하는 보안 신호로 사용하지 않는다.

## 실패 처리

- 사용자 정보 조회가 실패하면 로그인 자체를 실패 처리하고 기존 공통 오류 흐름을 따른다.
- 확인 일시 저장이 실패하면 알럿을 닫지 않고 재시도 가능한 오류를 안내한다.
- 중복 확인 요청은 오류로 처리하지 않고 현재 확인 완료 상태를 반환한다.
- 화면 이동이나 브라우저 종료로 요청이 완료되지 않으면 확인되지 않은 상태로 유지한다.

## 검증 계획

### 사용자 서버

- 확인 일시가 없는 활성 계정의 권장 대상 응답
- 확인 완료 계정의 권장 제외 응답
- 본인 계정 확인 일시 최초 저장과 중복 요청 멱등 처리
- 비활성화, 영구 탈퇴 대기 및 이용정지 계정의 확인 요청 거부
- 사용자 식별값 위변조 방지와 CSRF 검증
- 영구 삭제 시 사용자 원본과 확인 일시의 동시 삭제

### 사용자 웹

- 웹 로그인 완료 후 확인 일시가 없을 때 한 번만 노출
- 확인 성공 후 현재 세션과 이후 로그인에서 미노출
- 저장 실패 시 오류 안내와 재시도
- 설치형 PWA 실행 중 미노출
- 로그인, 온보딩, 복귀 안내 및 제한 화면과 알럿이 겹치지 않는지 확인
- 모바일·데스크톱 키보드 및 보조기기 접근성 확인

## 구현 순서

1. 사용자 저장소의 스키마 원본과 테이블 명세에 확인 일시 항목을 반영한다.
2. 사용자 정보 조회 응답과 확인 저장 API를 구현한다.
3. 사용자 웹에 실행 환경 판정과 설치 권장 알럿을 구현한다.
4. 계정 상태별 접근 제어와 영구 삭제 동작을 확인한다.
5. 서버, 프론트엔드 및 반응형 검증을 수행한다.

## 대안과 선택 이유

### 설치 상태 및 전환 이벤트 추적

- 장점은 설치 전환 추이와 브라우저별 행동을 분석할 수 있는 점이다.
- 단점은 브라우저별 신호 차이로 전체 설치를 정확히 측정할 수 없고 별도 상태, 이벤트 및 집계 구조가 필요하다는 점이다.
- 이번 범위에서는 설치 권장 안내만 필요하므로 선택하지 않는다.

### 브라우저 설치 대화상자 호출

- 장점은 지원 브라우저에서 설치 절차를 바로 시작할 수 있는 점이다.
- 단점은 브라우저 지원 여부와 사용자 동작에 따라 흐름이 달라지고 브라우저 자체 확인 단계를 생략할 수 없는 점이다.
- 일관된 단일 알럿 경험을 위해 이번 범위에서는 선택하지 않는다.

### 확인 여부 값 저장

- 장점은 값이 단순한 점이다.
- 단점은 최초 확인 시각을 알 수 없고 별도 관리 값 없이 데이터 생성 시점을 확인할 수 없는 점이다.
- 한 항목으로 확인 여부와 최초 확인 시각을 함께 표현할 수 있는 nullable 일시를 선택한다.

## 제외 범위와 남은 제약

- 실제 PWA 설치, 설치 취소 및 제거 여부 감지
- 설치 버튼과 브라우저별 수동 설치 방법 제공
- 설치 권장 노출, 닫기 및 설치 전환 이벤트 이력
- PWA 관련 관리자 통계와 개별 사용자 조회
- 설치형 PWA로 먼저 이용한 계정의 확인 일시 자동 저장
- 계정 단위 정책으로 인해 한 기기에서 확인하면 다른 기기에서도 권장하지 않는 제약
