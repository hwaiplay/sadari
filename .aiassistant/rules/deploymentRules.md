# Deployment Rules

이 문서는 Sadari 프로젝트의 환경설정, GitHub Actions, Docker 및 운영 배포 문서 동기화 규칙을 정의합니다.
배포 설정을 생성하거나 수정할 때 아래 규칙을 예외 없이 적용합니다.

## 1. YML과 배포 문서 동기화

- `application.yml`, `application-*.yml`에 설정을 추가, 삭제, 변경하거나 환경변수 이름과 기본값을 변경하면 같은 작업에서 `docs/github-actions-deployment.md`를 수정합니다.
- 운영 배포에 필요한 환경변수는 이름, 기본값, 용도, 등록 위치를 `docs/github-actions-deployment.md`에 기록합니다.
- 로컬 전용 설정이나 운영에서 고정하는 설정은 환경변수로 등록하지 않더라도 적용 프로필과 고정 사유를 `docs/github-actions-deployment.md`에 기록합니다.
- YML 환경변수는 `.env.example`, GitHub Actions 워크플로, Docker Compose에서 전달이 필요한지 확인하고 필요한 파일을 같은 작업에서 동기화합니다.

## 2. 환경변수 분류

- 비밀번호, 토큰, 개인키, API 비밀키는 GitHub Actions `Secret`으로 분류합니다.
- 포트, 제한 건수, 타임아웃, 정책 기간처럼 공개되어도 보안 문제가 없는 값은 GitHub Actions `Variable`로 분류합니다.
- 기본값이 있어도 운영 정책을 변경할 가능성이 있으면 재빌드 없이 조정할 수 있도록 환경변수 사용을 우선 검토합니다.
- 운영에서 절대 활성화하면 안 되는 테스트 설정은 환경변수로 노출하지 않고 운영 YML에 안전한 값으로 고정합니다.

## 3. 보안 규칙

- 실제 비밀번호, 토큰, 개인키, 서비스 계정 JSON 원문을 YML, 예시 파일, 배포 문서에 기록하지 않습니다.
- `.env.example`에는 실제 값 대신 용도를 알 수 있는 예시 값만 작성합니다.
- 공개 가능한 설정과 비밀 설정을 같은 GitHub Actions 등록 영역으로 안내하지 않습니다.

## 4. 검증 규칙

- YML의 환경변수 이름과 `docs/github-actions-deployment.md`, `.env.example`, GitHub Actions 워크플로의 이름이 일치하는지 확인합니다.
- 기본값과 단위가 모든 설정 파일과 문서에서 일치하는지 확인합니다.
- 프로필별 설정이 의도한 환경에서만 활성화되는지 확인합니다.
- 변경된 배포 문서에 실제 비밀값이 포함되지 않았는지 확인합니다.
