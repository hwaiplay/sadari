# View Rules

이 문서는 Sadari 프로젝트의 React 화면 렌더링, 사용자 노출 문구, JSX 주석 및 공통 CSS 규칙을 정의합니다.
화면 코드를 생성하거나 수정할 때 아래 규칙을 예외 없이 적용합니다.
규칙은 공통 주석 정책, 화면 영역 식별, 사용자 메시지 식별, 이미지, 버튼 및 CSS 작성 형식 순으로 중요도가 높은 항목부터 나열합니다.

## 1. 공통 주석 작성 규칙

- 일반 주석과 JSDoc은 모두 `한다`, `이다`, `된다` 형태의 반말 서술체로 작성합니다.
- 주석에 `합니다`, `입니다`, `됩니다` 형태의 존댓말을 사용하지 않습니다.
- 주석에 이모티콘과 이모지를 사용하지 않습니다.
- 주석에 느낌표와 물음표를 사용하지 않습니다.
- 사용자에게 노출되는 실제 문구를 인용한 주석은 원문을 그대로 작성하며 문구 안의 문체와 문장부호는 예외로 둡니다.
- 코드 내용을 그대로 읽는 주석은 작성하지 않고 화면 정책과 구현 이유를 설명합니다.

## 2. 화면 영역 주석 규칙

- 하나의 페이지를 구성하는 모든 주요 화면 영역 바로 위에 해당 영역의 역할을 설명하는 JSX 주석을 작성합니다.
- 주요 화면 영역 안에 독립된 정보, 입력, 목록, 통계, 버튼 또는 상태 표시 영역이 있으면 각 하위 영역 바로 위에도 JSX 주석을 작성합니다.
- 하위 영역 안에 다시 독립된 기능 단위가 있으면 깊이와 관계없이 같은 방식으로 주석을 작성합니다.
- 주석은 사용자가 화면에서 인식하는 기능과 정보 단위를 기준으로 작성합니다.
- `div`, `span` 등 HTML 태그명이나 CSS 클래스명을 설명하지 않고 해당 영역이 사용자에게 제공하는 역할을 작성합니다.
- 레이아웃 정렬만을 위한 래퍼처럼 별도의 기능과 의미가 없는 요소에는 영역 주석을 강제하지 않습니다.
- 반복 목록에는 목록 전체 영역 주석과 개별 항목 영역 주석을 각각 작성합니다.
- 모달에는 모달 전체, 배경, 본문, 헤더, 입력 또는 정보, 버튼 영역을 구분하여 주석을 작성합니다.
- 조건부 렌더링과 Portal로 분리된 화면도 실제 화면에 표시되는 독립 영역이면 주석을 작성합니다.
- 렌더링 함수가 특정 화면 영역 전체를 반환하면 반환 JSX의 최상위 요소 바로 위에 영역 주석을 작성합니다.
- 영역이 추가되거나 역할이 변경되면 관련 영역 주석도 같은 변경에서 함께 수정합니다.

```tsx
<main className={styles.page}>
  {/* 마이페이지 프로필과 독서 활동 전체 영역 */}
  <form className={styles.profileShell}>
    {/* 프로필 배경 이미지 영역 */}
    <section className={styles.cover}>
      {/* 배경 이미지 변경과 프로필 저장 및 수정 버튼 영역 */}
      <div className={styles.coverActionGroup}>
        {profileActions}
      </div>
    </section>

    {/* 프로필 기본 정보 영역 */}
    <section className={styles.profileBody}>
      {/* 프로필 이미지와 이미지 변경 영역 */}
      <div className={styles.avatarWrap}>
        {profileImage}
      </div>

      {/* 닉네임과 한줄소개 영역 */}
      <div className={styles.profileText}>
        {profileText}
      </div>
    </section>

    {/* 현재 읽고 있는 책 영역 */}
    <section className={styles.currentReading}>
      {/* 현재 읽고 있는 책 목록 영역 */}
      <div className={styles.currentReadingList}>
        {reports.map((report) => (
          /* 현재 읽고 있는 책 개별 항목 영역 */
          <article key={report.reptNumb}>
            {/* 현재 읽고 있는 책 표지 영역 */}
            {report.bookCover}

            {/* 현재 읽고 있는 책 제목과 독서기간 영역 */}
            <div>{report.bookInfo}</div>
          </article>
        ))}
      </div>
    </section>
  </form>
</main>
```

## 3. 사용자 메시지 주석 규칙

- 사용자나 보조기기에 전달되는 문구는 JSX와 TypeScript 코드에 직접 작성하지 않고 `message` 함수와 메시지 프로퍼티 키로 관리합니다.
- 제목, 페이지 설명, 본문, 라벨, 버튼명, 링크명, `placeholder`, 도움말, 빈 상태, 로딩 상태, 상태명, 옵션명, 단위, 알림, 기본값 및 대체 문구를 모두 메시징 처리합니다.
- `aria-label`, `aria-description`, `title` 및 의미가 있는 이미지 `alt`도 사용자 노출 문구로 간주하여 메시징 처리합니다.
- 조건식, 배열, 객체, 상수, 템플릿 문자열 및 문자열 결합 안에 있는 표시 문구도 직접 작성하지 않습니다.
- 서버가 완성된 표시 문구로 제공한 값과 사용자가 작성한 콘텐츠는 메시징 처리 대상에서 제외하되, 코드의 기본값이나 대체 문구가 함께 표시되면 해당 문구는 메시징 처리합니다.
- 메시지 키를 추가, 변경 또는 삭제할 때는 기본 언어와 영어를 포함한 모든 지원 언어 파일을 함께 수정하고 키 집합과 치환 파라미터를 일치시킵니다.
- `message`, `alert`, toast, SweetAlert, 모달 및 안내 문구처럼 사용자 화면에 문구를 노출하는 모든 코드 바로 위에 실제 노출 문구를 주석으로 작성합니다.
- 메시지 프로퍼티 키를 호출할 때는 해당 키에 연결된 기본 언어의 실제 문구를 주석에 작성합니다.
- 주석에는 `화면표시:`와 같은 접두사를 작성하지 않고 실제 문구만 큰따옴표로 감싸서 작성합니다.
- 조건에 따라 서로 다른 문구를 호출하면 각 메시지 호출 바로 위에 해당 분기의 실제 문구를 개별 작성합니다.
- 서버에서 이미 완성된 표시 문구를 받아 그대로 렌더링하는 경우에는 메시지 함수 호출이 아니므로 실제 문구 주석을 강제하지 않습니다.
- 메시지 프로퍼티의 문구가 변경되면 호출부의 실제 문구 주석도 같은 변경에서 함께 수정합니다.
- 둘 이상의 화면에서 의미와 기본 문구가 같은 메시지는 `frontend.common.*` 키를 우선 사용합니다.
- 번역 결과만 같거나 화면 맥락, 동작, 상태의 의미가 다르면 기능별 메시지 키를 유지합니다.

## 4. JSX 메시지 주석 형식

- JSX 태그 내부에서는 `{/* "실제 문구" */}` 형식으로 주석을 작성합니다.
- JSX 요소의 여는 태그와 닫는 태그 사이에는 일반 `/* ... */` 주석을 작성하지 않습니다.
- JSX 자식 영역의 일반 `/* ... */` 문자열은 주석으로 처리되지 않고 화면에 노출되므로 반드시 `{/* ... */}` 형식을 사용합니다.
- `return (` 바로 다음처럼 JSX 요소 바깥의 JavaScript 표현식 영역에서만 일반 `/* ... */` 주석을 사용합니다.
- JSX 바깥의 TypeScript 영역에서는 `// "실제 문구"` 형식으로 주석을 작성합니다.
- JSX 조건 분기에서는 Fragment를 사용하여 각 메시지 호출 바로 위에 주석을 배치합니다.
- 하나의 주석으로 여러 메시지 호출을 묶지 않습니다.

```tsx
<section className={styles.section}>
  <h2 className={styles.sectionTitle}>
    {/* "공개 여부" */}
    {message("frontend.common.visibility")}
  </h2>

  <div className={styles.statusPill}>
    {bookData.pubcYsnoName ||
      (bookData.pubcYsno === "Y" ? (
        <>
          {/* "공개" */}
          {message("frontend.common.public")}
        </>
      ) : (
        <>
          {/* "비공개" */}
          {message("frontend.common.private")}
        </>
      ))}
  </div>
</section>
```

## 5. TypeScript 메시지 주석 형식

- JSX 밖에서 메시지를 변수에 저장하거나 알림 함수에 전달하는 경우에도 각 함수 호출 바로 위에 실제 문구를 작성합니다.
- 메시지 조회와 사용자 알림 호출이 분리되어 있으면 각 호출의 역할에 맞는 주석을 개별 작성합니다.

```typescript
// "필수 입력 항목을 확인해 주세요."
const requiredMessage = message("frontend.validation.required");

// "필수 입력 항목을 확인해 주세요."
await sweetWarning(requiredMessage);
```

## 6. 동적 이미지 오류 처리

### 6.1 회원 프로필 이미지

- API, 외부 CDN 또는 업로드 경로에서 받은 프로필 이미지는 공통 프로필 이미지 컴포넌트를 사용합니다.
- 프로필 이미지 경로가 비어 있거나 `null`, `undefined` 문자열이면 브라우저 요청 전에 `/img/common/icon-user.svg`로 보정합니다.
- 원본 프로필 이미지 로드에 실패하면 `/img/common/icon-user.svg`로 교체합니다.
- 기본 이미지 로드까지 실패한 경우 같은 경로를 반복 대입하여 오류 이벤트가 무한 반복되지 않게 처리합니다.
- HTTPS 화면에서 차단될 수 있는 신뢰된 외부 프로필 이미지의 HTTP 주소는 지원 가능한 HTTPS 주소로 보정합니다.
- 앨범에서 선택한 프로필 및 배경 이미지는 모바일 PWA 메모리 한도를 고려해 브라우저에서 원본을 디코딩하지 않고, 사용자 전용 비공개 서버 임시 저장소가 방향 보정과 축소를 완료한 미리보기만 표시합니다.
- 서버가 허용하지 않는 이미지 형식과 해상도는 임시 저장 응답으로 안내하고 선택 상태에 반영하지 않습니다.
- 마이페이지 프로필 수정 모드는 기존 배경, 프로필 사진, 닉네임 및 한줄소개 위치와 정렬을 유지하며 독서 통계와 독서 활동 영역만 렌더링에서 제외합니다.
- 앱 재시작 후 만료되지 않은 서버 임시 선택본을 복원할 때도 기존 사용자 정보 영역 안에서 미리보기와 편집 상태만 복원합니다.

### 6.2 책 표지 이미지

- 책 표지 이미지 경로가 비어 있거나 `null`, `undefined` 문자열이면 브라우저 요청 전에 `/img/common/no-image.png`로 보정합니다.
- 원본 책 표지 이미지 로드에 실패하면 `/img/common/no-image.png`로 교체합니다.
- `/img/common/no-image.png` 로드까지 실패한 경우 같은 경로를 반복 대입하지 않아 오류 이벤트의 무한 반복을 차단합니다.

## 7. 주요 명령 버튼 시각 규칙

- 저장, 검색, 선택, 확인, 등록, 수정 및 삭제처럼 페이지 기능을 실행하는 버튼은 공통 `ActionButton` 컴포넌트를 사용합니다.
- 기능 버튼의 중요도와 상태는 개별 화면에서 버튼 스타일을 다시 만들지 않고 `ActionButton`의 `variant`, `size`, `width` 속성으로 구분합니다.
- 아이콘만 표시하는 기능 버튼도 `ActionButton`을 사용하고 `aria-label`로 기능명을 제공합니다.
- 선택된 옵션과 달력 선택 날짜처럼 현재 상태를 전달하는 버튼은 `ActionButton` 적용 대상에서 제외할 수 있지만 공통 선택 상태 스타일을 사용합니다.
- 스위치 트랙과 아이콘처럼 버튼 배경이 아닌 요소는 상태 전달에 필요한 기존 색상을 유지할 수 있습니다.

### 7.1 클릭 요소 Hover 스타일

- `onClick` 또는 제출 동작이 있는 버튼, 링크, 카드 및 기타 클릭 요소에는 기본적으로 `hover` 스타일을 적용합니다.
- 배경이 `#ffffff` 또는 `vars.color.background`인 클릭 요소는 `hover` 배경에 `vars.color.gray100`을 사용합니다.
- 배경이 `vars.color.gray900`인 클릭 요소는 `hover` 배경에 `vars.color.darkGray`를 사용합니다.
- 배경이 `vars.color.negativeBg`인 클릭 요소는 `hover` 배경에 `vars.color.negativeHover`를 사용합니다.
- 기본 배경이 투명한 클릭 요소도 화면 구조에 맞는 `hover` 상태를 제공하며, 별도 의미 색상이 없으면 `vars.color.gray100`을 우선 사용합니다.
- 별도 테두리나 카드 배경 없이 페이지 배경 위에서 전체 너비를 차지하며 다른 화면으로 이동하는 단순 메뉴 행에는 `hover` 스타일을 적용하지 않습니다.
- 비활성화된 클릭 요소에는 `hover` 상태를 적용하지 않습니다.

### 7.2 선택형 카드와 칩 상태 스타일

- 관심분야, 설문, 필터처럼 사용자가 눌러 선택 상태를 전환하는 카드와 칩은 회원 탈퇴 화면의 선택 요소와 동일한 상태 표현을 사용합니다.
- 선택 전에는 `vars.color.gray300` 테두리, `#f7f8f8` 배경, `#7b8187` 글자색을 사용하고 마우스를 올리면 `vars.color.gray100` 배경을 사용합니다.
- 선택 후에도 `vars.color.gray300` 테두리를 유지하고 `#eef8f2` 배경과 `#34704d` 글자색으로 선택 상태를 구분합니다.
- 회원 탈퇴 방식처럼 설명을 포함하는 큰 선택 카드는 `rgba(74, 143, 101, 0.12)` 계열의 옅은 초록 그림자를 사용할 수 있지만 관심분야와 필터 같은 작은 선택 칩에는 그림자를 사용하지 않습니다.
- 키보드 포커스에는 `#78b991` 색상의 `2px` 외곽선을 사용해 선택 상태와 별개로 현재 조작 위치를 표시합니다.

### 7.3 모달 닫기 및 하단 명령 스타일

- 일반 입력과 선택 모달의 우측 상단 닫기 버튼은 마이페이지 독서 목표 설정 모달을 기준으로 `32px` 정사각형, 테두리 없음, `50%` 원형 모서리, `#f3f4f5` 배경의 `×` 명령을 사용합니다.
- 모달 닫기 버튼에는 메시지 프로퍼티로 관리하는 동작별 `aria-label`을 제공하고 키보드 포커스 외곽선과 비활성화 상태를 함께 표시합니다.
- 같은 화면 또는 기능 묶음의 모달 닫기 버튼은 공통 스타일이나 공통 컴포넌트를 재사용하며 개별 SVG, 테두리 상자 또는 서로 다른 크기로 다시 만들지 않습니다.
- 취소 또는 닫기와 저장 또는 확인을 함께 제공하는 모달 하단은 같은 너비의 두 열과 `8px` 간격을 사용하며, 왼쪽은 공통 `ActionButton`의 `secondary`, 오른쪽은 `primary`, 두 버튼 모두 `lg` 크기로 표시합니다.
- 단계 진행 표시는 사용자가 앞뒤 단계로 이동하는 실제 다단계 모달에만 표시하고 입력과 확인으로 끝나는 단일 단계 모달에는 표시하지 않습니다.

## 8. 제한 상태 화면 전환 규칙

- 정지, 영구 삭제 대기처럼 인증 상태가 일반 화면 접근을 제한하는 전용 화면에서 상세 데이터가 없다는 이유만으로 일반 화면을 전체 새로고침하지 않습니다.
- 제한 해제 여부는 서버의 최신 인증 상태를 다시 조회해 확정하고, 제한 상태가 해제된 경우에만 SPA 라우팅으로 일반 화면에 이동합니다.
- 인증 상태와 상세 데이터가 일치하지 않으면 전용 화면을 유지해 일반 화면과 제한 화면 사이의 반복 이동을 차단합니다.

## 9. 상태 변경 작업 처리 중 화면 규칙

- 등록, 수정, 삭제, 파일 업로드 및 외부 설정 변경을 시작하면 SweetAlert 스타일의 공통 처리 중 모달을 즉시 표시합니다.
- 처리 중 모달에는 회전형 로딩 표시와 작업 상태 문구만 제공하고 확인 버튼과 취소 버튼을 표시하지 않습니다.
- 처리 중 모달은 바깥 영역 클릭과 Escape 키로 닫히지 않으며 배경의 헤더, 내비게이션, 링크 및 버튼을 조작할 수 없게 합니다.
- PWA 스와이프와 브라우저 뒤로가기가 발생해도 처리 중에는 현재 화면을 유지하고 모달을 계속 표시합니다.
- 처리 중 문구는 작업 대상을 알 수 있게 작성하며 작업별 문구가 없을 때만 공통 `처리 중입니다.` 문구를 사용합니다.
- 성공 또는 실패 결과가 확정되면 처리 중 모달과 이동 차단을 자동으로 해제한 뒤 결과 알림이나 다음 화면을 표시합니다.
- 빠르게 끝나는 상태 변경도 같은 규칙을 적용하여 요청 시간에 따라 이탈 가능 여부가 달라지지 않게 합니다.

## 10. 조회 로딩 화면 규칙

### 10.1 모달 내부 데이터 조회

- 모달 안에서 데이터를 불러오는 모든 조회 진행 상태에는 프로젝트 공통 회전 링을 표시합니다.
- 모달 최초 조회는 공통 회전 링의 소형 버전을 모달 콘텐츠 영역 중앙에 표시합니다.
- 무한 스크롤이나 페이지 추가 조회는 같은 소형 공통 회전 링을 목록 끝의 추가 조회 위치에 표시합니다.
- 모달 조회 중에는 `목록 조회 중` 같은 로딩 텍스트를 화면에 표시하지 않고 회전 링만 노출합니다.
- 화면에 문구를 노출하지 않더라도 `role="status"`와 `aria-label`로 조회 진행 상태를 보조기기에 제공합니다.
- 화면별로 별도의 회전 애니메이션이나 링 스타일을 만들지 않고 공통 `Loading` 컴포넌트의 소형 모드를 재사용합니다.

### 10.2 페이지 최초 데이터 조회

- 페이지 최초 데이터를 불러오는 동안에는 현재 pathname에 대응하여 `TM_URMENU`에 등록된 메뉴명을 조회 문구에 사용합니다.
- 등록된 메뉴명이 있으면 `{메뉴명} 조회 중...` 형식으로 표시하며 예시는 `타이머 조회 중...`, `마이페이지 조회 중...`입니다.
- 현재 경로에 등록된 메뉴명이 없거나 메뉴명 조회에 실패하면 `목록 조회 중...`을 표시합니다.
- 페이지와 헤더는 같은 사용자 메뉴 조회 결과를 공유하여 메뉴명 표시를 위해 API를 중복 호출하지 않습니다.
- 로그인, 등록, 수정 및 삭제처럼 페이지 조회가 아닌 작업 진행 상태에는 해당 작업을 설명하는 기존 전용 문구를 유지합니다.

## 11. 공통 CSS 규칙

### 11.1 페이지 여백

- 페이지 설명이 없는 일반 페이지 최상위 컨테이너의 `padding-top`은 `20px`로 지정합니다.
- 페이지 설명이 있는 페이지 최상위 컨테이너의 `padding-top`은 공통 헤더와 설명 사이의 간격이 `10px`가 되도록 지정합니다.
- `padding` 축약 속성을 사용할 때 첫 번째 값은 페이지 설명 유무에 따라 각각 `20px` 또는 `10px`로 작성합니다.
- 공통 `Layout`의 `Container`는 좌우 `16px` 여백을 제공하므로 해당 `Container` 안의 페이지 최상위 컨테이너에는 좌우 `padding`을 중복으로 작성하지 않습니다.
- 공통 `Container` 밖에서 독립적으로 렌더링되는 페이지는 최상위 컨테이너에 좌우 `16px` 여백을 직접 작성합니다.
- 전체 너비 배경이나 가로 스크롤처럼 화면 가장자리까지 확장해야 하는 영역은 예외로 둘 수 있으며, 이 경우 실제 콘텐츠를 담는 내부 컨테이너에 좌우 `16px` 여백을 적용합니다.

### 11.2 페이지 설명

- 페이지 설명은 페이지 최상단에서 현재 페이지의 목적이나 사용자가 확인할 수 있는 내용을 한 문장으로 안내하는 텍스트를 의미합니다.
- 페이지 설명 문구는 JSX에 직접 작성하지 않고 `message` 함수와 기본 언어 및 영어 메시지 프로퍼티 키로 관리하며, 호출부에는 사용자 메시지 주석 규칙을 적용합니다.
- 페이지 설명 영역은 주요 콘텐츠와 구분되도록 `margin-bottom: 22px`을 적용합니다.
- 페이지 설명 텍스트는 `margin: 0`, `color: ${vars.color.black}`, `font-family: ${vars.font.semibold}`, `font-size: 16px`, `line-height: 1.55`를 사용합니다.
- 페이지 설명 앞에는 메가폰과 같은 장식 목적의 아이콘이나 이미지를 배치하지 않습니다.
- 페이지 설명과 페이지 기능 버튼을 같은 행에 배치할 때도 설명 텍스트 스타일과 하단 간격은 동일하게 유지합니다.
- 입력 도움말, 빈 상태 안내, 카드 설명 및 섹션 부제목은 페이지 설명으로 간주하지 않습니다.

### 11.3 테두리

- 화면에 실제로 표시하는 모든 테두리는 `1px solid ${vars.color.gray300}`을 사용합니다.
- `border: 0`, `border: none`처럼 테두리를 제거하는 선언은 이 규칙의 적용 대상에서 제외합니다.
- 선택, 오류, 경고 또는 포커스 상태는 테두리 색상이나 두께를 변경하지 않고 배경, 글자색, 그림자 또는 `outline`으로 구분합니다.

### 11.4 설명 텍스트

- 부제목, 도움말, 빈 상태 안내 및 입력 설명처럼 보조 설명 목적의 텍스트에는 `color: ${vars.color.gray600}`을 사용합니다.
- 제목, 본문 데이터, 상태값 및 기능 버튼 문구는 설명 텍스트로 간주하지 않습니다.

### 11.5 글자 크기

- 모든 `font-size`는 `10px` 이상의 짝수 정수만 사용합니다.
- 허용 예시는 `10px`, `12px`, `14px`, `16px`, `18px`이며 `11px`, `13px`, `15px`, `17px` 같은 홀수 크기와 `10px` 미만 크기는 사용하지 않습니다.
- 숫자형 `fontSize`를 사용할 때도 같은 기준을 적용하며 상대 단위가 필요하면 계산 결과가 이 기준의 픽셀 크기와 일치하도록 정의합니다.
